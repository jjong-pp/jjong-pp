## 1. 이 루브릭의 지위와 한계

이 문서는 스퀘어스 과제 원문과 PM 채용 공고를 직무 표본으로 보고, 제출 문서에서 실제로 관찰 가능한 역량을 일관되게 평가하기 위한 기준이다.

OPM과 EEOC가 제시하는 직무 분석, 내용 타당성, 구조화된 척도, 복수 평가 방법, 일관된 평가 원칙을 참고했다. 다만 스퀘어스 재직자의 실제 성과와 과제 점수의 상관관계를 검증한 것은 아니므로, 이 기준을 통계적으로 검증 완료된 스퀘어스 공식 채용 도구라고 표현하지 않는다.

이 루브릭이 직접 평가하는 것은 다음 네 가지다.

1. 모호한 GEO 개념을 측정 가능한 기준으로 정의하는 능력
2. B2B SaaS 사용자의 문제를 두 기능의 PRD로 전환하는 능력
3. 근거, 우선순위, 검증, 성공 측정을 하나의 의사결정 흐름으로 연결하는 능력
4. 판단과 주장 상태를 읽기 쉽게 전달하고 자신의 선택을 설명할 수 있는 능력

실제 협업, 갈등 조정, 영향력, 실행 속도, 장기 성과는 제출 문서만으로 평가하지 않는다. 이는 구조화 면접과 레퍼런스 또는 입사 후 수행에서 별도로 확인해야 한다.

## 3. 고정 적용 원칙

1. 절대평가한다. 이전 버전, 지원자 풀, 기대 합격 여부를 보고 원점수를 조정하지 않는다.
2. 제출본만 채점한다. 리서치 노트와 결정 로그는 사실 확인에 사용할 수 있지만, 제출본에 없는 논리를 보충해 점수를 올리지 않는다.
3. 계획은 계획으로 평가한다. 하지 않은 인터뷰, 실험, 파일럿, 성과를 결과로 인정하지 않는다.
4. 특정 PRD 목차, 특정 문장부호, 영문 사용, 표의 개수는 정답이 아니다.
5. GEO 기술 상세는 고객 문제와 제품 결정을 뒷받침할 때만 가점한다. API 명세나 통계 용어의 양 자체는 가점하지 않는다.
6. 근거의 개수보다 주장과 근거의 적합성, 적용 범위, 한계 인식을 평가한다.
7. AI 사용 여부를 추측해 감점하지 않는다. AI 사용으로 발생한 읽기 어려움, 근거 왜곡, 판단 부재만 해당 역량에서 평가한다.
8. 한 결함은 원칙적으로 한 항목에서만 감점한다. 별개의 하위 결과 문제가 생겼을 때만 추가 감점한다.
9. 모든 점수는 제출본의 문장, 표 또는 명시적 누락과 연결한다. 평가자가 선의로 의도를 완성하지 않는다.
10. 기준 변경은 원고 점수에 맞춰 하지 않는다. 변경하면 모든 기존 제출본을 소급 재평가한다.

## 4. 평가 절차: 다중 관문 구조

### 4-1. 관문 0: 과제 완결성

다음 중 하나라도 해당하면 `과제 미완결`로 표시한다. 진단 목적의 100점 채점은 계속하지만, 점수와 관계없이 선발상 `진행 권고`를 줄 수 없다.

- 문항 1 또는 문항 2의 답변이 없음
- 좋은 GEO의 기준이 정확히 세 개가 아님
- 최우선 기능이 정확히 두 개가 아님
- PRD에서 문제 정의, 핵심 사용자·시나리오, 주요 기능 요구사항, 성공 측정 중 하나가 실질적으로 없음
- 두 기능을 최우선으로 판단한 이유가 실질적으로 없음

단순히 제목이 없다는 이유로 미완결 처리하지 않는다. 해당 내용이 다른 구조 안에 명확하게 존재하면 충족으로 본다.

### 4-2. 관문 1: 신뢰성

다음이 확인되면 `신뢰성 Fail`로 처리한다. 총점으로 상쇄할 수 없다.

- 실행하지 않은 인터뷰·실험·성과를 실행한 사실처럼 기재
- 존재하지 않는 출처나 데이터를 만들어냄
- 출처가 지지하지 않는 수치를 검증된 사실로 제시하고, 단순 해석 오류를 넘어 반복적으로 사실 상태를 왜곡함
- 계획, 가설, 관찰 결과를 의도적으로 섞어 실제 성과처럼 보이게 함

출처 해석이 다르거나 인용 범위가 다소 넓다는 이유만으로 즉시 Fail 처리하지 않는다. 단순 오류는 A4 또는 D2에서 채점하고 면접 확인 항목으로 남긴다. 의도적 왜곡 여부가 불명확하면 `검증 필요`로 표시한다.

### 4-3. 관문 2: 100점 직무 표본 평가

관문 0과 1을 확인한 뒤 6절의 100점 루브릭을 채점한다.

### 4-4. 관문 3: 핵심 역량 최저선

총점이 높아도 다음 최저선을 모두 충족해야 `진행 권고`가 가능하다.

| 핵심 영역 | 최저선 | 이유 |
|---|---:|---|
| A. GEO 기준 | 14/24 | 문항 1을 주변 강점으로 상쇄하지 못하게 함 |
| B. PRD | 30/48 | 이 포지션의 핵심 직무 표본 |
| B3. 우선순위 | 행동수준 2 이상, 6/12 이상 | 과제에서 명시적으로 요구한 판단 |
| B4. 요구사항 | 행동수준 2 이상, 4/8 이상 | PRD가 설명문에 그치지 않게 함 |
| B5. 성공 측정 | 행동수준 2 이상, 4/8 이상 | 결과와 검증이 없는 기능 나열 방지 |
| D2. 주장 신뢰성 | 행동수준 3 이상, 3/4 이상 | 사실·가정·계획 구분은 필수 위생 요건 |

### 4-5. 관문 4: 구조화 면접 검증

과제 통과 후에는 11절의 질문으로 문서 소유권, 협업, 영향력, 실제 실행 경험을 별도로 검증한다. 면접 인상을 과제 원점수에 소급해 섞지 않는다.

## 5. 공통 행동수준과 점수 계산

모든 세부 항목은 0~4의 행동수준으로 판정한다.

| 수준 | 공통 의미 | 평가자의 판단 |
|---:|---|---|
| 0 | 부재·모순 | 요구 내용이 없거나 핵심 전제가 틀려 평가할 수 없음 |
| 1 | 언급 수준 | 용어나 제목은 있으나 실제 결정이나 실행에 사용할 수 없음 |
| 2 | 부분 충족 | 핵심 방향은 있으나 중요한 조건을 평가자가 추론해야 하거나 실행 위험이 큼 |
| 3 | 실무 충족 | 사소한 확인은 필요하지만 동료가 판단과 다음 행동을 이해할 수 있음 |
| 4 | 우수 | 대안·경계·실패 조건까지 명확해 재작업과 오판 위험을 크게 줄임 |

세부 점수는 `항목 배점 × 행동수준 ÷ 4`로 계산한다. 모든 배점은 4의 배수이므로 0.5점 추정 없이 정수로 채점된다.

- 4점 항목: 0 / 1 / 2 / 3 / 4점
- 8점 항목: 0 / 2 / 4 / 6 / 8점
- 12점 항목: 0 / 3 / 6 / 9 / 12점

수준 3이 모든 항목에서의 `실무 충족` 기준이다. 모든 항목이 수준 3이면 총점은 75점이 된다. 따라서 75점 기준은 임의의 합격 숫자가 아니라 모든 관찰 역량을 실무 충족 수준으로 수행했다는 의미다.

## 6. 100점 고정 루브릭과 항목별 행동 앵커

### A. 좋은 GEO의 기준: 24점

#### A1. 질문에 대한 직접 답변: 4점

평가 대상: “GEO를 잘하고 있다”는 상태를 직접 정의하고 정확히 세 기준으로 답했는가.

| 수준 | 행동 앵커 |
|---:|---|
| 0 | 정의가 없거나 기준이 세 개가 아니며, 경험담·시장 설명만 존재함 |
| 1 | 세 개의 제목은 있으나 GEO의 좋은 상태보다 SEO 수단이나 기능 목록에 가까움 |
| 2 | 한 문장 정의와 세 기준이 있으나 결과 상태와 실행 수단이 섞이거나 표현이 추상적임 |
| 3 | 첫 부분에서 좋은 GEO의 상태를 직접 정의하고, 정확히 세 개의 결과 기준으로 답함 |
| 4 | 수준 3에 더해 정의의 적용 범위와 사용자가 이 기준으로 내릴 판단까지 간결하게 드러남 |

#### A2. 세 기준의 구별성과 중요도: 8점

평가 대상: 세 기준이 서로 다른 실패 위험을 다루고, 함께 봤을 때 고객에게 중요한 결과를 설명하는가.

| 수준 | 행동 앵커 |
|---:|---|
| 0 | 세 기준이 사실상 같은 의미이거나 모두 구현 수단임 |
| 1 | 서로 다른 이름이지만 경계와 고객상 중요성이 설명되지 않음 |
| 2 | 의미 있는 세 축이지만 일부 중복되거나 중요한 결과 위험 하나가 비어 있음 |
| 3 | 각 기준이 다른 결과와 실패 위험을 다루며, 왜 세 가지를 함께 봐야 하는지 설명함 |
| 4 | 수준 3에 더해 각 기준의 비적용 사례나 상충 가능성을 밝혀 과대해석을 방지함 |

특정 정답 조합을 요구하지 않는다. `노출·선택·정확성`, `발견·신뢰·지속성` 등 다른 조합도 고객 결과와 경계가 강하면 같은 수준을 받을 수 있다.

#### A3. 조작적 정의와 GEO 측정 현실성: 8점

평가 대상: 각 기준을 실제로 판정할 수 있고, 생성형 AI 답변의 변동성을 최소 측정 계약에 반영했는가.

| 수준 | 행동 앵커 |
|---:|---|
| 0 | “많이 노출”, “긍정적 추천”처럼 관찰 방법이 없는 표현만 존재함 |
| 1 | 지표명은 있으나 계산 대상, 분모, 판정 규칙 또는 비교 조건이 거의 없음 |
| 2 | 일부 지표와 반복 필요성은 있으나 질문 의도, 모델·채널·시점 등 핵심 조건이 불완전함 |
| 3 | 각 기준에 관찰 단위와 판정 방법이 있고, 필요한 경우 분자·분모·질문 의도·반복·비교 조건을 정의함 |
| 4 | 수준 3에 더해 결측·출처 부재·판정 보류·불확실성 표현과 지표가 유효하지 않은 조건까지 통제함 |

최소 측정 계약을 평가하며 API 명세, 통계 검정력 계산, 전체 데이터 파이프라인 설계를 요구하지 않는다.

#### A4. 근거의 적합성과 한계: 4점

평가 대상: 왜 그 기준이 필요한지 근거로 설명하고, 근거가 말할 수 있는 범위를 넘지 않는가.

| 수준 | 행동 앵커 |
|---:|---|
| 0 | 근거가 없거나 출처가 핵심 주장을 반대로 말함 |
| 1 | 회사명·통계·경쟁사 사례를 제시하지만 해당 기준의 필요성과 연결되지 않음 |
| 2 | 관련 근거가 있으나 관찰과 인과, 시장 일반과 해당 사용자 맥락을 일부 혼동함 |
| 3 | 근거가 기준의 필요성을 직접 지지하고, 적용 조건과 한계를 필요한 수준에서 밝힘 |
| 4 | 수준 3에 더해 반대 근거나 대체 해석을 검토하고도 해당 기준을 선택한 이유가 명확함 |

### B. PRD: 48점

#### B1. 문제 정의와 핵심 사용자·시나리오: 8점

평가 대상: 기능 부재가 아니라 사용자의 현재 실패와 필요한 결정을 정의했는가.

| 수준 | 행동 앵커 |
|---:|---|
| 0 | 사용자와 문제가 없거나 “대시보드가 필요하다”처럼 기능을 문제로 표현함 |
| 1 | B2B SaaS 담당자라는 반복 외에 업무 상황, 실패, 필요한 결정이 없음 |

| 4 | 수준 3에 더해 가장 위험한 사용자 가정과 비대상 사용자를 밝혀 문제 범위를 통제함 |

#### B2. 두 기능의 가치와 경계: 8점

평가 대상: 정확히 두 기능이 서로 다른 사용자 결정을 돕고 하나의 흐름으로 연결되는가.

| 2 | 사용자 가치와 주요 출력은 있으나 두 기능의 역할이 겹치거나 사용 후 결정이 불명확함 |

경쟁 제품의 기능 존재는 참고 근거일 뿐 사용자 우선순위를 증명하지 않는다. 사용자 근거가 없으면 가설로 표시하고 검증 계획을 제시하면 된다.

평가 대상: 개발자와 디자이너가 핵심 동작을 같은 의미로 이해하고 구현 논의를 시작할 수 있는가.

모든 API와 화면을 명세할 필요는 없다. 두 기능의 가치와 품질을 좌우하는 정책이 빠지지 않았는지를 평가한다.

| 3 | 핵심 지표에 행동 이벤트·대상·분모·기간이 있고, 가치 지표와 품질 가드레일 및 다음 결정을 연결함 |

근거 없는 80%보다 내부 파일럿의 가설적 판단선이라고 명시한 수치가 낫다. 정성 관찰은 성공 증명 대신 실패 원인과 다음 가설을 찾는 데 사용한다.

#### B6. MVP 범위와 실행 가능성: 4점

평가 대상: 50명 이하 스타트업의 0→1 단계에서 실제로 시험할 수 있는 범위인가.

### C. 문항 간 연결과 0→1 제품 판단: 16점

#### C1. 기준→문제→기능→지표의 추적성: 8점

평가 대상: 문항 1과 문항 2가 별개의 모범답안이 아니라 같은 제품 논리로 이어지는가.

평가 대상: 사실, 해석, 가설, 계획, 미확인을 구분하고 출처의 범위 안에서 주장하는가.

한 결함은 아래의 주 항목에서 먼저 처리한다. 다른 항목에는 서로 다른 결과 결함이 증명될 때만 추가로 반영한다.

| 검증 활동은 있으나 결과별 다음 결정이 없음 | C2 | 성공 지표 자체도 없으면 B5 추가 가능 |
| 변동성·채널·자동 판정 위험을 무시 | C3 | 해당 위험 때문에 요구사항 정책도 틀리면 B4 추가 가능 |
| 길고 반복되어 결론을 찾기 어려움 | D1 | AI 위험 진단에 표시하되 추가 점수 감점 없음 |
| 사실·가정·계획이 충돌 | D2 | 중대한 허위이면 관문 1 적용 |
| 문체가 템플릿 같지만 판단은 명확함 | 점수 감점 없음 | AI 문체 위험에만 기록 |
| 선택과 제외가 없어 지원자의 판단이 안 보임 | D3 | B3에서 이미 같은 원인으로 전부 감점했다면 D3 재감점 금지 |

평가 보고서에는 감점마다 `주 항목`, `근거`, `다른 항목에 추가 반영했는지`를 기록한다.

## 8. AI스러움 진단: 점수와 분리

AI 사용 자체와 직무 능력은 같은 개념이 아니다. 따라서 AI 문체 위험은 총점과 별도로 `낮음 / 중간 / 높음`으로 보고하며, 등급 자체로 추가 감점하지 않는다.

### 8-1. 진단 대상

다음은 AI 사용의 증거가 아니라 면접 확인이 필요한 문서 신호다.

- 모든 단락이 같은 길이와 삼단 구조로 반복됨
- 추상 명사와 “가치를 제공한다” 같은 일반론이 실제 사용자 행동보다 많음
- 권위 있는 회사명, 시장 통계, 정밀 수치가 판단 장식으로 사용됨
- 긴 대시, 가운데점, 굵은 글씨, 괄호, 영문 제목이 누적되어 한국어 실무 문서의 독해를 방해함
- 가능한 반론을 모두 방어하지만 정작 선택하거나 포기한 것이 없음
- 문항 1과 PRD의 문체·개념 수준이 비정상적으로 다르거나 핵심 용어가 문서 안에서 일관되지 않음

### 8-2. 등급

| 등급 | 판정 |
|---|---|
| 낮음 | 문장 구조가 내용에 따라 달라지고, 사용자 행동·선택·제외·한계가 구체적임 |
| 중간 | 템플릿 문체가 누적되지만 핵심 판단과 근거는 추적 가능함 |
| 높음 | 추상적 모범답안 구조가 판단을 대신하고, 근거·용어·선택의 소유권을 문서만으로 확인하기 어려움 |

### 8-3. 점수에 반영하는 경계

- 읽기 어려움이 실제로 발생하면 D1에서만 평가한다.
- 근거 왜곡이나 사실 상태 충돌이 발생하면 D2에서만 평가한다.
- 선택과 제외가 없어 독립 판단이 보이지 않으면 D3 또는 B3 중 주 원인 한 곳에서 평가한다.
- 문장부호나 대칭 구조가 단지 취향과 다르다는 이유로 점수를 깎지 않는다.

### 8-4. 필수 보고 형식

AI 진단에는 반드시 다음 네 가지를 쓴다.

1. 위험 등급
2. 위험 신호가 나타난 실제 문장 또는 패턴
3. 지원자의 판단이 구체적으로 보이는 반대 증거
4. 면접에서 확인할 소유권 질문

## 9. 총점 해석과 진행 권고

총점은 관문 0·1과 핵심 역량 최저선을 통과했을 때만 진행 권고와 연결한다.

| 총점 | 수행 해석 | 진행 권고 |
|---:|---|---|
| 85~100 | 다수 항목이 실무 충족을 넘어 우수하며 재작업 위험이 낮음 | 강한 면접 진행 |
| 75~84 | 모든 핵심 역량이 실무 충족 수준이며 일부 확인 과제가 있음 | 면접 진행 |
| 60~74 | 부분 충족이 많아 중요한 판단을 평가자가 보완해야 함 | 보류 또는 제한적 검증 |
| 0~59 | 핵심 직무 표본이 언급 수준이거나 구조적으로 불완전함 | 진행 비권고 |

추가 판정 규칙:

- 75점 이상이어도 관문 0, 관문 1 또는 핵심 역량 최저선을 통과하지 못하면 `진행 비권고`다.
- 60~74점이더라도 한 가지 명확한 정보 누락 때문에 최저선을 놓쳤고 다른 핵심 항목이 수준 3 이상이면 `보류 후 구조화 검증`을 선택할 수 있다.
- 점수 구간은 실제 합격 확률이 아니다. 회사의 채용 인원, 지원자 풀, 내부 전략은 원점수와 분리한다.
- 평균적으로 모든 항목이 수준 3이면 75점, 수준 4이면 100점이다. 90점 이상은 단순히 문서가 매끄러운 것이 아니라 대부분의 핵심 항목에서 대안·경계·실패 조건까지 제시해야 한다.

## 10. 평가자 운영과 재현성 규칙

### 10-1. 독립 채점

가능하면 최소 두 명이 다음 순서로 독립 채점한다.

1. 지원자 이름, 이전 버전 점수, 다른 평가자의 점수를 보지 않는다.
2. 관문 0과 1을 먼저 판단한다.
3. 각 항목의 행동수준과 문서 근거 한 개 이상을 기록한다.
4. AI 문체 위험을 별도로 진단한다.
5. 총점을 계산한 후에만 전체 인상을 기록한다.

### 10-2. 불일치 조정

다음 중 하나면 근거를 대조해 재평가한다.

- 총점 차이가 5점 초과
- 동일 항목의 행동수준 차이가 1단계 초과
- 관문 또는 핵심 최저선 판정이 다름
- AI 위험 등급이 두 단계 다름

조정은 단순 평균으로 끝내지 않는다. 행동 앵커와 제출본 근거를 대조해 최종 수준을 정한다. 합의가 되지 않으면 더 낮은 점수를 자동 채택하지 않고 제3 평가자에게 해당 항목만 블라인드 검토시킨다.

### 10-3. 공정성 통제

- 출신 회사, 학교, 연차, 포트폴리오 인상을 과제 점수에 섞지 않는다.
- 문서 디자인, 영어, 학술적 표현은 직무 판단을 더 정확하게 전달할 때만 의미가 있다.
- 특정 GEO 정답 세트와 특정 PRD 템플릿을 강제하지 않는다.
- 접근 가능한 공개 자료를 사용한 지원자를 자료의 희소성으로 차별하지 않고, 근거 적용 능력을 평가한다.
- AI 탐지기 점수나 문체 추측을 선발 근거로 사용하지 않는다.

## 11. 구조화 면접 검증표: 과제 점수 밖의 관문

과제 통과자에게 동일한 핵심 질문과 후속 질문을 사용한다. 답변은 1~5 수준으로 별도 평가하며 과제 원점수와 합산하지 않는다.

### 11-1. 공통 질문

1. 세 GEO 기준 중 하나를 빼야 한다면 무엇을 빼고, 어떤 위험을 감수하겠는가?
2. 검토했지만 제외한 기능 두 개를 말하고, 현재 두 기능보다 뒤로 둔 이유를 설명해달라.
3. 가상의 질문 20개와 반복 답변 데이터가 주어졌다고 가정하고, 핵심 지표 하나의 분자·분모와 해석 한계를 설명해달라.
4. 실제 사용자 UI 결과가 API 결과와 다르다는 사실이 확인되면 수집 범위와 PRD를 어떻게 바꾸겠는가?
5. 제출한 근거 중 가장 약한 것 하나와 그 근거를 빼면 약해지는 주장을 말해달라.
6. 개발자가 일정상 두 기능 중 하나만 가능하다고 할 때 어떤 정보를 확인하고 무엇을 결정하겠는가?
7. 디자이너가 자동 판정의 신뢰도가 낮아 사용자에게 보여주기 어렵다고 반대하면 어떻게 합의하겠는가?

### 11-2. 면접 행동수준

| 수준 | 공통 행동 앵커 |
|---:|---|
| 1 | 문서 내용을 반복하지 못하거나 핵심 정의·수치·선택이 제출본과 충돌함 |
| 2 | 제출본을 요약할 수 있으나 반대 조건과 추가 질문에 판단을 수정하지 못함 |
| 3 | 핵심 선택과 근거를 일관되게 설명하고 새로운 제약에 합리적으로 대응함 |
| 4 | 대안과 트레이드오프를 명확히 비교하고 필요한 정보를 요청해 결정을 갱신함 |
| 5 | 자신의 약한 가정을 먼저 드러내고 이해관계자의 우려를 제품·실험 결정으로 통합함 |

면접에서 검증할 역량은 문서 소유권, 적응적 판단, 협업, 영향력, 피드백 수용이다. 말하기 유창함이나 자신감 자체를 높은 수준으로 보지 않는다.

## 12. 루브릭 검증과 캘리브레이션

이 루브릭은 다음 절차를 통과한 뒤에만 `평가자 간 안정성이 확인된 기준`이라고 표현한다.

1. 서로 다른 철학의 답안 최소 다섯 개를 준비한다.
   - SEO 수단 나열형
   - 노출 대시보드 중심형
   - 고객 행동·의사결정 중심형
   - 측정 과학은 강하지만 사용자 가치가 약한 형
   - 간결하고 실행 가능하지만 기술 상세가 적은 주니어형
2. 답안의 작성자와 의도를 숨긴다.
3. 최소 두 평가자가 독립 채점한다.
4. 총점 차이 5점 초과 또는 항목 수준 차이 1단계 초과를 기록한다.
5. 차이가 난 항목의 행동 앵커를 수정하되 특정 답안 점수를 올리기 위해 배점을 바꾸지 않는다.
6. 현재 V1~V4를 새 기준으로 모두 소급 채점한다.
7. 실제 채용에 사용할 경우 과제 점수와 이후 면접·입사 성과의 관계, 집단별 불리한 영향, 평가자 일치도를 지속적으로 확인한다.

## 13. 평가 보고서 고정 양식

모든 제출본 평가는 다음 순서로 보고한다.

1. 평가 대상 파일명과 수정 시각
2. 관문 0 완결성: 통과 / 미완결과 근거
3. 관문 1 신뢰성: 통과 / 검증 필요 / Fail과 근거
4. A~D 항목별 행동수준, 점수, 직접 근거
5. 중복 감점 귀속표
6. 원점수와 핵심 역량 최저선 충족 여부
7. AI 문체 위험 등급과 네 가지 필수 근거
8. 채용 담당자·CEO·시니어 PM·개발·디자인 관점의 주요 우려
9. P0 수정 최대 세 개와 예상 점수 변화
10. 최종 수행 해석과 진행 권고
11. 면접에서 검증할 질문 최대 다섯 개

## 14. 변경 통제

1. V1.2는 사용자의 명시적 요청 없이 수정하지 않는다.
2. 새 문제를 발견해도 현재 제출본 평가 도중 배점이나 행동 앵커를 바꾸지 않는다.
3. 변경 필요 사항은 별도 변경 제안서에 기록하고 다음 버전에서만 반영한다.
4. V1.3을 만들면 변경 이유, 영향을 받는 항목, 기존 점수 변화를 기록하고 V1~최신본을 모두 소급 평가한다.
5. 단순히 전체 점수가 낮거나 높다는 이유로 기준을 완화하거나 강화하지 않는다.

### V1.1에서 V1.2로 바뀐 핵심

- 사후 과적합을 줄이기 위해 특정 GEO 기준 조합이 아닌 결과·경계·측정 능력을 평가함
- 모든 항목에 0~4 행동 앵커를 부여함
- 0.5점 추정 채점을 없애고 행동수준으로 점수를 계산함
- 임의의 점수 상한 대신 완결성·신뢰성·핵심 역량 최저선의 다중 관문을 도입함
- 동일 결함의 중복 감점을 막는 귀속표를 추가함
- AI스러움을 점수에서 분리하고 가독성·신뢰성·판단 소유권의 실제 영향만 채점함
- 협업과 영향력을 과제 점수에서 제외하고 구조화 면접으로 분리함
- 모든 항목이 실무 충족 수준이면 75점이 되도록 점수 의미를 고정함
