## 1. 문제 정의

고객의 요청은 “자사 브랜드가 ChatGPT 등 AI 답변에 **얼마나, 어떻게** 노출되는지 알고 싶다”입니다. 표면의 문제는 측정 불능이지만, 더 근본적인 문제는 결과를 보더라도 **자신의 사업 목표와 어떤 관련이 있고 무엇부터 바꿔야 하는지 판단하기 어렵다**는 것입니다.

Forrester의 2025년 B2B 구매 여정 조사에서는 응답자의 94%가 구매 과정에서 AI를 사용한다고 답했습니다. 이는 특정 국가나 협업툴 고객 전체에 그대로 적용할 수 있는 수치는 아니지만, AI 답변 안의 브랜드 검토 구간을 마케팅 담당자가 무시하기 어렵다는 시장 신호입니다.[1] Bain의 정성 연구도 일부 중소기업 구매자가 LLM에서 초기 후보군을 만든 뒤 웹사이트·리뷰·영상으로 검증하는 행동을 관찰했습니다. AI 답변이 모든 구매의 출발점이라고 단정할 수는 없지만, 후보 형성에 관여할 수 있습니다.[2]

현재 담당자는 보통 직접 질문하고 스크린샷을 남깁니다. 그러나 이 방식에는 네 가지 문제가 있습니다.

| 문제 | 현재 방식의 한계 |
|---|---|
| 상태 판단 | 같은 질문도 회차·표현·모델에 따라 달라 한 번의 스크린샷으로 기준선을 만들기 어려움 |
| 사업 연결 | 모든 질문의 언급량을 합치면 중요한 고객 문제에서의 성과가 묻힘 |
| 품질 판단 | 이름이 나와도 추천인지 단순 언급인지, 사실과 강점에 맞는지 알기 어려움 |
| 다음 행동 | 숫자와 원문을 봐도 무엇부터 확인하고 바꿀지, 실행 후 나아졌는지 연결되지 않음 |

따라서 해결할 문제를 다음처럼 정의합니다.

> **한국어 기반 B2B SaaS 마케팅·그로스 담당자가 고객에게 중요한 질문에서 자사 브랜드의 노출·추천 상태와 서술 품질을 반복 가능한 근거로 판단하고, 가장 영향이 큰 다음 행동을 선택해 실행 전후 변화를 조직에 설명할 수 있게 한다.**

### 2-3. 대표 시나리오

**현재.** 대표가 “요즘 고객이 ChatGPT에 협업툴을 묻는다는데 우리는 어떤가요?”라고 묻습니다. 담당자가 같은 질문을 몇 번 입력해 보지만 자사가 나왔다가 사라집니다. 스크린샷은 있으나 현재 상태, 경쟁사 대비 위치, 다음 행동을 설명하지 못합니다.

**개선 후.** 담당자는 온보딩에서 브랜드명보다 먼저 `누구의 어떤 문제를 해결하는지`, `노출 뒤 기대 행동`, `검증 가능한 강점과 부적합 조건`을 선택 카드와 짧은 자유 입력으로 답합니다. AI가 후보 질문과 판단 근거를 제안하고 담당자가 수정·확정합니다. 이후 주간 리포트에서 중요한 질문의 노출·추천 변화, 추천 역할과 사실 오류, 영향이 큰 다음 행동을 확인합니다. 행동을 실행하면 같은 조건으로 다시 측정하고 다음 결정을 갱신합니다.

## 3. 목표와 비목표

### 목표

1. 고객 문제에서 사업적으로 중요한 목표 질문군을 만들고 사용자가 근거와 가중치를 소유하게 합니다.
2. 선언한 표본 안에서 자사 노출·추천 성과, 경쟁 위치, 추천 역할과 사실 정확성을 구분해 보여줍니다.
3. 고객·사업 영향이 큰 문제를 근거 있는 행동 또는 검증 과제로 바꾸고 동조건 재측정과 연결합니다.
4. 담당자가 같은 결과를 실무 우선순위와 조직 설득에 함께 사용할 수 있게 합니다.

### 비목표

- 콘텐츠를 자동 생성·게시하거나 외부 출처 수정을 대행하지 않습니다.
- 특정 행동이 노출·매출을 만든다고 보장하거나 인과를 단정하지 않습니다.
- 다국어·다지역, 다수 브랜드 통합 관리, 실시간 알림은 1차 범위에서 제외합니다.
- 범용 SEO 점검 도구나 `llms.txt` 생성기를 만들지 않습니다.

## 4. 최우선 기능 2개

문항 1의 세 기준을 두 기능으로 접습니다.

| 좋은 GEO 기준 | 제품 기능 |
|---|---|

### F1. 목표 질문 설계·노출/추천 진단

고객이 왜 GEO를 도입하려는지부터 묻고, 그 답을 측정할 질문으로 번역합니다. 반복 관측 결과는 `경영진용 요약 → 원자 지표 → 질문별 답변 원문` 순으로 내려가며 확인할 수 있게 합니다.

#### 핵심 요구사항

| ID | 요구사항 | 우선순위 |
|---|---|:---:|
| F1-01 | 선택 카드와 짧은 자유 입력으로 고객 문제·대상 사용자·발생 상황·기대 사업 행동·KPI·검증 가능한 강점·적합/부적합 조건을 수집 | MVP |
| F1-02 | AI가 고객 문제·구매 상황별 질문 의도군과 각 의도군의 대표 표현 2~3개를 만들고 사업 기여도·브랜드 적합성·판단 근거를 제안 | MVP |
| F1-03 | 사용자가 질문 의도군·대표 표현·근거·포함 여부·가중치를 수정·승인하고 변경 시 새 버전 생성 | MVP |
| F1-04 | 승인된 대표 표현 세트를 각 제공사가 지원하는 범위에서 반복 실행하고 질문 의도군 단위로 집계. 모델 식별자·웹 검색 설정과 실행 증거·언어·지역·회차를 함께 기록하며, 공식 API 운영 기준 시계열은 주 1회 질문–환경 조합당 최소 3회 반복 | MVP |
| F1-05 | 답변에서 자사·경쟁사를 탐지하고 `추천 / 비교·검토 후보 / 단순 언급 / 주의·비추천` 역할, 추천·제외 이유와 근거 원문을 저장 | MVP |
| F1-06 | 자사 가중 노출률·추천률, 고정 경쟁사군 대비 가중 추천 점유율, 회차 변동폭을 모델·질문별로 제공 | MVP |
| F1-07 | 대표·CMO가 볼 수 있는 주간 요약과 이미지·PDF 공유 기능 제공 | P1 |

대표 표현별 반복 결과를 먼저 평균내고 이를 질문 의도군 평균으로 묶은 뒤, 의도군 가중치를 한 번만 적용합니다. 표현 수가 많은 의도군이 점수를 과도하게 차지하지 않게 하기 위함입니다. `최소 3회`는 충분성이 검증된 통계 표준이 아니라 비용과 단발 오판 위험을 절충한 **MVP 최소값**이며 파일럿에서 조정합니다. 노출률도 전체 소비자 모집단의 확률이 아니라 선언한 질문 의도군×대표 표현×환경×반복 표본 안의 관측률로 표시합니다.

#### GEO 요약 점수

화면 상단에는 다음 MVP 가설을 경영진용 요약으로 제공합니다.

```text
GEO 원점수 100
├─ 자사 절대 성과 70 = 가중 노출률 25 + 가중 추천률 45
└─ 경쟁 위치 30 = 고정 경쟁사군 대비 가중 추천 점유율

품질 가드레일
└─ 사람이 확인한 중대한 사실 오류가 있으면 원점수는 보존하고 최종 등급을 ‘주의’ 또는 ‘위험’으로 표시
```

각 비율을 0~1로 놓고 `25×가중 노출률 + 45×가중 추천률 + 30×가중 추천 점유율`로 원점수를 계산합니다. 추천을 단순 언급보다 중요하게 보되, 브랜드가 먼저 등장해야 추천될 기회가 생기므로 노출을 버리지 않습니다. 상대 점수만 보면 경쟁사가 나빠져도 좋아 보일 수 있어 자사 절대 성과를 70점으로 더 크게 둡니다. `25/45/30`과 중대 오류의 등급 표시는 시장 표준이 아니라 파일럿에서 설명력·행동 변화·위험 전달력을 검증할 제품 가설입니다. 실제 의사결정의 중심은 종합점수가 아니라 하위 원자 지표와 원문입니다.

#### API 운영 기준 시계열과 통제 UI 표본

API와 소비자 UI의 출력이 같다고 가정하지 않습니다. OpenAI Responses API와 Gemini처럼 모델이 검색 실행 여부를 판단하는 경로에서는 응답별 실행 증거를 따로 기록하고, Perplexity Sonar처럼 웹 그라운딩을 전제로 한 경로도 실제 검색 결과·인용 메타데이터를 기록합니다. 각 제공사가 지원하는 범위에서만 조건을 고정하며, 지원되지 않거나 공개되지 않은 값은 실행 환경과 표시값만 기록합니다.[3][4][5]

- **API 운영 기준 시계열:** 원점수·주간 추이·행동 전후 변화량 계산에 사용합니다.
- **통제 UI 표본:** 최초 기준 표본 후 월 1회 `상위 질문 의도군에서 선정한 대표 표현 6개 × ChatGPT·Gemini·Perplexity × 2회 = 36회`를 수동 또는 사용자 보조로 확인합니다. API 추세 이상, 제공사 UI·표시 모델·검색 설정 변경, 고객 제보, 중대 오류 발생 시 영향 범위만 추가 점검합니다. 이 규모와 트리거는 파일럿에서 탐지력·오경보·운영 시간을 검증할 가설입니다.
- UI의 로그인·메모리·요금제·표시 모델·검색 모드·네트워크 지역을 기록하고, API 수치와 합산하지 않습니다. 설정이 바뀌면 새 기준선을 만듭니다.

### F2. 근거 기반 서술 진단·개선 루프

F1이 수집한 답변을 고객이 승인한 기준 정보와 대조하고, 중요한 문제를 다음 행동 또는 검증 과제로 바꿉니다. 데이터 원천과 사용자 과업이 하나이므로 별도의 콘텐츠 도구가 아니라 **진단에서 재측정까지 닫는 한 기능**으로 정의합니다.

#### 핵심 요구사항

| ID | 요구사항 | 우선순위 |
|---|---|:---:|
| F2-01 | 고객이 요금·기능·지원 범위·적합/부적합 조건과 공식 근거 URL을 기준 정보로 등록·승인 | MVP |
| F2-02 | 답변의 검증 가능한 사실 주장을 추출해 기준 정보와 대조하고 `일치 / 오류 후보 / 판단 불가` 및 근거 원문 표시 | MVP |
| F2-03 | 인용·언급 출처의 발행 주체·최신성·기준 정보 일치 여부와 통제 수준을 분리 표시. 인용을 답변 생성의 원인으로 단정하지 않음 | MVP |
| F2-04 | 사용자가 오류 후보와 추천 역할을 확인·기각하고, 고객 선택을 잘못 이끌 중대 오류를 P0로 확정 | MVP |
| F2-05 | `목표 적합성·최소 근거 관문 → P0 → 고객·사업 영향 → 근거 신뢰도 → 실행 효율` 순으로 행동 또는 검증 과제 제안 | MVP |
| F2-06 | 사용자가 순서·근거를 수정하고 행동을 완료하면 최초 발생 경로의 영향 범위를 같은 조건으로 재측정해 `개선 / 유지 / 악화 / 비교 불가` 판정 | MVP |
| F2-07 | 주간 유지·재발 상태와 다음 행동을 갱신하고 담당자·마감·내부 공유 이력을 관리 | P1 |

고영향·저신뢰 문제는 바로 수정하지 않고 범위를 제한한 검증 과제로 전환합니다. 사실 대조와 인용 URL 연결은 이미 상용 제품에서 구현되어 있어 기술적 실현 가능성은 확인할 수 있지만, 공급사 문서는 효과의 증거가 아닙니다.[6] 이 PRD에서 검증할 차별화 가설은 고객 문제에서 우선순위를 만들고 **특정 행동과 동조건 재측정을 연결하는 것**입니다.

## 5. 왜 이 두 기능이 최우선인가

| 판단 기준 | F1 | F2 |
|---|---|---|
| 고객 질문에 직접 답함 | “중요한 어디에서 얼마나, 어떤 역할로 등장하는가” | “그래서 무엇부터 확인하고 바꿀 것인가” |
| 선행 의존성 | 모든 진단과 전후 비교의 데이터 기준선 | F1의 동일 원문·기준 정보를 사용해 행동으로 변환 |
| 조직 설득 | 스크린샷 대신 반복 가능한 수치·경쟁 맥락 제공 | 영향 근거·행동·재측정 결과로 투자 판단 설명 |
| 반복 사용 이유 | 주간 상태와 변화 확인 | 행동 실행 후 결과 검토와 다음 과제 결정 |

F1만 있으면 상태를 보여주는 온도계에 머물고, F2만 있으면 기준선 없는 권고안이 됩니다. `목표 질문 확정 → 반복 진단 → 근거 확인 → 행동 선택 → 동조건 재측정 → 다음 결정`이라는 하나의 폐쇄 루프가 고객의 현재 문제를 처음부터 끝까지 해결하는 최소 범위입니다.

### 공개된 스퀘어스 자산과의 연결

큐샵 공개 기능 페이지는 AI가 읽기 쉬운 텍스트 구조·메타 정보 처리와 AI 크롤러 방문 이력 대시보드를 제공한다고 설명합니다.[7] 이를 기준으로 보면 F1은 `봇 방문`을 `중요한 답변에서 어떤 역할로 추천됐는가`까지 확장하고, F2는 발견한 문제를 고객이 실제로 수정할 수 있는 페이지·콘텐츠 자산과 재측정에 연결합니다. 새 도구를 고립시켜 만들기보다 기존 사이트 생성·운영 자산 위에 **관측 → 판단 → 실행 → 검증** 계층을 더한다는 제품 적합성 가설입니다. 공개 정보에서 도출한 추론이며 내부 데이터나 로드맵을 안다고 전제하지 않습니다.

### 검토했으나 제외한 기능

| 제외 기능 | 제외 이유 |
|---|---|
| 콘텐츠 자동 생성·게시 | 측정 기준선과 효과 검증 없이 실행부터 자동화하면 더 많은 콘텐츠만 만듦 |
| `llms.txt`·구조화 데이터 자동 생성 | 하나의 실행 수단일 뿐이며 고객의 상태 판단·우선순위 문제를 해결하지 않음 |
| 실시간 변동 알림 | 생성 변동을 사건처럼 과잉 알릴 위험. 공식 측정은 주간, UI는 월간+사건 기반 |
| 다국어·다지역 측정 | 한국어 기반 국내 B2B SaaS라는 1차 사용자 범위를 먼저 검증 |
| 다수 브랜드·에이전시 모드 | 단일 브랜드 실무자의 문제와 다른 권한·과금·운영 요구가 생김 |

## 6. 성공 측정 기준

**핵심 가치 지표:** `활성 계정 중 첫 4주 안에 고객·사업 영향 상위 문제의 개선 루프를 1회 완료한 비율`

| 단계 | 지표 | 초기 목표 |
|---|---|---:|
| 활성화 | 온보딩 완료 후 첫 리포트 도달 시간 | 3일 이내 |
| 활성화 | 목표 질문군과 질문별 근거를 확인·승인한 계정 비율 | 80% 이상 |
| 가치 경험 | 첫 4주 안에 1순위 행동 또는 검증 과제를 확정한 계정 비율 | 60% 이상 |
| 핵심 가치 | 첫 4주 안에 개선 루프를 1회 완료한 활성 계정 비율 | 30% 이상 |
| 고객 성과 | 비교 가능한 루프 중 목표 미달 계정은 가중 추천률 상승, 목표 도달 계정은 유지, 또는 중대 오류 감소를 확인한 계정 비율 | 파일럿 기준선 수집 |
| 조직 활용 | 리포트를 내보내거나 공유한 계정 비율 | 40% 이상 |

제품 신뢰성을 위해 공식 API 사이클 완주율, 회차 변동폭, API–UI 노출·추천 격차, 역할 일치율, 사람이 확인한 P0의 해제 후 재발을 별도 진단 지표로 봅니다. 사업 결과는 AI 서비스 리퍼럴, 영업·온보딩의 “어떻게 알게 되었는가”, 체험·파이프라인 추이를 탐색하되 GEO의 직접 인과로 단정하지 않습니다.

위 목표값은 모두 외부 벤치마크가 아니라 **초기 파일럿 가설**이며 베타 계정의 기준선·완주 비용·사용 행동을 확인한 뒤 보정합니다.

## 7. 핵심 리스크와 대응

| 리스크 | 대응 |
|---|---|
| 생성 변동과 모델 업데이트가 성과처럼 보임 | 반복 측정, 회차 변동폭, 모델·질문·조건 버전 기록, 비교 불가 구간 분리 |
| API 결과가 소비자 UI를 대표하지 못함 | API와 UI를 별도 관측으로 유지하고 월간·사건 기반 통제 UI 표본의 격차 공개 |
| 역할·사실 오류 자동 판정의 오탐 | 근거 원문과 기준 정보를 항상 노출하고 사용자 확인·기각·판단 불가 경로 제공 |
| 권고 행동과 결과의 인과를 과장 | 원인 ‘확정’이 아니라 근거가 표시된 가설로 제시하고 동조건 전후 관측으로만 표현 |
| 측정 비용이 고객 가치보다 커짐 | 주간 전체 API와 영향 범위 즉시 검증을 분리하고, UI는 월간 36회+사건 범위만 운영 |
