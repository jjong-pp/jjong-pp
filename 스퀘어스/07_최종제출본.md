# 1. “GEO를 잘 하고 있다”는 것은 무엇을 의미하는가

**좋은 GEO란 타깃 고객이 실제로 묻는 중요한 질문에서 브랜드가 반복적으로 추천되고, 사실과 실제 강점에 맞게 설명되며, 실행 후 같은 조건에서 그 상태가 유지·개선되는 것입니다.**

전통적 SEO에서는 결과 페이지의 URL·위치와 클릭·유입을 비교적 명시적으로 관찰할 수 있었습니다. 반면 생성형 AI에서는 브랜드의 등장 여부와 추천 맥락이 자연어 답변 안에 섞이고, 같은 의도라도 실행 회차·질문 표현·모델에 따라 결과가 달라질 수 있습니다. 따라서 한 번의 순위나 스크린샷이 아니라 `어디에서 얼마나 / 어떻게 / 바꾼 뒤 나아졌는가`를 나누어 봐야 합니다.

| 좋은 GEO의 기준 | 대표 질문 | 대표 지표 |
|---|---|---|
| 1. 중요한 질문에서 재현되는 성과 | 고객에게 중요한 곳에서 반복해 후보가 되는가? | 가중 노출률·추천률, 경쟁사 대비 추천 점유율, 회차 변동폭 |
| 2. 서술의 사실 정확성과 추천 역할 | 사실과 실제 강점에 맞는 이유로 추천되는가? | 사실 오류, 추천 역할, 추천·제외 이유와 근거 원문 |
| 3. 지속성과 개선 효과의 검증 가능성 | 무엇을 바꿨고, 같은 조건에서 나아졌는가? | 개선 루프 완료율, 동조건 전후 변화, 유지·재발 상태 |

## 기준 1. 중요한 질문에서 재현되는 절대·상대 성과

타깃 고객의 문제에서 도출하고 사업 기여도와 브랜드 적합성으로 우선순위화한 목표 질문군에서, 자사의 노출·추천 성과가 반복 측정해도 유지되며 고정 경쟁사군 대비 위치도 강하거나 개선되는 상태입니다.

한 번의 등장은 성과가 아니라 표본 하나입니다. 2026년 한 사전연구는 상업 추천 질문 50개를 두 모델(OpenAI gpt-5.4-mini, Anthropic Claude Sonnet 4.6)의 저·고 추론 강도, 총 네 조건에서 각각 30회 재실행했습니다. 같은 질문에서도 추천 브랜드 집합의 평균 중첩도(Jaccard)는 0.50~0.61이었습니다. 이 결과는 단발 실행이 불충분함을 보여줍니다. 같은 논문에서 의미를 유지한 표현 변형 간 추천 집합 Jaccard도 0.288에 그쳤습니다. 단일일·영어·두 제공사 실험이므로 수치를 보편화하지 않고, 한 문장을 구매 의도 전체의 대리값으로 쓰지 않아야 한다는 설계 근거로만 사용합니다.[1]

모든 질문의 한 번도 같은 가치가 아닙니다. “협업툴이란 무엇인가”와 “한국에서 일하는 50명 규모 스타트업에 적합한 협업툴을 추천해줘”를 같은 한 건으로 합산하면 숫자가 커져도 사업적 의미는 흐려집니다. 고객의 문제와 기대 행동에서 후보 질문을 만들고, 질문별 사업 기여도와 실제로 추천받을 만한 제품 근거를 확인한 뒤 사용자가 목표 질문과 가중치를 확정해야 합니다. 따라서 목표 질문은 단일 문장 목록이 아니라 고객 문제·구매 상황별 `질문 의도군`과 2~3개의 대표 표현으로 관리합니다. 이는 자연스러운 표현 분포 전체의 추정치가 아니라 파일럿 최소 표본이며, 점수는 사용자가 승인한 표현 세트에 한정해 해석합니다.

측정할 때는 다음을 함께 봅니다.

- 자사의 **목표 질문 가중 노출률·추천률**과 기준선 대비 변화
- 고정 경쟁사군 대비 **가중 추천 점유율**
- 질문·모델·회차별 변동폭과 결과가 뒤집힌 조합
- 질문·가중치·경쟁사군·측정 조건의 버전

여기서 노출률은 전체 소비자 모집단의 확률이 아니라, **선언한 질문×환경×반복 표본 안에서의 관측률**입니다. 상대 점수만 보면 경쟁사가 나빠져도 좋아 보일 수 있으므로 자사 절대 성과와 경쟁 위치는 서로 대체하지 않고 나란히 봅니다.

## 기준 2. 서술의 사실 정확성과 추천 역할

브랜드가 등장할 때 요금·기능·지원 범위 같은 사실이 기준 정보와 일치하고, 실제 강점과 적합 고객 조건에 맞는 역할로 추천되는 상태입니다.

틀린 요금제나 지원하지 않는 기능도 단순 등장률에서는 `+1`로 계산됩니다. 하ㄹㄹ지만 잘못된 노출은 고객 선택을 왜곡하고 이후 영업·지원 비용을 만드는 부채입니다. 또한 “추천”, “비교 후보”, “단순 언급”, “이 조건에는 부적합”은 의미가 다르므로 긍정 감성이나 이름 등장만으로 좋은 노출이라고 볼 수 없습니다.

답변을 다음처럼 분리해 판정합니다.

| 항목 | 판정 방식 |
|---|---|
| 추천 역할 | `추천 / 비교·검토 후보 / 단순 언급 / 주의·비추천`과 판정 근거 원문 |
| 추천 맥락 | 추천 순서, 적합 조건, 대안 관계, 추천·제외 이유 |
| 사실 정확성 | 승인된 요금·기능·지원 범위와 대조해 `일치 / 오류 후보 / 판단 불가` |
| 포지셔닝 | 답변의 소환 속성과 실제 강점·적합 고객 조건의 일치 여부 |

자동 분류는 결론이 아니라 검토 후보입니다. 사용자가 원문과 기준 정보를 보고 확인·기각할 수 있어야 하며, 애매한 내용은 판단 불가로 남깁니다. 사람이 확인한 중대한 사실 오류가 있다면 원점수는 보존하되 최종 등급을 `주의` 또는 `위험`으로 표시합니다. 다만 중대 오류의 등급 제한 방식은 상용 제품의 표준이 아니라 파일럿에서 검증할 자체 운영 가설입니다. 사실 주장 추출·기준 정보 대조·관련 인용 URL 표시는 이미 상용 제품에 구현되어 있어 기술적 실현 가능성도 확인할 수 있습니다.[4]

## 기준 3. 성과의 지속성과 개선 효과 검증 가능성

미노출·낮은 추천률·사실 오류·원하지 않는 포지셔닝을 근거가 표시된 원인 가설과 다음 행동으로 바꾸고, 실행 후 같은 조건에서 다시 측정해 `개선 / 유지 / 악화 / 비교 불가`를 판단하며 다음 결정을 갱신할 수 있는 상태입니다.

“추천률 20%”라는 숫자만으로 담당자는 무엇부터 바꿀지 알 수 없습니다. 중요한 질문의 격차를 답변 원문, 추천·제외 이유, 기준 정보와의 차이, 인용·언급 출처 같은 증거와 연결해야 행동이 됩니다. 다만 인용 링크가 특정 답변을 만들었다고 단정할 수 없으므로, 제품은 원인을 확정하기보다 **근거와 신뢰도가 표시된 원인 가설**을 제안해야 합니다.

또한 좋은 제3자 출처는 자사가 직접 통제하지 못해도 추천의 신뢰 근거가 될 수 있습니다. Bain이 소개한 약 5억 건의 인용 분석에서는 브랜드를 지명하지 않은 질문의 89%가 제3자 출처로 충족됐습니다. 따라서 자사 소유 출처 비중을 무조건 높이는 대신, 출처의 정확성·최신성과 `직접 수정 / 갱신 요청 / 보완 근거 확산` 중 가능한 대응 경로를 구분해야 합니다.[2]

```text
기준선 측정
→ 고객·사업 영향이 큰 문제 선택
→ 근거 원문과 원인 가설 확인
→ 행동 또는 범위를 제한한 검증 과제 실행
→ 영향 범위를 같은 조건으로 즉시 재측정
→ 주간 관측에서 유지·재발 확인
→ 다음 행동 결정
```

우선순위는 `목표 적합성·최소 근거 관문 → 중대한 사실 오류 → 고객·사업 영향 → 근거 신뢰도 → 실행 효율` 순으로 봅니다. 고영향·저신뢰 문제는 바로 수정하지 않고 범위를 제한한 검증 과제로 전환합니다. 실행 직후 한 번 좋아졌다고 인과 효과나 영구 해결을 주장하지 않고, 동일 조건의 재측정과 이후 정기 관측으로 유지·재발을 확인합니다.

세 기준은 순환합니다. 기준 1이 **어디에서 얼마나**를 정하고, 기준 2가 숫자의 **품질**을 판정하며, 기준 3이 결과를 **행동과 다음 학습**으로 연결합니다. 노출만 높으면 잘못 알려질 수 있고, 정확하기만 해도 후보에 들지 못할 수 있으며, 측정만 반복하면 고객 문제는 해결되지 않습니다.

## 2-2. 문제 정의

고객의 요청은 “자사 브랜드가 ChatGPT 등 AI 답변에 얼마나, 어떻게 노출되는지 알고 싶다”입니다. 그러나 노출률만 보여줘서는 고객 문제가 끝나지 않습니다. 담당자에게 필요한 것은 자신의 사업 목표와 관련 있는 질문에서 현재 상태를 판단하고, 다음 행동의 우선순위와 실행 후 변화를 설명할 근거입니다.

Forrester의 2025년 B2B 구매 여정 조사에서는 응답자의 94%가 구매 과정에서 AI를 사용한다고 답했습니다. 특정 국가나 협업툴 고객 전체에 그대로 적용할 수 있는 수치는 아니지만, AI 답변 안의 브랜드 검토 구간을 무시하기 어렵다는 시장 신호입니다.[3] Bain의 정성 연구도 일부 중소기업 구매자가 LLM에서 초기 후보군을 만든 뒤 웹사이트·리뷰·영상으로 검증하는 행동을 관찰했습니다. AI 답변이 모든 구매의 출발점이라고 단정할 수는 없지만 후보 형성에 관여할 수 있습니다.[2]

현재 담당자는 같은 질문을 몇 번 입력하고 스크린샷을 남길 수 있습니다. 하지만 회차마다 결과가 달라 상태를 판정하기 어렵고, 모든 질문의 언급량을 합치면 중요한 고객 문제에서의 성과가 묻힙니다. 이름이 나와도 추천인지 단순 언급인지, 사실과 강점에 맞는지 알기 어렵고, 결과를 확인해도 무엇부터 바꿀지 연결되지 않습니다.

따라서 해결할 문제를 다음처럼 정의합니다.

> **마케팅·그로스 담당자가 고객에게 중요한 질문에서 자사 브랜드의 노출·추천 상태와 서술 품질을 반복 가능한 근거로 판단하고, 가장 영향이 큰 다음 행동을 선택해 실행 전후 변화를 조직에 설명할 수 있게 한다.**

온보딩은 브랜드명·경쟁사 입력보다 `누구의 어떤 문제를 해결하는지`, `노출 뒤 기대 행동`, `검증 가능한 강점과 부적합 조건`을 먼저 묻습니다. 단계별 선택 카드와 짧은 자유 입력을 함께 쓰고, AI가 전체 답을 후보 질문과 근거로 조합합니다. 사용자는 질문·사업 기여도·브랜드 적합성·가중치를 그대로 승인하거나 수정합니다.

## 2-4. 목표와 비목표

**목표**

1. 고객 문제에서 중요한 목표 질문군을 만들고 사용자가 근거와 가중치를 소유하게 합니다.
2. 자사 노출·추천 성과, 경쟁 위치, 추천 역할과 사실 정확성을 구분해 보여줍니다.
3. 영향이 큰 문제를 근거 있는 행동 또는 검증 과제로 바꾸고 동조건 재측정과 연결합니다.

**비목표**

- 콘텐츠 자동 생성·게시, 외부 출처 수정 대행, 노출·매출 보장
- 다국어·다지역, 다수 브랜드 통합 관리, 실시간 변동 알림
- 범용 SEO 점검 또는 `llms.txt`·구조화 데이터 생성 도구

## 2-5. 기능 1 — 목표 질문 설계·노출/추천 진단

고객의 도입 목적을 측정할 질문으로 번역하고, 반복 관측 결과를 `경영진용 요약 → 원자 지표 → 질문별 원문` 순으로 보여줍니다.

| 핵심 요구사항 | 내용 |
|---|---|
| 문제 중심 온보딩 | 고객 문제·대상 사용자·기대 행동·KPI·검증 가능한 강점과 부적합 조건 수집 |
| 질문 설계 | AI가 고객 문제별 질문 의도군과 대표 표현, 사업 기여도·브랜드 적합성 근거를 제안하고 사용자가 수정·승인 |
| 반복 측정 | 승인된 대표 표현 세트를 제공사가 지원하는 조건에서 반복 실행하고, 결과는 질문 의도군 단위로 집계. 모델 식별자·검색 설정과 실행 증거·언어·지역·회차를 함께 기록 |
| 등장 방식 분석 | `추천 / 비교·검토 후보 / 단순 언급 / 주의·비추천`, 추천·제외 이유, 근거 원문 저장 |
| 성과 진단 | 가중 노출률·추천률, 고정 경쟁사군 대비 가중 추천 점유율, 회차 변동폭 제공 |
| 공유 | 대표·CMO용 주간 요약과 이미지·PDF 내보내기 |

상단의 GEO 원점수는 각 비율을 0~1로 놓고 `25×가중 노출률 + 45×가중 추천률 + 30×가중 추천 점유율`로 계산합니다. 추천을 단순 언급보다 중요하게 보되, 브랜드가 등장해야 추천 기회도 생기므로 노출을 버리지 않습니다. 상대 점수만 보면 경쟁사가 나빠져도 좋아 보일 수 있어 자사 절대 성과를 70점으로 더 크게 둡니다. 이 비중은 시장 표준이 아니라 파일럿에서 설명력과 행동 변화를 검증할 MVP 가설이며, 실제 판단은 하위 지표와 원문을 중심으로 합니다.

공식 점수·주간 추이·행동 전후 변화량은 **웹 검색 사용을 허용한 API 운영 기준 시계열**로 계산합니다. OpenAI Responses API와 Gemini처럼 모델이 검색 실행 여부를 판단하는 경로에서는 응답별 검색 실행 증거를 따로 기록합니다. Perplexity Sonar처럼 웹 그라운딩을 전제로 한 경로도 실제 검색 결과·인용 메타데이터를 기록합니다. API와 소비자 UI가 같다고 가정하지 않으며, 각 제공사가 지원하지 않거나 공개하지 않은 조건은 추정하지 않습니다.[5–8]

실제 화면 대표성은 월간·사건 기반 통제 UI 표본으로 별도 확인하며, API 수치와 합산하지 않습니다. 상세 표본 설계는 부록 A에 제시합니다.

## 2-6. 기능 2 — 근거 기반 서술 진단·개선 루프

기능 1이 수집한 답변을 고객이 승인한 기준 정보와 대조하고, 중요한 문제를 다음 행동 또는 검증 과제로 바꿉니다.

| 핵심 요구사항 | 내용 |
|---|---|
| 기준 정보 | 고객이 요금·기능·지원 범위·적합/부적합 조건과 공식 근거 URL을 등록·승인 |
| 사실·출처 진단 | 검증 가능한 주장을 기준 정보와 대조하고 근거 원문, 출처의 최신성·일치 여부·통제 수준 표시 |
| 사람 확인 | 오류 후보와 추천 역할을 사용자가 확인·기각하고 `중대한 고객 위험(P0)`으로 확정 |
| 영향 기반 우선순위 | `목표·최소 근거 → P0 → 고객·사업 영향 → 근거 신뢰도 → 실행 효율` 순으로 행동·검증 과제 제안 |
| 재측정 | 행동 완료 후 최초 발생 경로의 영향 범위를 같은 조건으로 다시 실행해 `개선 / 유지 / 악화 / 비교 불가` 판정 |
| 다음 결정 | 주간 유지·재발 상태와 다음 행동을 갱신하고 공유 이력 관리 |

고영향·저신뢰 문제는 바로 수정하지 않고 범위를 제한한 검증 과제로 전환합니다. 사실 대조 기능 자체는 이미 상용화되어 있으므로 차별점으로 과장하지 않습니다.[4] 이 PRD에서 검증할 차별화 가설은 고객 문제로 우선순위를 정하고, **특정 행동과 동조건 재측정을 연결하는 것**입니다.

## 2-7. 왜 이 두 기능이 최우선인가

| 판단 기준 | 기능 1 | 기능 2 |
|---|---|---|
| 고객 질문 | 중요한 어디에서 얼마나, 어떤 역할로 등장하는가 | 그래서 무엇부터 확인하고 바꿀 것인가 |
| 선행 관계 | 모든 진단과 전후 비교의 기준선 | 기능 1의 동일 원문·기준 정보를 행동으로 변환 |
| 조직 설득 | 스크린샷 대신 반복 가능한 수치와 경쟁 맥락 | 영향 근거·행동·재측정 결과로 투자 판단 설명 |
| 반복 사용 | 주간 상태와 변화 확인 | 행동 실행 후 결과 검토와 다음 과제 결정 |

기능 1만 있으면 상태를 보여주는 온도계에 머물고, 기능 2만 있으면 기준선 없는 권고안이 됩니다. `목표 질문 확정 → 반복 진단 → 근거 확인 → 행동 선택 → 동조건 재측정 → 다음 결정`이라는 폐쇄 루프가 고객 문제를 처음부터 끝까지 해결하는 최소 범위입니다.

### 스퀘어스의 공개 자산과 연결

큐샵 공개 기능 페이지는 AI가 읽기 쉬운 텍스트 구조·메타 정보 처리와 AI 크롤러 방문 이력 대시보드를 제공한다고 설명합니다.[9] 이를 기준으로 보면 기능 1은 `봇이 방문했는가`를 `중요한 답변에서 어떤 역할로 추천됐는가`까지 확장하고, 기능 2는 발견한 문제를 고객이 실제로 수정할 수 있는 페이지·콘텐츠 자산과 재측정에 연결할 수 있습니다. 즉 새 도구를 고립시켜 만드는 것보다 기존 사이트 생성·운영 자산 위에 **관측 → 판단 → 실행 → 검증** 계층을 더하는 방향입니다. 이는 공개 정보에서 도출한 제품 적합성 가설이며 내부 데이터나 로드맵을 안다고 전제하지 않습니다.

## 2-8. 성공 측정 기준

**핵심 가치 지표:** 활성 계정 중 첫 4주 안에 고객·사업 영향 상위 문제의 개선 루프를 1회 완료한 비율

| 단계 | 지표 | 초기 목표 |
|---|---|---:|
| 활성화 | 온보딩 완료 후 첫 리포트 도달 시간 | 3일 이내 |
| 활성화 | 목표 질문군과 근거를 확인·승인한 계정 비율 | 80% 이상 |
| 가치 경험 | 첫 4주 안에 1순위 행동 또는 검증 과제를 확정한 계정 비율 | 60% 이상 |
| 핵심 가치 | 첫 4주 안에 개선 루프를 1회 완료한 활성 계정 비율 | 30% 이상 |
| 고객 성과 | 비교 가능한 루프 중 목표 미달 계정은 가중 추천률 상승, 목표 도달 계정은 유지, 또는 중대 오류 감소를 확인한 계정 비율 | 파일럿 기준선 수집 |
| 조직 활용 | 리포트를 내보내거나 공유한 계정 비율 | 40% 이상 |

공식 측정 사이클 완주율, 회차 변동폭, API–UI 노출·추천 격차, 역할 일치율, 사람이 확인한 중대 오류의 해제 후 재발은 제품 신뢰성 지표로 별도 추적합니다. AI 서비스 리퍼럴, 영업·온보딩의 “어떻게 알게 되었는가”, 체험·파이프라인 추이는 후행 탐색 지표로 보되 GEO의 직접 인과로 단정하지 않습니다.

위 목표값은 모두 외부 벤치마크가 아니라 **초기 파일럿 가설**이며 베타 계정의 기준선·완주 비용·사용 행동을 확인한 뒤 보정합니다.

## A. 핵심 측정 원칙

- 대표 표현별 반복 결과를 먼저 평균내고, 이를 질문 의도군 평균으로 묶은 뒤 의도군 가중치를 한 번만 적용합니다. 표현 수가 많은 의도군이 점수를 과도하게 차지하지 않게 합니다.
- `최소 3회`는 충분성이 검증된 통계 표준이 아니라 비용과 단발 오판 위험을 절충한 MVP 최소값입니다.
- 웹 검색 사용 가능 설정과 실제 검색 사용 증거를 구분하며, 검색 정책·실행 여부가 달라진 결과를 같은 시계열로 합치지 않습니다.
- 질문·가중치·경쟁사군·산식·모델 또는 실행 조건이 바뀌면 새 버전으로 구간을 나눕니다.
- 사람이 확인한 중대한 사실 오류가 있으면 원점수는 보존하되 최종 등급을 `주의` 또는 `위험`으로 표시하고, 최초 발견 경로의 반복 재검증과 사람 승인 후 해제합니다.
- 인용 URL은 원인 확정이 아니라 원인 가설과 대응 경로를 만드는 증거로 사용합니다.
- `미재현`은 현재 조건의 표본에서 다시 관측되지 않았다는 뜻이며 영구 해결이나 인과를 의미하지 않습니다.
- 실제 화면 대표성은 최초 기준 표본 후 월 1회 `상위 질문 의도군에서 선정한 대표 표현 6개 × ChatGPT·Gemini·Perplexity × 2회 = 36회`로 점검합니다. API 추세 이상·제공사 변경·고객 제보·중대 오류 발생 시 영향 범위만 추가 확인합니다. UI의 로그인·메모리·요금제·표시 모델·검색 모드·네트워크 지역을 기록하며, 36회와 사건 트리거는 파일럿에서 탐지력·오경보·운영 시간을 검증할 가설입니다.
