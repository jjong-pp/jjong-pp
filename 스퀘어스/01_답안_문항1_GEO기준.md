# 문항 1 — “GEO를 잘 하고 있다”는 것은 무엇을 의미하는가

> **좋은 GEO란 타깃 고객이 실제로 묻는 중요한 질문에서 브랜드가 반복적으로 추천되고, 사실과 실제 강점에 맞게 설명되며, 실행 후 같은 조건에서 그 상태가 유지·개선되는 것입니다.**

전통적 SEO에서는 결과 페이지의 URL·위치와 클릭·유입을 비교적 명시적으로 관찰할 수 있었습니다. 반면 생성형 AI에서는 브랜드의 등장 여부와 추천 맥락이 자연어 답변 안에 섞이고, 같은 의도라도 실행 회차·질문 표현·모델에 따라 결과가 달라질 수 있습니다. 따라서 한 번의 순위나 스크린샷이 아니라 `어디에서 얼마나 / 어떻게 / 바꾼 뒤 나아졌는가`를 나누어 봐야 합니다.

| 좋은 GEO의 기준 | 대표 질문 | 대표 지표 |
|---|---|---|
| 1. 중요한 질문에서 재현되는 절대·상대 성과 | 고객에게 중요한 곳에서 반복해 후보가 되는가? | 가중 노출률·추천률, 경쟁사 대비 추천 점유율, 회차 변동폭 |
| 2. 서술의 사실 정확성과 추천 역할 | 사실과 실제 강점에 맞는 이유로 추천되는가? | 사실 오류, 추천 역할, 추천·제외 이유와 근거 원문 |
| 3. 성과의 지속성과 개선 효과 검증 가능성 | 무엇을 바꿨고, 같은 조건에서 나아졌는가? | 개선 루프 완료율, 동조건 전후 변화, 유지·재발 상태 |

---

## 기준 1. 중요한 질문에서 재현되는 절대·상대 성과

### 정의

타깃 고객의 문제에서 도출하고 사업 기여도와 브랜드 적합성으로 우선순위화한 목표 질문군에서, 자사의 노출·추천 성과가 반복 측정해도 유지되며 고정 경쟁사군 대비 위치도 강하거나 개선되는 상태입니다.

### 근거

**한 번의 등장은 성과가 아니라 표본 하나입니다.** 2026년 한 사전연구는 상업 추천 질문 50개를 두 모델(OpenAI gpt-5.4-mini, Anthropic Claude Sonnet 4.6)의 저·고 추론 강도, 총 네 조건에서 각각 30회 재실행했습니다. 같은 질문에서도 추천 브랜드 집합의 평균 중첩도(Jaccard)는 0.50~0.61이었고, 의미를 유지한 표현 변형 간 추천 집합 Jaccard는 0.288이었습니다. 단일일·영어·두 제공사 실험이므로 수치를 보편화하지 않고, 단발 실행과 고정 문장 하나가 구매 의도 전체를 대표할 수 없다는 설계 근거로만 사용합니다.[1]

**모든 질문의 한 번은 같은 가치가 아닙니다.** “협업툴이란 무엇인가”와 “한국에서 일하는 50명 규모 스타트업에 적합한 협업툴을 추천해줘”를 같은 한 건으로 합산하면 숫자가 커져도 사업적 의미는 흐려집니다. 그래서 고객의 문제와 기대 행동에서 질문 후보를 만들고, 그 질문에서 추천될 사업적 가치와 실제로 추천받을 만한 제품 근거를 분리해 확인한 뒤 사용자가 목표 질문과 가중치를 확정해야 합니다. 목표 질문은 단일 문장 목록이 아니라 고객 문제·구매 상황별 `질문 의도군`과 2~3개의 대표 표현으로 관리합니다. 이는 자연스러운 표현 분포 전체의 추정치가 아니라 파일럿 최소 표본이며, 점수는 승인된 표현 세트에 한정해 해석합니다.

### 측정 방법

1. `고객 문제·사용 상황 → 기대 사업 행동 → 검증 가능한 강점·적합/비적합 조건` 순으로 입력받아 후보 질문을 만듭니다.
2. 사용자가 질문별 사업 기여도·브랜드 적합성의 근거와 포함 여부를 확인하고 가중치를 확정합니다.
3. 각 제공사가 지원하는 범위에서 질문·모델 식별자·검색 설정·언어·지역·반복 조건을 기록해 API 운영 기준 시계열을 만듭니다. 공개되지 않은 값은 추정하지 않습니다.
4. `목표 질문 가중 노출률`, `목표 질문 가중 추천률`, `고정 경쟁사군 대비 가중 추천 점유율`과 회차 간 변동폭을 함께 봅니다.
5. 질문·가중치·경쟁사군 또는 측정 조건이 바뀌면 버전을 나누어 구성 변경을 성과 개선으로 오독하지 않습니다.

노출률은 전체 소비자 모집단의 확률이 아니라, **선언한 질문×환경×반복 표본 안에서의 관측률**입니다. 자사 추천률이 그대로인데 경쟁사만 하락하면 상대 점유율은 좋아질 수 있으므로, 자사 절대 성과와 경쟁 위치는 서로 대체하지 않고 나란히 봅니다.

## 기준 2. 서술의 사실 정확성과 추천 역할

### 정의

브랜드가 등장할 때 요금·기능·지원 범위 같은 사실이 기준 정보와 일치하고, 실제 강점과 적합 고객 조건에 맞는 역할로 추천되는 상태입니다.

### 근거

틀린 요금제나 지원하지 않는 기능도 단순 등장률에서는 `+1`로 계산됩니다. 그러나 잘못된 노출은 고객의 선택을 왜곡하고 이후 영업·지원 비용을 만드는 부채입니다. 특히 B2B SaaS에서는 “추천”, “비교 후보”, “저렴한 대안”, “이 조건에는 부적합” 같은 역할과 꼬리표가 후보 검토에 영향을 줄 수 있으므로, 긍정 감성이나 이름 등장만으로 좋은 노출이라 판단할 수 없습니다.

답변에서 사실 주장을 추출해 브랜드 기준 정보와 대조하고 관련 원문·인용 URL을 제시하는 기능은 상용 제품에서도 구현되어 있습니다. 이는 효과를 보장하는 근거가 아니라 **기술적·시장적 실현 가능성**의 근거입니다.[2]

### 측정 방법

| 항목 | 판정 방식 |
|---|---|
| 추천 역할 | `추천 / 비교·검토 후보 / 단순 언급 / 주의·비추천` 4단계와 근거 원문 |
| 추천 맥락 | 추천 순서, 적합 조건, 대안 관계, 추천·제외 이유를 별도 필드로 기록 |
| 사실 정확성 | 고객이 승인한 요금·기능·지원 범위와 대조해 `일치 / 오류 후보 / 판단 불가`로 분류 |
| 포지셔닝 | 답변이 언급한 속성과 실제 강점·적합 고객 조건의 일치 여부 확인 |
| 품질 가드레일 | 사람이 확인한 중대한 사실 오류가 있으면 원점수는 보존하되 최종 등급을 `주의` 또는 `위험`으로 표시. 파일럿에서 검증할 자체 운영 가설 |

자동 분류는 결론이 아니라 검토 후보입니다. 사용자가 항상 원문과 기준 정보를 보고 확인·기각할 수 있어야 하며, 애매한 내용은 억지로 맞거나 틀리다고 분류하지 않습니다.

## 기준 3. 성과의 지속성과 개선 효과 검증 가능성

### 정의

미노출·낮은 추천률·사실 오류·원하지 않는 포지셔닝을 근거가 표시된 원인 가설과 다음 행동으로 바꾸고, 실행 후 같은 조건에서 다시 측정해 `개선 / 유지 / 악화 / 비교 불가`를 판단하며 다음 결정을 갱신할 수 있는 상태입니다.

### 근거

“추천률 20%”라는 숫자만으로 담당자는 무엇부터 바꿀지 알 수 없습니다. 중요한 질문의 격차를 답변 원문, 추천·제외 이유, 기준 정보와의 차이, 인용·언급 출처 같은 증거와 연결해야 행동이 됩니다. 다만 인용 링크가 특정 답변을 만들었다고 인과적으로 단정할 수 없으므로, 제품은 **근거와 신뢰도가 표시된 원인 가설**을 제안해야 합니다.

또한 좋은 제3자 출처는 자사가 직접 통제하지 못해도 추천의 신뢰 근거가 될 수 있습니다. Bain이 소개한 약 5억 건의 인용 분석에서는 브랜드를 지명하지 않은 질문의 89%가 제3자 출처로 충족됐습니다. 이는 자사 소유 출처 비중을 무조건 높이기보다, 출처의 정확성·최신성과 `직접 수정 / 갱신 요청 / 보완 근거 확산` 중 가능한 대응 경로를 구분해야 한다는 근거입니다.[3]

### 측정 방법

```text
기준선 측정
→ 고객·사업 영향이 큰 문제 선택
→ 근거 원문과 원인 가설 확인
→ 행동 또는 범위를 제한한 검증 과제 실행
→ 영향받은 범위를 같은 조건으로 즉시 재측정
→ 주간 운영 기준 시계열에서 유지·재발 확인
→ 다음 행동 결정
```

우선순위는 `목표 적합성과 최소 근거 관문 → 중대한 사실 오류 → 고객·사업 영향 → 근거 신뢰도 → 실행 효율` 순으로 판단합니다. 고영향·저신뢰 문제는 곧바로 수정하지 않고 범위를 제한한 검증 과제로 전환합니다. 실행 직후 한 번 좋아졌다고 인과 효과나 영구 해결을 주장하지 않으며, 동일 조건의 유효한 재측정과 이후 정기 관측으로 유지·재발을 봅니다.

## 세 기준의 관계

기준 1이 **어디에서 얼마나**를 정하고, 기준 2가 그 숫자의 **품질**을 판정하며, 기준 3이 결과를 **행동과 다음 학습**으로 연결합니다. 노출만 높으면 잘못 알려질 수 있고, 정확하기만 해도 후보에 들지 못할 수 있으며, 측정만 반복하면 고객 문제는 해결되지 않습니다.

브랜드 검색, AI 서비스 유입, 체험 신청과 파이프라인 기여는 확인해야 할 후행 사업 지표입니다. 다만 제로클릭과 복수 접점 때문에 GEO 활동의 직접 인과로 단정하지 않고, AI 리퍼럴 세그먼트와 영업·온보딩의 “어떻게 알게 되었는가” 응답을 함께 보조적으로 확인합니다.
