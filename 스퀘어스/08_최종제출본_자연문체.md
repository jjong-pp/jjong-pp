# 스퀘어스 서비스기획 PM 과제

지원자: 박종혁  
작성일: 2026년 8월 16일

## 1. “GEO를 잘 하고 있다”는 것은 무엇을 의미하는가

저는 현재 이커머스 유통사에서 일하며 최근 GEO 도입을 검토했습니다. 내부 논의에서 가장 먼저 막힌 질문은 “GEO 기술이 얼마나 좋은가”가 아니라 “우리 사업의 어디에 쓰고, 어떤 결과를 성공으로 볼 것인가”였습니다. 기술 설명만으로는 현업의 실행 과제나 조직을 설득할 자료가 만들어지지 않았습니다.

이 경험 뒤로 저는 기능을 설명하기 전에 고객이 왜 이 기능을 찾았고 어떤 결과를 원하는지부터 묻게 됐습니다.

제게 좋은 GEO는 고객의 구매 판단에 가까운 질문에서 우리 브랜드가 꾸준히 후보로 나오고, 실제 강점에 맞는 이유로 소개되며, 문제를 고친 뒤 결과가 나아졌는지 다시 확인할 수 있는 상태입니다.

| 기준 | 왜 필요한가 | 확인할 지표 |
|---|---|---|
| 1. 중요한 질문에서 반복해 후보가 되는가 | 구매 상황과 가까운 질문에서 성과가 이어지는가 | 질문별 노출률과 추천률, 경쟁사 대비 추천 점유율, 회차별 편차 |
| 2. 맞는 이유로 추천되는가 | 사실 오류 없이 실제 강점과 고객 조건이 설명되는가 | 추천 역할, 추천·제외 이유, 요금·기능 오류 |
| 3. 수정할 문제와 이후 변화가 보이는가 | 다음 행동을 고르고 같은 조건에서 변화를 확인할 수 있는가 | 과제 실행 여부, 전후 변화, 유지·재발 여부 |

### 기준 1. 고객에게 중요한 질문에서 반복해 후보가 되는가

모든 언급을 같은 한 건으로 세면 숫자는 커져도 의미는 흐려집니다. “협업툴이란 무엇인가”와 “한국에서 일하는 50명 규모 스타트업에 적합한 협업툴을 추천해줘”는 사업에 미치는 무게가 다릅니다. 먼저 고객이 해결하려는 문제, 구매 상황, AI 답변을 본 잠재 고객에게 기대하는 행동을 묻고 측정할 질문을 골라야 합니다. 질문의 중요도도 담당자가 이유를 보고 조정할 수 있어야 합니다.

반복 측정도 필요합니다. 2026년 사전연구에서 같은 상업 추천 질문을 여러 번 실행했을 때 추천 브랜드 집합의 평균 중첩도는 0.50~0.61이었고, 뜻을 유지한 표현 변형끼리는 0.288이었습니다.[1]

연구가 영어 질문과 두 제공사만 다뤘기 때문에 이 수치를 목표값으로 쓰지는 않았습니다. 다만 한 번의 스크린샷만으로 성과를 판단할 수 없다는 점은 분명합니다.

제품에서는 고객 문제와 구매 상황별로 질문 묶음을 만들고, 처음에는 각 묶음에 대표 표현을 2~3개 둡니다. 같은 질문을 여러 차례 확인해 자사 노출과 추천 여부를 보고, 미리 정한 경쟁사의 결과도 함께 봅니다.

대표 표현은 우선 2~3개로 시작합니다. 파일럿에서 결과 편차와 측정 비용을 본 뒤 개수를 조정합니다. 이 결과는 전체 시장 점유율이 아니라, 사용자가 고른 질문과 실행 환경 안에서만 해석합니다.

### 기준 2. 브랜드가 맞는 이유로 추천되는가

이름이 등장했다고 모두 좋은 노출은 아닙니다. 지원하지 않는 기능이나 틀린 요금으로 소개된 답변도 단순 언급률에서는 한 건으로 잡힐 수 있습니다. 저는 이런 노출을 성과로 세지 않고 잘못된 고객 정보로 따로 다룹니다. 추천, 비교 후보, 단순 언급, 제외는 서로 다른 역할이므로 답변 원문과 추천 이유를 함께 남겨야 합니다.

사실 여부는 고객이 승인한 요금, 기능, 지원 범위와 대조합니다. 자동 판정은 사람이 확인하기 전까지 오류 후보로만 두고, 애매하면 판단 불가로 남깁니다. 상용 GEO 제품의 FactCheck에도 주장 추출, 기준 정보 대조, 관련 인용 URL 확인 기능이 구현되어 있습니다.[4]

사실 대조 기능은 이미 상용 제품에 구현돼 있습니다. 그래서 이 기능 자체보다 담당자가 여러 오류 중 무엇을 먼저 고칠지 정할 수 있게 하는 데 초점을 뒀습니다.

### 기준 3. 무엇을 고칠지와 고친 뒤의 변화가 보이는가

담당자에게 “추천률 20%”만 보여주면 회의 자료는 만들 수 있어도 다음 일을 정하기 어렵습니다. 어떤 질문에서 빠졌고 답변이 무슨 이유를 들었는지, 공식 정보와 어디가 다른지까지 봐야 수정 순서를 정할 수 있습니다.

제가 GEO 도입을 검토할 때도 이 지점이 가장 막혔습니다. 기술 설명만으로는 도입 이유가 생기지 않았고, 먼저 풀 문제와 기대 결과를 정해야 했습니다.

인용된 출처도 대응 방법을 고르는 단서가 됩니다. Bain이 소개한 약 5억 건의 인용 분석에서는 브랜드를 지명하지 않은 질문의 89%가 제3자 출처로 충족됐습니다.[2]

그래서 자사 페이지 비중 자체를 목표로 삼지 않았습니다. 틀린 자사 정보는 직접 고치고, 제3자 정보는 갱신을 요청하거나 근거를 보완합니다. 출처마다 할 수 있는 일이 다르며, 인용 링크만으로 답변의 원인을 단정하지도 않습니다.

수정 전후 확인은 다음 순서로 진행합니다.

1. 중요한 질문에서 빠진 이유나 사실 오류를 답변 원문과 함께 확인합니다.
2. 고객과 사업에 미치는 영향을 보고 먼저 다룰 문제를 고릅니다.
3. 페이지 수정, 정보 갱신 요청, 근거 보완 중 하나를 실행합니다.
4. 처음 문제가 나온 질문과 실행 환경에서 다시 확인하고 이후에도 유지되는지 봅니다.

세 기준 중 먼저 볼 것은 질문의 중요도입니다. 고객에게 중요하지 않은 질문에서 많이 언급돼도 사업 성과로 보기 어렵기 때문입니다. 그다음 추천 이유를 확인하고, 고친 뒤 같은 조건에서 다시 봅니다.

## 2. PRD — 목표 질문에서 다음 행동까지

### 2-1. 문제 정의

과제에서 제시한 담당자는 ChatGPT 등 AI 답변에 자사 브랜드가 얼마나, 어떻게 나오는지 알고 싶어 합니다. 몇 번 검색한 화면과 언급 횟수만으로는 이 질문에 답하기 어렵습니다.

같은 질문도 실행 시점과 표현에 따라 결과가 달라질 수 있고, 브랜드가 등장하더라도 실제 추천인지 단순 언급인지에 따라 의미가 다릅니다. 모든 질문의 노출을 합치면 구매 가능성이 높은 질문에서 약한 상태가 가려질 수도 있습니다. 담당자는 결과를 확인한 뒤에도 무엇부터 바꿔야 할지, 그 판단을 대표나 다른 팀에 어떻게 설명해야 할지 막힙니다.

Forrester 조사에서는 2025년 B2B 구매 여정 응답자의 94%가 구매 과정에서 AI를 사용한다고 답했습니다.[3]

Bain은 일부 중소기업 구매자가 LLM에서 후보를 만든 뒤 웹사이트, 리뷰, 영상으로 다시 살펴보는 행동을 관찰했습니다.[2] 두 자료를 협업툴 시장의 규모로 해석하지는 않았습니다. AI 답변이 후보군을 만드는 단계에 쓰이고 있다는 시장 신호로 봤습니다.

이 제품이 해결하려는 문제는 다음과 같습니다.

> 마케팅·그로스 담당자가 고객에게 중요한 질문에서 브랜드가 어떤 이유로, 어떤 역할로 등장하는지 파악한다. 그 결과로 먼저 할 일을 정하고, 실행 뒤 달라진 답변을 조직에 설명할 수 있어야 한다.

### 2-2. 사용자와 사용 장면

주 사용자는 한국어 시장에서 구독형 협업툴의 SEO, 콘텐츠, 브랜드 업무를 함께 맡는 마케팅·그로스 담당자입니다. 대표나 CMO는 요약 결과를 함께 봅니다.

아래 내용은 사용자 인터뷰 결과가 아니라 제품 범위를 구체화하기 위한 가상 시나리오입니다.

월요일 회의에서 대표가 “ChatGPT에서 우리 서비스는 어떻게 나오나요?”라고 묻습니다. 담당자는 직접 검색한 화면 몇 장을 가지고 있지만 질문마다 결과가 달라 현재 상태를 설명하기 어렵습니다. 이름이 나온 답변도 추천인지 단순 비교인지 알 수 없고, 경쟁 서비스가 선택된 이유도 정리되어 있지 않습니다.

담당자는 자사의 고객과 구매 상황을 고른 뒤 제품이 제안한 질문을 검토합니다. 구매 가능성이 높은데도 자사가 빠진 질문과 기능이 잘못 설명된 답변을 찾습니다.

그중 하나를 골라 콘텐츠를 수정하고 같은 질문을 다시 실행합니다. 대표에게는 건수 대신 문제가 생긴 질문, 바꾼 내용, 달라진 답변을 공유합니다.

### 2-3. 목표와 범위

이번 MVP에서 하려는 일은 두 가지입니다.

- 고객의 도입 목적을 측정 가능한 질문으로 바꾸고, 그 질문에서 자사와 경쟁사가 어떤 역할로 등장하는지 비교합니다.
- 진단 결과 중 먼저 다룰 문제를 골라 이번 주 과제로 만들고, 실행 전후 답변을 나란히 봅니다.

초기 범위에서는 다음을 제외합니다.

- 콘텐츠 자동 생성·게시, 외부 사이트 수정 대행, AI 답변 노출·매출 상승 보장
- 다국어·다지역 관리, 여러 브랜드를 한 번에 운영하는 에이전시 기능
- 범용 SEO 진단

먼저 한 브랜드의 한국어 목표 질문에서 진단과 개선이 실제 의사결정으로 이어지는지 확인합니다.

### 2-4. 기능 1 — 목표 질문 기반 노출·추천 진단

첫 번째 기능은 사용자가 관리할 질문을 고르게 하고, 질문마다 브랜드가 추천·비교·언급 중 어떤 역할로 나오는지 보여줍니다.

온보딩의 첫 질문은 브랜드명이나 경쟁사가 아닙니다. 먼저 어떤 고객의 어떤 문제를 푸는지, AI 답변을 본 고객에게 어떤 행동을 기대하는지, 제품이 증명할 수 있는 강점과 맞지 않는 고객 조건을 묻습니다. 선택 카드 뒤에 짧은 자유 입력을 두어 응답 부담을 줄입니다.

AI는 고객 문제, 구매 단계, 기대 행동을 바탕으로 질문 묶음과 대표 표현을 제안합니다. 각 질문이 왜 중요한지와 어떤 제품 근거가 필요한지도 함께 보여줍니다. 사용자는 그 이유를 보고 문구와 우선순위를 고칩니다.

정해진 질문은 같은 조건에서 여러 번 실행합니다. 결과는 단순 언급 횟수만 세지 않고 추천, 비교 후보, 단순 언급, 주의 또는 비추천으로 나눕니다.

첫 화면에서는 다음 네 가지를 볼 수 있어야 합니다.

- 질문별 노출 여부와 추천 역할
- 추천되거나 제외된 이유와 답변 원문
- 주요 경쟁사와의 비교와 회차별 편차
- 대표와 CMO에게 공유할 수 있는 한 페이지 상태 요약

대표가 현재 상태를 빠르게 볼 수 있도록 상단에 요약 점수와 상태 등급을 둡니다. 요약 점수는 추천률을 중심으로 노출률과 경쟁사 대비 추천 점유율을 묶되, 바로 아래에서 원지표와 답변 원문을 확인할 수 있게 합니다.

사람이 확인한 중대한 사실 오류가 있으면 원점수가 높아도 상태를 ‘주의’보다 좋게 표시하지 않습니다. 점수 비중과 등급 기준은 임의로 굳히지 않습니다. 파일럿 사용자가 계산 방식을 이해하고 실제 우선순위 결정에 쓰는지 본 뒤 정합니다.

주간 변화는 실행 조건을 남길 수 있는 API로 보고, 소비자 화면은 별도 표본으로 확인합니다. API는 같은 조건의 전후 비교에, 소비자 화면은 고객이 실제로 보는 환경과의 차이를 찾는 데 씁니다. 두 결과는 합산하지 않고 관측 환경을 함께 표시합니다. 제공사가 기록을 지원하지 않는 조건은 추정하지 않습니다.[5][6][7]

### 2-5. 기능 2 — 문제별 개선 카드와 전후 비교

두 번째 기능은 진단에서 발견한 문제를 이번 주 과제로 정리하고, 수정 전과 후의 답변을 나란히 보여줍니다.

담당자가 자사 공식 페이지 URL을 고르면 제품이 요금, 기능, 지원 범위, 적합 고객 조건의 후보를 가져옵니다. 담당자는 사실 대조에 쓸 항목과 기준 문구를 승인합니다. 제품이 찾은 오류는 처음에는 확인 필요 상태로 두고, 담당자가 답변 원문과 공식 정보를 보고 실제 오류인지 결정합니다.

문제 하나당 개선 카드 하나를 만듭니다. 카드에는 해당 질문, 답변 원문, 문제가 된 이유, 고객과 사업에 미칠 영향, 이번 주에 할 일을 담습니다. 카드의 순서는 고객 문제와 예상 영향으로 먼저 정합니다. 다만 근거가 약하면 바로 수정을 권하지 않고 먼저 살펴볼 항목만 제시합니다. 다음 행동은 자사 페이지 수정, 외부 정보 갱신 요청, 제품 근거 보완으로 나눕니다.

담당자가 행동을 완료하면 처음 문제가 발견된 질문을 다시 실행하고 이전 답변과 나란히 봅니다. 재확인 결과를 “이 행동 때문에 좋아졌다”는 증거로 쓰지는 않습니다. 이전과 같은 조건에서 답변이 달라졌는지만 기록합니다.

제가 자동 콘텐츠 생성보다 이 기능을 먼저 둔 이유는 고객 문제가 진단에서 끝나지 않는다고 보기 때문입니다. 상태를 모른 채 콘텐츠부터 늘리면 실행량은 늘어도 무엇이 좋아졌는지 설명하기 어렵습니다. 먼저 문제와 근거를 확인하고, 사람이 행동을 선택한 뒤, 결과를 다시 보는 과정이 필요합니다.

### 2-6. 두 기능을 먼저 제안한 이유

| 비교 항목 | 기능 1: 목표 질문 진단 | 기능 2: 개선 카드 |
|---|---|---|
| 답하는 질문 | 중요한 질문에서 어떤 역할로 등장하는가 | 무엇을 먼저 바꾸고 이후 답변이 달라졌는가 |
| 필요한 정보 | 목표 질문, 답변 원문, 경쟁사 결과 | 공식 정보, 문제 영향, 실행할 과제 |
| 사용자가 내리는 결정 | 우선 관리할 질문과 문제 | 이번 주 과제와 다음 측정 시점 |
| 다시 쓰는 시점 | 주간 상태를 볼 때 | 수정 결과를 보고 다음 과제를 정할 때 |

진단만 제공하면 결국 보고서로 끝납니다. 어떤 질문을 먼저 고칠지 정하고, 수정한 뒤 답변이 달라졌는지 다시 보는 데까지 있어야 담당자의 실제 업무가 됩니다.

### 2-7. 스퀘어스의 기존 자산을 어떻게 활용할 수 있는가

큐샵은 공개 기능 페이지에서 AI가 읽기 쉬운 텍스트 구조와 메타 정보 처리, AI 크롤러 방문 이력 대시보드를 제공한다고 설명합니다.[8]

큐샵의 AI 크롤러 방문 이력 옆에 실제 AI 답변에서 브랜드가 어떤 역할로 나왔는지를 보여줄 수 있습니다. 문제가 발견되면 해당 페이지나 콘텐츠를 바로 열어 수정하고 같은 질문을 다시 실행합니다.

저라면 GEO 진단을 별도 서비스로 떼기보다 큐샵의 페이지 관리 화면 안에 둡니다. 그래야 담당자가 진단 화면과 수정 화면 사이를 오가지 않아도 됩니다. 이 제안은 공개 기능만 보고 세운 것이므로, 실제 우선순위는 고객 사용 데이터와 인터뷰를 보고 정해야 합니다.

### 2-8. 성공을 어떻게 확인할 것인가

가장 먼저 볼 값은 온보딩을 마친 파일럿 계정 가운데 첫 4주 안에 중요한 문제 하나를 고르고, 행동과 재확인까지 마친 계정의 비율입니다. 4주는 기준선 확인, 한 차례의 수정, 재확인을 포함하기 위한 초기 운영 가정입니다.

다만 완주만으로 성공을 판단하지는 않습니다. 개선 과제를 다시 확인했을 때 추천 역할이 나아졌거나 사실 오류가 해소됐는지를 함께 봅니다. 이미 목표 상태인 질문의 유지는 개선 성과가 아니라 별도의 정기 관측 지표로 둡니다.

| 단계 | 측정할 값 | 성공 여부를 판단할 질문 |
|---|---|---|
| 시작 | 온보딩 완료율과 첫 진단까지 걸린 시간 | 질문을 정하는 과정에서 이탈하는가 |
| 결정·실행 | 첫 4주 안에 과제를 고르고 재확인까지 마친 계정 비율 | 진단이 실제 업무로 이어지는가 |
| 관측 결과 | 비교 가능한 개선 과제 재확인 중 추천 역할 개선 또는 사실 오류 해소가 관측된 비율 | 원하는 GEO 상태의 변화도 함께 나타나는가 |
| 신뢰 | 사람이 확인한 자동 분류의 일치율과 판단 불가율 | 검토 시간을 줄일 수준인가 |
| 조직 활용 | 결과를 공유한 계정 비율과 공유 뒤 다음 과제가 정해진 사례 | 결과가 내부 의사결정에 쓰였는가 |

초기 파일럿에서는 각 지표의 기준선과 사용 비용을 먼저 모읍니다. 목표치는 실제 사용자 행동을 확인한 뒤 정합니다. 관측된 변화는 제품 사용과 함께 나타난 결과로 기록하되, 특정 행동의 인과 효과로 단정하지 않습니다. 인터뷰에서는 “이 결과로 이번 주 할 일을 정할 수 있었는가”를 묻습니다.

### 2-9. 예상하는 위험과 대응

- **생성 결과의 변동:** 같은 질문과 가능한 한 같은 조건에서 여러 번 확인하고, 모델이나 검색 조건이 달라진 결과는 이전 구간과 분리합니다.
- **API와 소비자 화면의 차이:** 두 경로를 하나의 수치로 합치지 않고 어디에서 관측한 결과인지 밝힙니다.
- **자동 분류의 오류:** 답변 원문과 고객이 등록한 기준 정보를 함께 보여주고 사용자가 판정을 수정할 수 있게 합니다.
- **인과관계의 과장:** “해결”이라고 단정하기보다 관측된 변화와 재발 여부를 보여줍니다.
- **측정 비용의 증가:** 사용자가 승인한 우선 질문부터 다루고, 실제 행동으로 이어지지 않는 분석 항목은 추가하지 않습니다.
