출처 해석의 경계:

- [ReliableEval](https://aclanthology.org/2025.findings-emnlp.594/)은 의미를 유지한 질문 표현 변화와 반복 평가의 필요성을 지지한다. 그러나 표현 2개를 각각 3회 실행하면 충분하다고 말하지 않는다.
- [CheckEval](https://aclanthology.org/2025.emnlp-main.796/)은 주관적인 척도보다 분해된 이진 체크리스트가 LLM 평가자의 일관성과 해석 가능성을 높일 수 있음을 보여준다. 브랜드 사실 판정의 정확도나 Macro-F1 0.85를 직접 검증한 연구는 아니다.
- [Profound](https://help.tryprofound.com/articles/3443229936-answer-engine-insights-overview)와 [Peec AI](https://docs.peec.ai/metrics-overview)는 반복 수집, 브랜드 노출, 경쟁 비교, 출처 분석, 브랜드·출처 가시성 구분을 뒷받침한다.

따라서 출처 사용은 정직하지만 논문에서 제품 수치까지 직접 도출된 것으로 해석하면 안 된다.

#### 강점

12~14행에서 세 기준 모두 분자와 분모 또는 오류 건수로 바뀌었다. V5에서 상대적으로 약했던 사실 정확성도 `사실 일치율 + 중대 오류 건수`로 분리했다.

18행은 협업툴 도입 맥락에 보안·권한·연동·이관을 추가해 질문의 중요도를 제품 범주와 연결한다. 22행은 단순 나열을 추천에서 제외하고, 26행은 공식 정보 대조와 판단 보류를 둔다.

#### 남은 위험

`중대 오류 0건`은 좋은 가드레일이지만 중대성 판정 기준이 없다. 예를 들어 가격 오차, SSO 지원 여부, 데이터 보관 지역 오류가 모두 같은 중대성을 갖는지 정책이 필요하다.

또한 사실 일치율의 분모가 `사람이 검수한 사실 문장`이므로 어떤 문장을 검수 대상으로 추출했는지에 따라 값이 달라질 수 있다. 사실 문장 추출 재현율 또는 표본 추출 정책은 후속 과제로 남는다.

#### B1 문제와 사용자

38행은 V5의 두 페르소나를 그대로 유지하지 않고 하나의 담당자와 두 업무로 재정의한다. 45행은 사용자 구조와 확인 주기가 가설이라고 직접 선언하고 다음 결정을 연결한다.

- 월 1회 이하 또는 사건 중심이면 정기 리포트·사건 중심 사용 방식 검토
- 24시간 안의 확인 요구가 강하면 알림 우선순위 상승

이것은 단순히 “인터뷰하겠다”가 아니라 결과에 따라 제품 형태를 바꾸는 문제 가설이다.

수준 4가 아닌 이유는 비대상 사용자가 없고, 현재 문제 빈도·업무 비용·지불 의사에 관한 직접 근거가 아직 없기 때문이다. 인터뷰 계획을 구체화한 것이 사용자 근거 자체를 대신하지는 않는다.

#### B2 기능 경계

V6에서는 두 기능의 연결이 명확하다.

1. 변화가 큰 질문을 발견
2. 해당 답변의 원문·설명·출처 확인
3. 추가 조사 대상 또는 이상 없음 저장

기능 1은 데이터가 5개 미만이면 추세 대신 데이터 부족을 표시하고, 기능 2는 공식 정보가 없으면 오류를 확정하지 않는다. 각 기능의 실패 상태와 사용자 종료 상태가 생겼다.

#### B3 우선순위

54행에서 기능 후보를 다음 세 기준으로 비교했다.

- 핵심 질문에 직접 답하는가
- 후속 기능에 필요한 데이터를 만드는가
- 개발 전에 수동 검증할 수 있는가

56행에는 자동 질문 생성의 재검토 조건이 있고, 45행에는 알림의 재검토 조건이 있다. V5보다 명확히 좋아졌다.

그러나 `자동 질문 생성과 자동 사실 비교는 2개, 알림과 콘텐츠 생성은 1개`라는 결과만 있고 후보별로 어떤 기준을 충족·미충족했는지는 보이지 않는다. 또한 사용자 빈도, 오판 피해, 개발·운영 비용을 비교 기준에서 제외했다.

따라서 우선순위는 실무 충족 수준 3이며 우수 수준 4는 아니다.

#### B4 요구사항

다음 정책이 추가되어 개발 재질문이 크게 줄었다.

- 유효 답변: 정상 완료 + 분석 가능한 본문
- 6개 중 5개 미만이면 데이터 부족
- 단순 나열은 추천 제외
- 질문 표현·채널 변경 시 새 버전
- API와 소비자 화면 시계열 분리
- 등장 역할 자동 분류 사용자 수정
- 공식 정보 부재 시 오류 확정 금지

남은 개발 쟁점:

- `분석 가능한 본문`의 최소 조건
- 질문 표현 두 개의 의미 동등성 검수
- 같은 질문의 새 버전과 기존 버전을 화면에서 연결하는 방식
- 데이터 부족 이후 재수집과 비용 한도
- 소비자 화면 수집의 기술·정책상 허용 범위

#### B5 성공 측정

V5의 선택 편향 문제를 해결했다. 78행은 리포트를 열어본 계정이 아니라 `유효한 첫 리포트를 받은 계정`을 분모로 사용하고, 84~89행은 설정 시작부터 반복 가치까지 퍼널을 분리한다.

93행에서는 다음 실패 결정을 제시한다.

- 판단 전환 미달: 기능 추가보다 원문 확인·판단 저장 과정 재검토
- 반복 가치 미달 + 실제 확인 빈도 월 1회 이하: 구독형 대시보드 가설 재검토

다만 숫자가 많다고 자동으로 좋은 성공 측정은 아니다.

- 80%, 90%, 60%, 50%가 어떤 비용·기회비용을 기준으로 정해졌는지 없음
- Macro-F1 0.85와 정밀도 0.90을 계산할 최소 검수 표본 수가 없음
- 다섯 클래스의 불균형이 큰 경우 Macro-F1 변동성이 커질 수 있음
- 사실 오류는 정밀도만 높으면 놓치는 오류가 많아도 통과할 수 있으므로 재현율 또는 중대 오류 누락률이 필요함

현재는 내부 가설이라고 밝혔고 20개 이상 파일럿에서 성공 수와 전체 수를 같이 보겠다고 했으므로 수준 4를 유지한다. 면접에서는 숫자의 근거와 수정 규칙을 반드시 확인해야 한다.

C1 수준 4를 받으려면 `세 GEO 기준→사용자 실패→기능→제품 성공 지표→깨지는 가정`을 한 표로 연결해야 한다. 현재는 구성요소가 모두 있으나 독자가 직접 연결해야 하는 부분이 남아 있다.

| D2 주장 상태와 신뢰성 | 4 | 4/4 | 사용자 구조·빈도와 수치를 가설·내부 기준으로 명시하고 논문·제품 문서의 역할을 구분함 |
| D3 판단 소유권·과제 특화성 | 3 | 3/4 | 협업툴 질문, 역할 통합, 제품 형태 역전 조건, 제외 판단이 있어 정석 구조를 자기 판단으로 전환함. 직접 사용자 근거나 비전형적 통찰은 없음 |

## 4. AI 및 답안 구별력 진단

- AI 문체 위험: **중간**
- AI 생성 용이성: **높음**
- 판단 소유권·과제 특화성: **수준 3, 3/4점**

### 명사 치환 검사 — 위험 중간~높음

보안·권한·연동·이관이 추가되어 협업툴 맥락은 V5보다 강하다. 그러나 핵심 구조인 추세 진단→원문·출처 확인→판단 저장은 다른 B2B SaaS에도 그대로 적용할 수 있다.

### 과제 문구 재배열 검사 — 위험 높음

`얼마나`는 노출·추천 흐름, `어떻게`는 설명·출처 진단으로 여전히 직접 변환된다. 이 구조는 정확하지만 전형적이다.

### 표준 PM 템플릿 검사 — 위험 높음

문제 가설, 인터뷰 임계값, 기능 비교, 세부 요구사항, 퍼널 KPI, 소규모 테스트, 20개 계정 파일럿이 빈틈없이 배치됐다. 문서 품질은 높지만 평가 기준을 입력한 생성형 AI가 만들기 쉬운 완결 구조이기도 하다.

특히 다음 수치 밀도는 실제 근거보다 `정교해 보이는 PRD` 인상을 줄 수 있다.

- 인터뷰 8명 중 5명
- 사용성 테스트 5명 중 4명
- 질문 표현 2개×3회
- 6개 중 5개 미만
- 설정 80%, 첫 리포트 90%, 첫 가치 80%, 판단 60%, 반복 50%
- Macro-F1 0.85, 정밀도 0.90

모두 내부 가설이라고 밝혀 신뢰성 문제는 아니지만, 왜 그 숫자인지 물으면 대부분 방어가 어렵다.

### 근거-결정 고유성 검사 — 위험 중간

V6는 근거가 결정에 일부 연결된다.

- ReliableEval→단일 표현·단일 답변 대신 표현과 반복
- CheckEval→종합 점수보다 근거 문장과 수정 가능한 분류
- 경쟁 제품 조사→반복 수집과 출처 분석은 기반 기능, 종합 점수·콘텐츠 생성은 제외

다만 논문이 현재 반복 횟수와 품질 목표를 정한 것은 아니며, 경쟁 제품의 빈틈을 실제 사용자 문제로 확인한 것도 아니다.

### 반증·역전 검사 — 위험 낮음

V6에서 가장 크게 개선된 부분이다.

- 낮은 확인 빈도→정기 리포트·사건 중심 방식
- 높은 긴급성→알림 우선순위 상승
- 질문 설정 실패→자동 질문 생성 우선순위 상승
- 반복 가치 미달→구독형 대시보드 가설 재검토

### 사람의 판단이 보이는 반대 증거

- 두 직무를 억지로 두 명의 페르소나로 고정하지 않음
- 데이터 부족 상태를 별도 표시
- 질문·채널 변경 시 새 버전 생성
- 자동 분류 사용자 수정
- 오류 확정과 판단 보류 구분
- 성공하지 않으면 기능을 추가하지 않고 제품 형태까지 재검토

따라서 생성 용이성은 높지만 D3은 V5의 수준 2에서 수준 3으로 상승한다.

## 7. 이해관계자별 평가

### 채용 담당자

과제 형식, 논리, 문서 완결성, 사실 상태 구분은 강하다. 서류 단계에서는 상위권으로 넘길 가능성이 높다. 다만 AI와 평가 기준을 이용해 매우 정교하게 다듬은 인상이 있어 면접 소유권 검증이 필요하다.

### CEO·대표

사용 빈도가 낮으면 구독형 대시보드 자체를 재검토하는 판단이 좋다. 기능을 지키기보다 사업 가설을 버릴 수 있다는 신호다.

반면 문제의 실제 빈도와 지불 의사는 여전히 확인 전이다. 20개 파일럿을 하기 전에 이 문제가 반복 과금 가능한 문제인지, 리포트·컨설팅·대행 서비스가 더 적합한지 확인해야 한다.

### 시니어 PM

V5 피드백을 정확히 구조화해 반영했다. 기능 정책과 검증 루프는 강하다. 그러나 후보 비교가 `3개 중 몇 개 충족`으로 단순화돼 기준 간 중요도와 비용 차이가 사라졌다. 세 체크를 모두 충족해도 비싼 기능보다 두 체크만 충족하지만 핵심 사용가치가 높은 기능이 우선일 수 있다.

### 개발자

구현 논의를 시작할 수 있는 수준이다. 상태값, 분모, 결측, 버전, 수정 권한이 들어갔다.

추가 결정이 필요한 부분:

- 소비자 UI 수집 방식과 이용약관·안정성
- 질문 표현의 의미 동등성
- 재시도 횟수와 수집 비용 한도
- 자동 분류 변경 이력과 재집계
- 공식 정보 버전과 사실 판정 시점

### 디자이너

발견→원문 확인→판단 저장 흐름은 명확하다. 데이터 부족, 판단 보류, 이상 없음 상태도 생겼다.

반면 초기 설정에서 브랜드·경쟁사·질문 3개·표현 2개·기대 설명 3개를 입력해야 한다. 자동 질문 생성을 뒤로 미뤘기 때문에 10분 설정 목표와 충돌할 수 있다. 이 충돌 자체가 첫 사용성 테스트의 핵심 가설이다.

### 데이터·AI 품질 관점

Macro-F1과 정밀도를 사용한 것은 단순 정확도보다 낫지만 다음을 정의해야 한다.

- 검수 표본 크기와 추출 방식
- 다섯 역할 클래스의 불균형
- 검수자 간 불일치 해결
- 사실 오류의 정밀도뿐 아니라 재현율 또는 중대 오류 누락률
- 질문 표현·반복 수가 충분한지 판단하는 변동성 기준

## 8. P0 수정 세 가지

### P0-1. 기능 후보 비교를 감사 가능한 표로 바꾼다

후보별로 세 기준의 충족 여부를 보여주고 `사용 빈도 / 오판 피해 / 구현·운영 비용`을 추가한다. 단순 충족 개수 합산이 아니라 왜 특정 기준을 더 중요하게 봤는지 적는다.

예상 영향: B3 수준 3→4, 최대 +3점

### P0-2. 정밀 수치를 줄이고 교정 규칙을 추가한다

현재 숫자를 모두 삭제할 필요는 없다. 다음처럼 구분한다.

- 근거가 있는 값
- 파일럿을 시작하기 위한 임시값
- 파일럿 후 다시 정할 값

Macro-F1·정밀도에는 최소 검수 표본과 신뢰구간 또는 성공 수·전체 수를 함께 쓰고, 사실 오류에는 중대 오류 누락률을 추가한다. 설명할 수 없는 숫자는 범위 또는 의사결정 문장으로 바꾼다.

예상 영향: 원점수보다 AI 문체 위험과 면접 방어력 개선

### P0-3. 협업툴이라서 달라진 하나의 제품 결정을 만든다

보안·권한·연동·이관을 질문 예시로만 두지 말고 기능 또는 우선순위를 바꾸는 근거로 사용한다. 예를 들어 구매·도입 질문을 일반 질문보다 먼저 진단하거나, 중대 오류를 가격·보안·데이터·연동으로 구분해 대응 우선순위를 다르게 둘 수 있다.

실제 사용자 근거가 없다면 가설로 표시하고 어떤 인터뷰 결과로 유지·폐기할지 연결한다.

예상 영향: B1 또는 D3의 수준 4 가능성, AI 생성 용이성 완화

## 9. 면접에서 반드시 검증할 질문

3. 자동 질문 생성과 자동 사실 비교가 각각 세 기준 중 무엇을 충족·미충족하는지 표 없이 설명해달라.

5. 협업툴 대신 HR SaaS를 대상으로 하면 현재 PRD에서 반드시 달라져야 하는 세 가지는 무엇인가?

## 10. 한 문장 최종 평가

**V6는 V5의 결함을 실제 정책·분모·반증 조건으로 해결해 89점의 강한 과제로 올라왔지만, 핵심 제품 구조와 수치 중심의 완결성은 여전히 AI로 쉽게 재생산할 수 있으므로 면접에서는 숫자를 외웠는지가 아니라 왜 이 구조와 기준을 선택했고 어떤 증거에서 버릴 수 있는지를 검증해야 한다.**
