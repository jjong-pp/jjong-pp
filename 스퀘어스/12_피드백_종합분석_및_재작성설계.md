# 피드백 종합 분석과 V3 재작성 설계

## 1. 결론

기존 제출본의 문제는 GEO 지식이나 조사량의 부족이 아니다. 오히려 조사한 내용을 너무 많이 남긴 탓에 과제에서 보려는 핵심 역량인 직접적인 답변, 기능을 두 개로 자르는 판단, 우선순위의 근거가 흐려졌다.

현재 V2는 리서치 메모로는 수준이 높지만 채용 과제로는 위험하다. 읽는 사람은 “많이 조사했다”보다 “질문보다 크게 설계한다”, “반론을 모두 막느라 핵심을 늦게 말한다”, “생성형 AI가 만든 완결형 보고서 같다”는 인상을 받을 수 있다.

## 2. 멀티에이전트 구성과 진행 방식

세 가지 관점을 독립적으로 검토했다.

1. GEO 제품 리서처
   Gewriter, Profound, Peec AI, Scrunch의 공개 자료를 확인해 질문 수집 방식, 답변 수집 방식, 주요 지표, 공개되지 않은 부분을 나눴다.
2. B2B SaaS 시니어 PM
   문제 정의, 가설, 기능 두 개의 경계, 선후 관계, 실험과 성공 지표를 PRD 관점에서 검토했다.
3. 한국 스타트업 채용 과제 심사자
   동문서답, 문서 분량, 기호와 표의 사용, 출처 방식, 지원자 목소리, AI 문체 위험을 검토했다.

세 관점의 공통 결론은 다음과 같다.

- 경험담으로 시작하지 말고 첫 문장에서 GEO의 기준을 정의해야 한다.
- 기존 세 번째 기준인 “고친 뒤에도 유지되거나 나아지는가”는 좋은 GEO의 상태보다 개선 실험 절차에 가깝다.
- 기능 1과 기능 2 안에 너무 많은 하위 기능이 묶여 있다.
- “우선 행동 카드”는 담당자가 물은 “어떻게 노출되는가”보다 한 단계 뒤의 해결책이다.
- 외부 시장 통계보다 담당자의 현재 행동과 불편, 경쟁 도구의 공통 측정 구조가 기능 우선순위의 직접적인 근거다.
- 큐샵 자산 연결, 자동화 전환 조건, API와 소비자 화면의 세부 운영, 장문의 위험 관리는 제출 본문에서 빼는 편이 낫다.

## 3. 기존 문항 1의 문제

### 3-1. 질문보다 경험이 먼저 나온다

V2는 “현재 이커머스 유통사에서 일하며 최근 GEO 도입을 검토했습니다”로 시작한다. 그러나 직접 한 역할과 결과가 구체적이지 않고, 질문은 경험이 아니라 좋은 GEO의 기준을 묻고 있다. 피드백에서 이미 동문서답처럼 보인다고 지적된 부분이 그대로 남아 있어 더 큰 감점 요인이 된다.

### 3-2. 세 기준의 층위가 섞여 있다

기존 첫 번째 기준에는 중요한 질문, 반복 실행, 노출, 추천, 경쟁 위치가 한꺼번에 들어 있다. 두 번째 기준에는 등장 역할, 추천 이유, 사실 정확성이 묶여 있다. 세 번째 기준은 수정 뒤 재측정하는 업무 절차다. 세 기준이 같은 수준의 결과 상태가 아니고 일부는 서로 겹친다.

V3에서는 결과 상태를 다음처럼 다시 나눴다.

- 중요한 질문에서 발견되는가
- 경쟁사와 비교해 선택되는가
- 정확하고 신뢰할 수 있게 설명되는가

반복 측정은 세 번째 기준으로 두지 않고 세 기준 모두에 적용하는 측정 원칙으로 내렸다.

### 3-3. 근거가 결론보다 앞선다

기존 답안의 논문 수치와 자료 한계는 사실을 조심스럽게 다룬다는 장점이 있다. 그러나 채용 과제 본문에서는 기준을 이해하는 데 필요한 시간보다 수치의 적용 범위를 해석하는 시간이 더 길어진다. V3에서는 학술 수치와 거시 시장 통계를 빼고, 공개된 GEO 제품이 실제로 사용하는 측정 구조만 짧게 참고했다.

## 4. 기존 PRD의 문제

### 4-1. 명목상 기능 두 개지만 실제로는 여러 에픽이다

기존 기능 1에는 온보딩, 질문 생성, 사용자 승인, 반복 수집, 역할 분류, 경쟁 분석, 대시보드, 공유가 들어 있다. 기능 2에는 역할 분석, 사실 확인, 출처 분석, 우선순위 계산, 행동 제안, 재측정이 들어 있다. 기능 이름은 두 개지만 개발 범위는 두 개의 제품군에 가깝다.

V3에서는 기능의 경계를 사용자 질문에 맞췄다.

- 기능 1. 핵심 질문별 AI 노출 모니터링: “얼마나”에 답한다.
- 기능 2. 답변 맥락과 출처 분석: “어떻게”에 답한다.

자동 콘텐츠 생성, 게시, 자동 개선안, 실시간 알림, 다국가와 다브랜드 관리는 후순위로 뺐다. 결과 저장과 공유는 각 기능의 사용을 확인하기 위한 최소 동작만 남겼다.

### 4-2. 문제 정의보다 해결책이 앞선다

기존 글은 담당자가 “이번 주에 할 일 하나를 고르고 싶다”고 가정하고 행동 카드를 핵심 기능으로 잡았다. 하지만 과제에서 확인된 요구는 자사 브랜드가 얼마나, 어떻게 노출되는지 알고 싶다는 것이다. 사용자가 행동 추천까지 원하는지는 별도로 검증해야 한다.

V3는 현재 행동을 먼저 적었다. 담당자는 직접 질문하고 스크린샷을 남기지만, 결과 변동 때문에 현재 상태와 경쟁사 차이, 등장 맥락과 출처를 설명하기 어렵다. 여기서 두 개의 문제 가설을 만들고 각각 한 기능에 연결했다.

### 4-3. 우선순위 설명의 비중이 거꾸로다

V2는 과제의 핵심인 “왜 이 두 기능이 먼저인가”를 짧은 문단으로 끝내고, 파일럿 조건, 위험, 출처의 한계를 더 길게 설명했다. V3는 사용자 요구 직접성, 선행 관계, 개발 전 검증 가능성 세 가지 기준으로 우선순위를 설명한다.

### 4-4. 성공 지표의 층위가 섞여 있다

기존 표에는 활성화, 분석 정확도, 수동 운영 비용, 재측정, 노출 개선이 한꺼번에 들어 있었다. V3의 핵심 지표는 리포트를 본 뒤 근거 문장과 출처가 포함된 이슈를 저장하거나 공유한 계정 비율이다. 보조 지표는 첫 가치, 이해, 분석 사용, 반복 가치, 분석 품질로 나눴다.

초기 제품이 외부 AI 서비스의 답변을 직접 통제하지 못하므로 노출률 상승은 첫 제품 성공 지표에서 제외했다. 이는 제품 사용과 데이터 품질을 먼저 검증하기 위한 선택이다.

## 5. 공개 GEO 도구 조사에서 반영한 내용

Gewriter는 URL을 바탕으로 타깃 키워드와 구매 여정별 질문을 만들고 ChatGPT와 AI Mode에서 브랜드, 도메인, URL 노출을 측정한다고 설명한다. 다만 GEO 점수 산식, 질문 원천, 반복 횟수와 수집 조건은 공개 자료에서 확인되지 않았다. 소개서의 30페이지 기준과 홈페이지의 50페이지 기준도 서로 달라 해당 주장은 객관적 기준으로 사용하지 않았다.

Profound는 프롬프트를 주제와 태그로 관리하고 매일 실행해 Visibility, Share of Voice, Position, Citation, Sentiment와 실제 답변을 연결한다. Peec AI도 질문을 여러 AI 서비스에서 정기 실행한 뒤 노출, 경쟁 위치, 감성, 원문 답변과 출처를 제공한다. 브랜드가 답변에 등장하는 것과 자사 콘텐츠가 출처로 사용되는 것을 구분한다는 점도 확인했다.

이 조사에서 가져온 것은 특정 제품의 점수나 마케팅 주장이 아니다. 질문을 먼저 정하고, 반복 수집한 정량 결과에서 실제 답변과 출처로 내려가는 공통 제품 구조만 V3에 반영했다.

## 6. 3회 자체 평가와 수정 결과

### 1차 평가: 문항 적합성

평가 질문은 “문항 1에 바로 답하는가”, “정확히 세 기준인가”, “PRD 필수 항목이 있는가”, “기능이 정확히 두 개인가”, “왜 먼저인지 분명한가”였다.

초안은 내용상 91점으로 평가했지만 표가 6개라 다시 템플릿 문서처럼 보일 위험이 있었다. 제품 개요와 우선순위 표를 문장으로 바꿔 표를 4개로 줄였다. 기능 1과 기능 2가 각각 “얼마나”와 “어떻게”에 답한다는 문장을 우선순위의 첫 근거로 올렸다.

### 2차 평가: 제품 논리와 실현 가능성

평가 질문은 “입력, 처리, 출력, 예외가 연결되는가”, “두 기능의 선후 관계가 맞는가”, “지표 정의가 일관적인가”, “개발 전에 시험할 수 있는가”였다.

초안은 89점으로 평가했다. 기준표의 평균 등장 위치와 기능 요구사항의 추천률이 어긋나 있었고, 수집 실패와 미노출을 구분할 기록이 부족했다. 추천률 정의를 하나로 통일하고, 표시된 모델, 언어, 실행 시각, 검색 사용 여부, 성공 여부를 저장하도록 수정했다. 주 1회 기본 수집 주기와 5분 이내 과업 완료 조건도 명시했다.

### 3차 평가: 문체와 제출 완성도

평가 질문은 “첫 문장이 답인가”, “지원자의 판단이 보이는가”, “불필요한 면책과 기호가 없는가”, “읽는 사람이 한 번에 이해할 수 있는가”였다.

최종 원고는 약 6,700자, 제목 15개, 표 4개다. V2에서 AI 문체로 지적받은 긴 대시, 가운뎃점, 백틱, 출처 2-A 같은 내부 참조 표기를 제거했다. 참고자료는 Gewriter, Profound, Peec AI 세 묶음으로 줄였고, 경쟁 제품 설명도 기능 선택에 필요한 한 문단만 남겼다. 최종 평가는 94점으로 판단했다.

## 7. 최종 산출물 원칙

- 별도 표지 없이 제목, 지원자, 작성일로 시작한다.
- 문항 1은 첫 문장에서 정의하고 세 기준을 한 페이지 안에서 이해할 수 있게 한다.
- PRD는 제품 개요, 문제와 가설, 사용자 시나리오, 기능 두 개, 우선순위, 프로토타입, 성공 지표 순서로 구성한다.
- 본문은 약 4쪽에서 6쪽을 목표로 하고 참고자료는 마지막에 짧게 둔다.
- Word에서는 맑은 고딕 계열 글꼴, 단순한 회색 표, 넉넉한 여백을 사용한다.
- 조사 과정과 상세 산식은 제출본이 아니라 면접 대비 자료에 남긴다.

## 8. V4 재분석에 추가로 사용한 피드백

V3 총평은 제출 가능한 수준이지만 면접 대상을 결정할 만큼 선명하지는 않다고 평가했다. 특히 다음 네 가지 지적은 타당하다고 판단했다.

- 인터뷰로 확인했다고 쓴 뒤 다시 인터뷰를 계획하는 문장은 사실관계와 시제가 충돌한다.
- 기능 이름은 두 개지만 각 기능 안에 여러 에픽이 들어 있어 MVP 범위가 커 보인다.
- 반복 측정의 횟수, 주기, 조건, 분모가 닫혀 있지 않으면 지표를 재현할 수 없다.
- 문제를 찾은 경우만 성공으로 세면 이상이 없음을 확인한 정상 사용을 놓친다.

반면 V3의 문장 몇 개만 고치는 방식은 채택하지 않았다. 사용자가 직접 지적한 핵심 문제는 개별 오류보다 2번 문항의 구조와 분량이었다. 따라서 제품 개요, 별도 가설 목록, 프로토타입 장, 장문의 우선순위 설명을 유지한 채 국소 수정하면 같은 문제가 반복된다고 봤다.

## 9. V4의 재작성 원칙

V4는 지금까지의 결정 중 사용자가 직접 밝힌 가치관과, AI에게 위임한 구현 세부를 구분해 반영했다.

### 유지한 판단

- 기술보다 고객이 실제로 확인하려는 문제에서 시작한다.
- 모든 질문을 같은 값으로 보지 않고 사용자가 중요한 질문을 확정한다.
- 단순 노출과 선택지로 추천되는 것을 구분한다.
- 긍정적인 표현보다 실제 강점, 적합한 고객, 가격과 기능의 정확성을 본다.
- 자동 판정은 근거 문장을 보여주고 사람이 수정하거나 판단을 보류할 수 있어야 한다.
- 수치는 다음 판단으로 이어져야 하지만 자동 개선안과 콘텐츠 실행은 MVP에서 제외한다.
- 한 번의 결과를 성과로 보지 않고 같은 조건에서 다시 확인한다.
- 실행하지 않은 인터뷰나 파일럿을 결과처럼 쓰지 않는다.

### 줄이거나 바꾼 부분

- 문항 1의 경험담과 시장 통계를 삭제하고 첫 문장에서 좋은 GEO를 정의했다.
- 세 기준을 발견, 이해, 개선으로 정리해 답변의 기억점을 만들었다.
- 문항 2의 제품 개요를 삭제하고 문제와 사용자 다음에 기능 2개와 선정 근거를 바로 배치했다.
- 기능 1은 질문 확정, 반복 수집, 지표, 원문 이동의 네 요구사항으로 닫았다.
- 기능 2는 등장 맥락, 사실 확인 대상, 출처, 사용자 판단의 네 요구사항으로 닫았다.
- 사실 확인은 공식 기준 정보가 없는 상태에서 자동 정답을 내리지 않고 “확인이 필요한 사실”을 표시하는 수준으로 낮췄다.
- 성공 지표에 “추가 조사 필요”뿐 아니라 “이상 없음” 판단도 포함했다.
- 자동 질문 생성, 다국가와 다브랜드, 자동 사실 비교, 알림, 콘텐츠 생성과 게시, 고급 공유는 후순위로 명시했다.

## 10. V4의 측정 계약

측정 결과를 비교할 수 있도록 MVP 기본값을 다음과 같이 닫았다.

- 주기: 주 1회
- 반복: 질문별, AI 서비스별 3회
- 동일 조건: 질문 문구, AI 서비스, 언어, 검색 설정, 수집 채널
- 분모: 수집에 성공한 유효 답변만 포함하며 실패는 미노출에서 제외
- 노출률: 자사가 등장한 유효 답변 수를 전체 유효 답변 수로 나눈 값
- 추천률: 추천 또는 비교 의도 질문에서 자사가 적합한 선택지로 제시된 유효 답변 비율
- 변경 처리: 측정 조건이 바뀌면 이전 결과와 같은 시계열로 합치지 않음

3회와 주 1회는 검증된 시장 표준이 아니라 첫 MVP 운영 가정이다. 파일럿에서 답변 변동성과 수집 비용을 확인한 뒤 조정해야 한다.

## 11. 공개 제품 재확인 결과

2026년 8월 16일 기준 공식 자료를 다시 확인했다. Profound는 사용자가 관리하는 프롬프트를 AI 답변 엔진에 반복 실행하고 Visibility, Share of Voice, Position, Citation과 실제 답변을 연결한다. Peec AI는 브랜드가 답변에 언급되는 Brand Visibility와 자사 도메인 또는 콘텐츠가 사용되는 Source Visibility를 구분한다. Gewriter는 구매 여정별 질문을 기준으로 브랜드, 도메인, URL 노출을 진단한다고 설명한다.

V4에는 특정 경쟁 제품의 종합 점수나 성과 주장을 가져오지 않았다. 세 제품에서 공통으로 확인되는 질문 단위 측정, 경쟁 비교, 원문과 출처 확인이라는 기본 구조가 두 기능 선택과 어긋나지 않는지 확인하는 데만 사용했다.

## 12. V4 3회 자체 평가

### 1차: 문항 적합성과 분량

- 문항 1은 첫 문장에서 정의하고 정확히 세 기준과 근거를 제시했다.
- 문항 2는 과제가 요구한 문제 정의, 핵심 사용자와 시나리오, 기능 요구사항, 성공 측정 기준을 포함한다.
- 최우선 기능은 정확히 두 개이며 각 기능이 “얼마나”와 “어떻게”에 직접 답한다.
- 분량은 약 4,100자로 V3 약 6,700자보다 약 38% 줄었다.

평가: 94점. 요구사항 누락 없이 구조를 줄였지만 참고 자료까지 포함하면 여전히 한 번 더 압축할 여지는 있다.

### 2차: 제품 논리와 측정 가능성

- 문제, 기능, 출력, 사용자 판단, 성공 지표가 한 흐름으로 이어진다.
- 추천률을 모든 질문에 적용하지 않고 추천 또는 비교 의도 질문으로 분모를 제한했다.
- 출처와 사실 정확성을 같은 개념으로 보지 않았다.
- 반복 횟수, 주기, 조건, 실패 처리와 시계열 분리 기준을 명시했다.

평가: 88점. 측정 계약은 닫혔지만 3회와 주 1회는 아직 사용자 가치와 비용으로 검증하지 않은 가정이다. AI 서비스별 허용 수집 방식도 구현 전에 별도로 확인해야 한다.

### 3차: 가독성, 문체, 차별성

- 제품 개요와 장문의 실험 설계를 빼고 기능 선정 근거가 먼저 보이게 했다.
- 긴 대시, 가운뎃점, 내부 출처 번호, 거시 시장 통계, 과장된 수치를 사용하지 않았다.
- 차별점은 새로운 분석 지표를 많이 제시하는 데 두지 않고, 중요한 질문의 승인, 추천과 노출의 구분, 근거를 본 뒤 사람이 판단하는 흐름에 뒀다.

평가: 90점. V3보다 지원자의 판단은 선명하지만 기능 조합 자체는 GEO 도구의 기본 범주에 속한다. 실제 B2B SaaS 담당자 인터뷰가 없으므로 사용자 문제의 강도와 업무 빈도는 아직 가설이다.
