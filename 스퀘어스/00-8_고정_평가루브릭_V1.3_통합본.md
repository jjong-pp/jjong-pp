## 1. 이 평가의 목적

이 과제는 GEO 지식을 많이 아는 사람을 뽑는 퀴즈가 아니다. 스퀘어스가 실제로 찾는 PM의 다음 능력을 제한된 문서 안에서 관찰하는 직무 표본이다.

1. 표준이 없는 개념을 사용자에게 의미 있는 기준으로 정의하는가
2. 모호한 고객 요구를 문제와 결정의 언어로 바꾸는가
3. 가능한 기능 중 두 개만 선택하고 나머지를 버릴 수 있는가
4. 개발자·디자이너가 논의를 시작할 수 있는 PRD를 쓰는가
5. AI 제품의 변동성과 오류를 측정·운영 정책에 반영하는가
6. 결과가 틀리면 기능뿐 아니라 문제·사업 가설도 바꿀 수 있는가
7. AI의 도움을 받더라도 자신의 근거와 판단으로 답안을 소유하는가

평가의 중심 질문은 다음 한 문장이다.

> 이 지원자는 불확실한 GEO 시장에서 고객 문제를 발견하고, 근거를 통제하며, 작은 제품으로 검증하고, 결과에 따라 다음 결정을 내릴 수 있는가?

## 2. 무엇을 평가하고 무엇을 평가하지 않는가

### 과제에서 직접 평가하는 것

- GEO 개념 정의와 기준 설정
- 사용자 문제와 핵심 시나리오
- 기능 선택과 우선순위
- 요구사항과 정책 명확성
- 성공 지표와 검증 계획
- AI·GEO 현실성
- 문서 전달력과 주장 신뢰성
- 판단 소유권과 과제 특화성

### 과제만으로 직접 평가하지 않는 것

- 실제 협업과 갈등 조정
- 권한 없이 조직을 설득하는 능력
- 개발 일정과 운영 프로세스 관리 성과
- 장기적인 제품 성과
- 발표력과 대면 커뮤니케이션
- 실제 AI 도구 사용 과정

이 항목들을 문서 점수에 억지로 섞지 않는다. 과제 통과 후 구조화 면접에서 별도로 확인한다.

## 3. 기준을 만든 근거

### 과제 원문

1. 좋은 GEO의 기준 정확히 세 개
2. 담당자에게 가장 필요한 기능 정확히 두 개
3. 두 기능을 최우선으로 판단한 근거
4. 문제 정의
5. 핵심 사용자와 시나리오
6. 주요 기능 요구사항
7. 성공 측정 기준

### 공고의 직무 요구

- GEO 시장과 경쟁 서비스 리서치
- PRD·기능정의·정책 문서 작성
- 논리적인 문제 발견과 주도적 해결
- 생성형 AI 도구의 실무 활용
- 개발자·디자이너와의 명확한 커뮤니케이션
- 0→1 신규 서비스의 기획·개발·출시·운영

### 공개된 선발·평가 원칙

- 직무 분석과 평가 내용이 직접 연결돼야 한다.
- 실제 직무 산출물과 가까운 과제가 내용 타당성이 높다.
- 동일 질문·동일 척도·행동 기준을 사용해야 평가자 편차가 줄어든다.
- 한 가지 도구만으로 모든 역량을 측정하지 않고 과제와 면접을 분리한다.
- 평가가 실제 직무 성과와 연결되는지는 지속적으로 검증해야 한다.

## 4. 전체 평가 구조

평가는 점수 하나로 끝내지 않고 다섯 관문으로 진행한다.

| 순서 | 관문 | 확인 내용 | 점수로 상쇄 가능 여부 |
|---:|---|---|---|
| 0 | 과제 완결성 | 질문과 필수 구성요소를 실제로 답했는가 | 불가 |
| 1 | 신뢰성 | 허위 실행, 출처 조작, 사실 상태 왜곡이 없는가 | 불가 |
| 2 | 100점 직무 표본 | A~D의 관찰 가능한 PM 역량 | 가능 |
| 3 | 핵심 역량 최저선 | 총점이 높아도 핵심 PRD 역량이 무너지지 않았는가 | 불가 |
| 4 | 구조화 면접 | 문서 소유권, 협업, 적응적 판단이 확인되는가 | 과제 점수와 별도 |

## 5. 관문 0: 과제 완결성

다음 중 하나라도 해당하면 `과제 미완결`이다. 진단용 점수는 계산하지만 진행 권고를 줄 수 없다.

- 문항 1 또는 문항 2가 없음
- 좋은 GEO의 기준이 정확히 세 개가 아님
- 최우선 기능이 정확히 두 개가 아님
- 문제 정의가 실질적으로 없음
- 핵심 사용자·시나리오가 실질적으로 없음
- 주요 기능 요구사항이 실질적으로 없음
- 성공 측정이 실질적으로 없음
- 두 기능의 최우선 선정 근거가 실질적으로 없음

제목의 존재가 아니라 실제 내용을 본다. 다른 목차 안에 내용이 명확하게 있으면 충족이다.

### 이 관문이 필요한 이유

과제에서 명시한 핵심 요구를 지키는 것은 PM의 기본적인 요구사항 해석 능력이다. 다른 부분이 뛰어나도 기능을 세 개 제안하거나 성공 측정을 생략하면 과제 자체를 다르게 푼 것이다.

## 6. 관문 1: 신뢰성

다음이 확인되면 `신뢰성 Fail`이다.

- 실행하지 않은 인터뷰·실험·파일럿·성과를 완료한 것처럼 작성
- 존재하지 않는 출처나 데이터 생성
- 출처가 지지하지 않는 수치를 검증된 사실처럼 반복적으로 왜곡
- 가정과 계획을 실제 사용자 사실이나 제품 성과처럼 표현
- 과거형·미래형을 의도적으로 혼용해 실행 범위를 부풀림

단순 해석 오류나 출처 적용 범위의 논쟁은 바로 Fail 처리하지 않는다. A4 또는 D2에서 평가하고 `검증 필요`로 남긴다.

### 이 관문이 필요한 이유

GEO는 표준이 없고 외부 검증이 어려운 시장이다. 이런 시장에서는 모르는 것을 명확히 말하는 능력이 그럴듯한 확신보다 중요하다. 허위 실행과 근거 조작은 제품 판단 능력으로 상쇄할 수 없는 신뢰 문제다.

## 7. 100점 배점과 배점 이유

| 영역 | 배점 | 배점 이유 |
|---|---:|---|
| A. 좋은 GEO 기준 | 24 | 신생 시장을 스스로 정의하고 측정하는 능력 |
| B. PRD | 48 | 실제 채용 포지션의 가장 직접적인 직무 표본 |
| C. 연결·0→1 판단 | 16 | 문항 두 개를 별도 모범답안이 아닌 하나의 제품 논리로 만드는 능력 |
| D. 소통·신뢰성·과제 특화성 | 12 | 좋은 판단을 타인이 이해하고 신뢰하며 지원자의 판단으로 구별할 수 있는지 |
| **합계** | **100** |  |

B3 우선순위에 단일 최고 배점인 12점을 준다. 과제에서 직접 `왜 이 두 기능을 최우선으로 판단했는지`를 요구하고, 0→1 PM의 핵심은 기능을 많이 생각하는 것보다 지금 만들 것과 버릴 것을 정하는 일이기 때문이다.

문서 표현 영역은 12점으로 제한한다. 글이 예쁘다는 이유로 문제 정의나 제품 판단의 약점을 덮지 못하게 하기 위해서다.

## 8. 공통 행동수준과 계산법

모든 세부 항목은 0~4 행동수준으로 판정한다.

| 수준 | 의미 | 판정 기준 |
|---:|---|---|
| 0 | 부재·모순 | 요구 내용이 없거나 핵심 전제가 무너짐 |
| 1 | 언급 | 제목이나 용어는 있으나 실제 결정에 사용할 수 없음 |
| 2 | 부분 충족 | 방향은 맞지만 중요한 조건을 평가자가 보완해야 함 |
| 3 | 실무 충족 | 사소한 확인만으로 동료가 판단과 다음 행동을 이해할 수 있음 |
| 4 | 우수 | 대안·경계·실패 조건까지 있어 재작업과 오판 위험을 크게 줄임 |

점수 계산은 `배점 × 행동수준 ÷ 4`다.

- 4점 항목: 0 / 1 / 2 / 3 / 4점
- 8점 항목: 0 / 2 / 4 / 6 / 8점
- 12점 항목: 0 / 3 / 6 / 9 / 12점

모든 항목이 수준 3이면 정확히 75점이다. 따라서 75점은 임의의 합격 숫자가 아니라 모든 관찰 역량이 실무 충족 수준이라는 뜻이다.

## 9. A. 좋은 GEO의 기준: 24점

### A1. 질문에 대한 직접 답변: 4점

#### 무엇을 보는가

“GEO를 잘하고 있다”는 상태를 먼저 정의하고 정확히 세 기준으로 답했는가.

#### 왜 보는가

경험담이나 시장 통계보다 질문의 핵심을 먼저 정의하는 능력은 PM 문서의 기본이다. 정의하지 못하면 이후 지표와 기능도 흔들린다.

| 수준 | 판정 |
|---:|---|
| 0 | 정의가 없거나 기준이 세 개가 아님 |
| 1 | 세 제목은 있으나 SEO 수단·기능 목록에 가까움 |
| 2 | 정의와 세 기준은 있으나 결과 상태와 실행 수단이 섞임 |
| 3 | 첫 부분에서 좋은 GEO를 직접 정의하고 세 결과 기준으로 답함 |
| 4 | 수준 3 + 적용 범위와 이 기준으로 내릴 사용자 판단까지 간결함 |

### A2. 세 기준의 구별성과 중요도: 8점

#### 무엇을 보는가

세 기준이 다른 실패를 다루며 함께 볼 이유가 있는가.

#### 왜 보는가

노출률·언급률·가시성처럼 이름만 다른 같은 지표 세 개를 제시하면 시장을 구조화한 것이 아니다. 좋은 기준은 고객이 실패하는 서로 다른 방식을 구분해야 한다.

| 수준 | 판정 |
|---:|---|
| 0 | 세 기준이 같은 의미이거나 모두 구현 수단 |
| 1 | 이름만 다르고 경계·중요성이 없음 |
| 2 | 의미 있는 축이지만 중복 또는 중요한 공백이 있음 |
| 3 | 다른 결과와 실패를 다루며 함께 볼 이유가 명확함 |
| 4 | 수준 3 + 비적용 사례 또는 기준 간 상충을 통제함 |

특정 조합을 정답으로 요구하지 않는다. 발견·추천·정확성 외 다른 조합도 경계와 고객 결과가 강하면 같은 점수를 받는다.

### A3. 조작적 정의와 GEO 측정 현실성: 8점

#### 무엇을 보는가

각 기준을 실제로 판정할 수 있고 LLM 답변의 변동성을 측정 조건에 반영했는가.

#### 왜 보는가

GEO는 단일 답변이 매번 같지 않다. 측정 단위·분모·질문 의도·모델·채널·시점을 통제하지 않으면 변화인지 우연인지 구별할 수 없다.

| 수준 | 판정 |
|---:|---|
| 0 | 많이 노출, 긍정 추천처럼 관찰 방법이 없음 |
| 1 | 지표명만 있고 분모·판정·조건이 없음 |
| 2 | 일부 지표와 반복은 있으나 핵심 비교 조건이 빠짐 |
| 3 | 각 기준의 관찰 단위·판정·분모·반복·비교 조건이 있음 |
| 4 | 수준 3 + 결측·판정 보류·불확실성·지표 비적용 조건을 통제함 |

최소 측정 계약을 평가한다. API 전체 명세나 통계 검정력 계산을 요구하지 않는다.

### A4. 근거의 적합성과 한계: 4점

#### 무엇을 보는가

왜 그 기준이 필요한지 근거로 설명하고 근거 범위를 넘지 않는가.

#### 왜 보는가

경쟁사가 제공한다는 사실은 기능 존재를 보여줄 뿐 사용자 수요나 인과 효과를 증명하지 않는다. 신생 시장일수록 근거 종류와 주장 강도를 구분해야 한다.

| 수준 | 판정 |
|---:|---|
| 0 | 근거가 없거나 출처가 주장을 반대로 말함 |
| 1 | 회사명·통계를 장식처럼 사용함 |
| 2 | 관련 근거는 있으나 관찰·인과 또는 시장·사용자 맥락을 혼동함 |
| 3 | 근거가 기준 필요성을 지지하고 조건·한계를 밝힘 |
| 4 | 수준 3 + 반대 근거나 대체 해석을 검토하고도 선택 이유가 분명함 |

## 10. B. PRD: 48점

### B1. 문제 정의와 핵심 사용자·시나리오: 8점

#### 무엇을 보는가

기능 부재가 아니라 사용자의 현재 실패, 비용, 필요한 결정을 정의했는가.

#### 왜 보는가

`대시보드가 필요하다`는 문제 정의가 아니다. 사용자가 언제 무엇을 하다가 왜 실패하고 어떤 결정을 못 내리는지가 있어야 기능 우선순위를 판단할 수 있다.

| 수준 | 판정 |
|---:|---|
| 0 | 사용자·문제가 없거나 기능을 문제로 표현 |
| 1 | B2B 담당자라는 반복 외에 업무 상황과 결정이 없음 |
| 2 | 사용자·불편은 있으나 현재 대안·비용·다음 결정이 불완전 |

### B2. 두 기능의 가치와 경계: 8점

### B4. 주요 기능 요구사항과 정책: 8점

#### 무엇을 보는가

개발자와 디자이너가 핵심 동작을 같은 의미로 이해하고 논의를 시작할 수 있는가.

#### 왜 보는가

PRD는 아이디어 소개문이 아니다. 입력·처리·출력·사용자 제어·예외가 연결돼야 구현 중 핵심 의미가 달라지지 않는다.

| 수준 | 판정 |
|---:|---|
| 0 | 슬로건이나 화면 이름뿐 |
| 1 | 입력 또는 출력만 있고 처리와 제어가 없음 |

모든 화면과 API를 요구하지 않는다. 기능 가치와 품질을 좌우하는 정책을 본다.

#### 왜 보는가

기능 출시나 리포트 조회 자체는 고객 가치가 아니다. 첫 가치, 반복 가치, 품질 가드레일과 진행·수정·중단 조건이 필요하다.

| 수준 | 판정 |

근거 없는 80%는 시장 기준이 아니다. 내부 파일럿 판단선이라고 밝히고 결과에 따라 다시 정하면 허용한다. 숫자의 개수는 가점 요인이 아니다.

### B6. MVP 범위와 실행 가능성: 4점

## 11. C. 문항 간 연결과 0→1 판단: 16점

### C1. 기준→문제→기능→지표 추적성: 8점

#### 무엇을 보는가

문항 1과 PRD가 같은 제품 논리로 이어지는가.

#### 왜 보는가

GEO 기준은 훌륭하지만 PRD가 다른 지표를 측정하면 두 개의 독립된 모범답안일 뿐이다. 정의한 기준이 기능과 성공 측정까지 살아 있어야 한다.

| 수준 | 판정 |
|---:|---|
| 0 | 문항 1과 PRD가 무관 |
| 1 | 같은 용어만 반복하고 연결 불명 |

개별 항목의 동일 누락을 C1에서 다시 감점하지 않는다. 구성요소는 있는데 서로 연결되지 않을 때만 감점한다.

생성형 AI를 결정론적 검색엔진처럼 다루지 않고 핵심 위험을 제품에 반영했는가.

| 1 | 변동성을 언급하지만 제품 정책에 영향 없음 |
| 2 | 일부 위험만 반영하고 중요한 채널·출처·분류 위험이 비어 있음 |
| 3 | 주요 위험을 요구사항과 해석 정책에 반영함 |
| 4 | 수준 3 + API·UI 차이, 관찰·인과 경계, 검수 비용까지 우선순위에 반영함 |

## 12. D. 커뮤니케이션·신뢰성·과제 특화성: 12점

### D1. 가독성과 의사결정 전달: 4점

#### 무엇을 보는가

CEO·PM·개발자·디자이너가 결론과 근거를 빠르게 이해할 수 있는가.

#### 왜 보는가

기획 문서는 정보를 많이 담는 것이 아니라 다른 사람이 같은 결정을 이해하게 만드는 도구다.

| 수준 | 판정 |
|---:|---|
| 0 | 핵심 답을 찾기 어렵고 문장·표가 의미를 훼손 |
| 1 | 정보는 많지만 배경·반론·반복에 결론이 묻힘 |
| 2 | 흐름은 이해되지만 중복·긴 문장·표 때문에 재독 필요 |

특정 대시·가운데점·굵은 글씨·영어 한 번으로 감점하지 않는다. 누적 사용이 실제 독해를 방해할 때만 본다.

### D2. 주장 상태와 근거 신뢰성: 4점

#### 무엇을 보는가

사실·해석·가설·계획·미확인을 구분하고 출처 범위 안에서 주장하는가.

#### 왜 보는가

정확하지 않은 확신은 AI 제품과 신생 시장에서 큰 위험이다. 지원자가 모르는 것과 확인한 것을 분리해야 문서를 신뢰할 수 있다.

| 수준 | 판정 |
|---:|---|
| 0 | 중대한 허위·조작 또는 문서 전체 신뢰 불가 |
| 1 | 근거 없는 수치·권위 인용과 사실·계획 충돌 반복 |
| 2 | 대부분 구분하지만 중요한 사용자 주장·성과 상태가 모호 |
| 3 | 핵심 주장 상태가 명확하고 출처가 범위를 지지함 |
| 4 | 수준 3 + 미확인·반증 가능성을 표시하고 근거에 맞춰 주장 강도를 조절함 |

### D3. 판단 소유권·과제 특화성·대체 불가능성: 4점

#### 무엇을 보는가

일반적인 PM·GEO 모범 구조를 조립한 수준을 넘어 해당 사용자와 문제에 대한 지원자의 근거·선택·조건부 판단이 있는가.

#### 왜 보는가

문체는 자연스럽지만 같은 과제와 프롬프트를 주면 누구나 만들 수 있는 답안일 수 있다. 채용 과제는 정답의 정확성뿐 아니라 후보자를 구별할 판단 흔적이 필요하다.

| 수준 | 판정 |
|---:|---|
| 0 | 선택 이유가 없고 지원자가 설명할 수 있을지 신뢰 불가 |
| 1 | 과제 문구를 제목으로 재배열했거나 명사를 바꿔 그대로 쓸 일반론 |
| 2 | 구체 정책은 있으나 핵심 구조가 전형적이고 사용자 근거·반증·비전형적 통찰이 부족 |
| 3 | 해당 상황의 제약·선택·제외·실패 조건이 있고 왜 이렇게 잘랐는지 추적 가능 |
| 4 | 수준 3 + 직접 관찰·독자적 근거 해석·약한 가정·반증 시 변경 조건이 있어 일반 프롬프트만으로 재현하기 어려움 |

#### 가점하는 것

- 실제 사용자 행동 또는 구체적인 1차 관찰
- 공개 자료 사이의 빈틈을 사용자 문제와 연결한 해석
- 명시적으로 버린 대안과 감수한 비용
- 가장 약한 가정과 반증 시 바꿀 결정
- 해당 산업·사용자·회사 단계 때문에 달라진 정책

#### 가점하지 않는 것

- 새로운 기능명과 신조어
- 근거 없는 독창성
- 출처 개수와 유명 회사명
- 필요 이상의 기술 복잡성
- 개인 경험담 자체
- 사람처럼 보이는 특이한 문체

정석 기능을 선택해도 사용자 근거와 조건부 판단이 강하면 높은 점수를 받는다. 독특해도 고객 문제와 연결되지 않으면 가점하지 않는다.

## 13. 출처와 수치의 평가 기준

### 근거 우선순위

1. 과제 원문과 공고
2. 실제 사용자 행동·인터뷰·업무 자료
3. 원 연구·공식 기술 문서
4. 공식 제품 문서
5. 시장 보고서·2차 자료
6. 외부 피드백
7. 개인적 문체 취향

### 출처별 허용 범위

| 출처 | 뒷받침할 수 있는 것 | 뒷받침하지 못하는 것 |
|---|---|---|
| 경쟁 제품 공식 문서 | 해당 기능·지표의 공개 존재, 시장 구현 패턴 | 우리 사용자의 우선순위, 인과 효과, 실제 사용 만족 |
| 원 연구 | 해당 연구의 표본·방법·결과 범위 | 다른 제품 맥락의 구체적 목표값 자동 정당화 |
| 사용자 인터뷰 | 해당 참여자의 행동·문제·언어 | 시장 전체 비율과 인과 효과 |
| 파일럿 | 정해진 조건에서의 초기 사용 행동 | 장기 유지율, 시장 성과, 일반화된 수요 |
| 내부 판단선 | 다음 개발 결정 기준 | 업계 평균, 통계적으로 검증된 성공선 |

### 정밀 수치 판정

- 숫자가 있다는 이유로 가점하지 않는다.
- 이벤트·대상·분모·기간·다음 결정이 있을 때 의미가 있다.
- 근거 없는 80%도 내부 판단선으로 명시하면 허용한다.
- 설명할 수 없는 소수점과 정밀 목표는 AI 생성 인상과 면접 위험을 높인다.
- 파일럿 후 목표를 어떻게 교정할지 없으면 수준 4를 주기 어렵다.
- 성공 수와 전체 수를 함께 표시하는 것을 권장한다.

## 14. AI 및 답안 구별력 진단

AI 사용 여부를 탐지하지 않는다. 다음 세 개를 분리한다.

| 진단 | 질문 | 점수 반영 |
|---|---|---|
| AI 문체 위험 | 문장이 생성형 AI 초안처럼 읽혀 독해·신뢰를 방해하는가 | 실제 영향이 있으면 D1·D2 |
| AI 생성 용이성 | 일반 프롬프트로 비슷한 구조를 쉽게 만들 수 있는가 | 등급 자체는 감점하지 않음 |
| 판단 소유권·과제 특화성 | 전형적 구조를 자신의 근거와 판단으로 바꿨는가 | D3 4점 |

### AI 문체 위험

#### 낮음

- 문장 구조가 내용에 따라 달라짐
- 구체 행동·선택·제외가 추상 표현보다 많음
- 표와 기호가 탐색에 도움을 줌

#### 중간

- 대칭적인 삼단 구조와 비슷한 문장 길이 반복
- 정밀 수치와 체크리스트가 지나치게 빈틈없이 배치
- 지원자 판단보다 평가 기준 충족 인상이 앞섬

#### 높음

- 일반론·권위 인용·시장 통계가 구체 판단을 대체
- 모든 반론을 방어하지만 실제 선택이 없음
- 용어·문체·개념 수준이 문서 안에서 불일치
- 면접에서 그대로 설명하기 어려운 과도한 전문성·정밀함

### AI 생성 용이성 다섯 검사

#### 1. 명사 치환

산업·브랜드·사용자 이름만 바꿔도 그대로 쓸 수 있는가.

#### 2. 과제 문구 재배열

`얼마나·어떻게`를 `노출 대시보드·출처 분석`으로 옮긴 것 이상의 판단이 있는가.

#### 3. 표준 PM 템플릿

문제→페르소나→기능→KPI→5명 테스트 목차를 제거해도 고유 판단이 남는가.

#### 4. 근거-결정 고유성

특정 자료가 실제 기능·정책·우선순위를 바꿨는가. 그 자료가 빠지면 결정이 달라지는가.

#### 5. 반증·역전

어떤 사용자 증거가 나오면 문제·기능·사업 형태를 바꿀지 명시했는가.

### 생성 용이성 등급

| 등급 | 판정 |
|---|---|
| 낮음 | 네 검사 이상에서 과제 특화 판단이 확인되고 같은 결론에 지원자의 근거가 필요함 |
| 중간 | 기능은 전형적이나 범위·정책·트레이드오프 일부가 상황에 특화됨 |
| 높음 | 과제 문구가 전형적인 문제·기능·KPI로 변환되고 일반 프롬프트로 유사 답안을 만들기 쉬움 |

생성 용이성 높음은 자동 탈락이 아니다. 구조화 면접에서 문서 소유권을 반드시 확인한다.

## 15. 중복 감점 방지 규칙

한 결함은 가장 직접적인 한 항목에서만 전부 감점한다. 다른 항목에서는 별도의 결과 결함이 생겼을 때만 추가 감점한다.

| 문제 | 주 항목 | 추가 반영 조건 |
|---|---|---|
| GEO 정의가 없음 | A1 | D1에 같은 이유로 재감점 금지 |
| 세 기준이 중복 | A2 | PRD와 연결이 실제로 끊기면 C1 가능 |
| 기준 지표·분모·조건 없음 | A3 | PRD 정책에도 별도로 없으면 B4 가능 |
| 문항 1 근거 범위 과장 | A4 | 문서 전체의 사실 상태 왜곡이면 D2 가능 |
| 사용자 문제 모호 | B1 | 기능이 다른 문제를 풀면 C1 가능 |
| 두 기능 역할 중복 | B2 | 범위 무제한이면 B6 가능 |
| 우선순위 대안 없음 | B3 | D3에 같은 이유로 재감점 금지 |
| 요구사항 정책 없음 | B4 | 누락 때문에 성공 측정 불가능하면 B5 가능 |
| 성공 지표 불완전 | B5 | 같은 누락을 A3에서 재감점 금지 |
| MVP·비목표 없음 | B6 | 우선순위 범위 결정도 없으면 B3 가능 |
| 구성요소는 있으나 연결 안 됨 | C1 | 개별 누락을 반복 감점하지 않음 |
| 테스트는 있으나 다음 결정 없음 | C2 | 성공 지표 자체도 없으면 B5 가능 |
| 변동성·채널·분류 위험 무시 | C3 | 그 결과 요구사항도 틀리면 B4 가능 |
| 길고 반복되어 결론이 묻힘 | D1 | AI 진단에 표시하되 추가 점수 감점 없음 |
| 사실·가정·계획 충돌 | D2 | 중대한 허위면 관문 1 |
| 문체는 전형적이나 판단 명확 | 점수 감점 없음 | AI 문체·생성 용이성만 기록 |
| 전체 답안이 대체 가능 | D3 | B3에서 같은 대안 부족을 다시 감점하지 않음 |

## 16. 관문 3: 핵심 역량 최저선

총점이 높아도 다음을 모두 충족해야 진행 권고가 가능하다.

## 17. 점수 해석

| 총점 | 수행 의미 | 진행 권고 |
|---:|---|---|
| 85~100 | 다수 항목이 실무 충족을 넘어 우수 | 강한 면접 진행 |
| 75~84 | 핵심 역량이 실무 충족, 일부 검증 필요 | 면접 진행 |

관문 0·1 또는 핵심 최저선을 통과하지 못하면 총점과 관계없이 진행 비권고다. 점수 구간은 실제 합격 확률이 아니다.

## 18. 이해관계자별 해석

이 관점들은 별도 가산점이 아니라 같은 문서를 다른 업무 위험에서 해석하기 위한 보조 프레임이다.

| 관점 | 주로 보는 것 | 대표 질문 |
|---|---|---|
| 채용 담당자 | 과제 준수, 완결성, 신뢰성, AI 위험 | 요구를 지켰고 면접에서 검증할 가치가 있는가 |
| CEO·대표 | 문제 빈도, 지불 가치, 범위, 사업 가설 | 이 문제가 반복 제품이 될 만큼 중요한가 |
| 시니어 PM | 문제·우선순위·트레이드오프·학습 | 왜 이 두 기능이고 어떤 증거에서 바꾸는가 |
| 개발자 | 상태·분모·예외·수집·운영 가능성 | 같은 의미로 구현을 시작할 수 있는가 |
| 디자이너 | 핵심 과업, 정보 우선순위, 상태 전이 | 사용자가 무엇을 보고 어떤 결정을 내리는가 |
| 데이터·AI | 표본, 분류, 결측, 불확실성, 품질 지표 | 이 수치를 신뢰할 수 있고 오류를 발견할 수 있는가 |

같은 결함을 관점별로 반복 감점하지 않는다. 최종 평가에서 위험과 면접 질문을 구체화하는 용도다.

## 19. 관문 4: 구조화 면접

과제 통과자에게 같은 핵심 질문과 행동 척도를 사용한다. 과제 점수와 합산하지 않는다.

### 공통 질문

1. GEO 기준 하나를 빼야 한다면 무엇을 빼고 어떤 위험을 감수할 것인가
2. 제외한 기능 두 개와 현재 기능보다 뒤로 둔 이유는 무엇인가
3. 가상 데이터로 핵심 지표의 분자·분모와 한계를 설명할 수 있는가
4. API와 실제 소비자 UI 결과가 다르면 PRD를 어떻게 바꾸는가
5. 가장 약한 근거와 그 근거가 빠지면 약해지는 주장은 무엇인가
6. 개발 일정상 기능 하나만 가능하면 어떤 정보를 확인하고 결정하는가
7. 디자이너가 자동 판정 신뢰도를 문제 삼으면 어떻게 합의하는가
8. 다른 B2B SaaS로 바꾸면 현재 PRD에서 반드시 달라질 세 가지는 무엇인가
9. AI가 가장 쉽게 만들 수 있는 부분과 지원자의 판단이 가장 많이 들어간 부분은 무엇인가
10. 어떤 결과가 나오면 핵심 기능 두 개를 모두 버릴 것인가

### 면접 행동수준

| 수준 | 판정 |
|---:|---|
| 1 | 문서 내용을 설명하지 못하거나 핵심 정의·선택이 충돌 |
| 2 | 요약은 가능하지만 새로운 제약에 판단을 수정하지 못함 |
| 3 | 선택과 근거를 일관되게 설명하고 새 조건에 대응 |
| 4 | 대안·트레이드오프를 비교하고 필요한 정보를 요청해 판단 갱신 |
| 5 | 약한 가정을 먼저 드러내고 이해관계자 우려를 실험·제품 결정으로 통합 |

AI 생성 용이성이 높고 면접 소유권 수준이 2 이하이면 `소유권 미검증`으로 진행 비권고할 수 있다.

## 20. 평가 운영 절차

1. 파일명·수정 시각·해시를 기록한다.
2. 이전 버전과 자체평가를 보지 않고 제출본만 먼저 읽는다.
3. 관문 0과 1을 판단한다.
4. A~D 각 항목의 행동수준과 직접 근거를 기록한다.
5. 중복 감점 귀속표를 확인한다.
6. 핵심 역량 최저선을 적용한다.
7. AI 문체 위험과 생성 용이성을 별도 진단한다.
8. 이해관계자별 위험과 면접 질문을 작성한다.
9. P0 수정은 최대 세 개만 선정한다.
10. 이전 버전과 같은 항목끼리만 비교한다.

가능하면 평가자 두 명이 독립 채점한다.

- 총점 차이 5점 초과
- 동일 항목 행동수준 차이 1단계 초과
- 관문 판정 불일치
- AI 위험 등급 두 단계 차이

위 조건이면 근거를 대조해 재평가한다. 단순 평균으로 끝내지 않고 행동 앵커와 제출본 문장을 기준으로 합의한다.

## 22. 공정성 통제

- 출신 회사·학교·연차를 과제 점수에 섞지 않는다.
- 특정 PRD 템플릿과 특정 GEO 기준 조합을 강제하지 않는다.
- 문서 디자인과 영어는 판단 전달에 실제로 기여할 때만 본다.
- 출처 개수와 어려운 기술 용어는 가점하지 않는다.
- AI 탐지기 점수와 문체 추측을 선발 근거로 사용하지 않는다.
- 전형적인 해결책이라는 이유만으로 감점하지 않는다.
- 독특하다는 이유만으로 가점하지 않는다.
- 제출본 밖의 좋은 리서치로 원고의 누락을 보충하지 않는다.
- 평가 중 새 문제를 발견해도 배점과 기준을 바꾸지 않는다.

## 23. 루브릭 자체 검증

이 기준이 특정 V5·V6 구조에 과적합되지 않았는지 다음 답안으로 역검증한다.

1. SEO 수단 나열형
2. 노출 지표만 있는 대시보드형
3. 고객 행동·사업 결정 중심형
4. 측정 과학은 강하지만 사용자 가치가 약한 형
5. 간결하고 실행 가능하지만 기술 상세가 적은 주니어형
6. 문체는 자연스럽지만 AI로 쉽게 생성 가능한 전형형
7. 독특하지만 근거와 실행성이 약한 아이디어형

좋은 기준이라면 3번과 5번을 높게 평가하고, 6번은 직무 점수와 생성 용이성 위험을 분리하며, 7번은 독창성만으로 가점하지 않아야 한다.

실제 채용에 사용한다면 과제 점수와 면접·입사 후 성과의 관계, 평가자 일치도, 집단별 불리한 영향을 계속 확인해야 한다.
