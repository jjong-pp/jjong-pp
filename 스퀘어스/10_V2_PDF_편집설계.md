# V2 Word·PDF 편집 설계

대상 원고: `09_최종제출본_V2.md`  
목표 결과: 별도 장식 표지 없이 A4 약 7~8쪽의 읽기 쉬운 제출 문서  
적용 시점: V2 Word 생성과 이후 PDF 변환 단계에서 동일하게 적용

## 1. 편집 원칙

1. 장식보다 **정보 계층**을 먼저 보이게 한다.
2. 첫 페이지에서 지원자의 관점과 좋은 GEO 기준 3개를 모두 확인할 수 있게 한다.
3. 기능 2개는 같은 형식으로 보여주되 카드형 도형이나 표를 남용하지 않는다.
4. 제목은 모두 검정으로 두고, 크기·굵기·간격만으로 위계를 만든다.
5. 페이지 수를 맞추려고 본문 글자나 행간을 줄이지 않는다.
6. Word 생성 뒤 전 페이지를 이미지로 렌더링해 표·줄바꿈·고아 문단을 확인한다.

## 2. 페이지와 기본 글꼴

| 항목 | 적용값 |
|---|---|
| 용지 | A4 세로, 210×297mm |
| 여백 | 위 18mm, 아래 18mm, 왼쪽 19mm, 오른쪽 19mm |
| 머리말·꼬리말 | 머리말 8mm, 꼬리말 9mm |
| 본문 폭 | 약 172mm |
| 기본 글꼴 | **맑은 고딕** — Word와 LibreOffice 렌더링에서 동일하게 적용 |
| 안전 대체 글꼴 | Noto Sans KR |
| 영문·숫자 | 한글과 같은 글꼴 사용 |
| 기본 글자색 | `#222222` |
| 배경 | 흰색 |
| 정렬 | 왼쪽 정렬 |
| 첫 줄 들여쓰기 | 사용하지 않음 |

PDF 저장 시 사용한 글꼴을 포함한다. 맑은 고딕 포함에 문제가 생기면 문서 전체를 Noto Sans KR로 바꾸며, 두 글꼴을 섞어 페이지 수를 조정하지 않는다.

## 3. 글자 크기와 제목 계층

| 스타일 | 크기·굵기 | 색상 | 문단 간격 |
|---|---|---|---|
| 문서 제목 | 21.5pt Bold | `#000000` | 뒤 12pt |
| 대제목 H2 | 16pt Bold | `#000000` | 앞 22pt, 뒤 9pt |
| 소제목 H3 | 12.5pt Bold | `#000000` | 앞 17pt, 뒤 6pt |
| 본문 | 10.2pt Regular | `#222222` | 고정 15.8pt 행간, 뒤 5pt |
| 목록 | 10.2pt Regular | 본문색 | 항목 뒤 3pt, 목록 뒤 6pt |
| 표 본문 | 9pt Regular, 행 라벨만 Bold | 본문색 | 고정 13pt 행간 |
| 본문 출처 태그 | 8.5pt Regular | `#595959` | 앞 0pt, 뒤 7pt |
| 출처 설명 | 8.8pt Regular | `#333333` | 고정 12.5pt 행간, 항목 뒤 6pt |
| 머리말·꼬리말 | 8pt Regular | `#6B7280` | 단일 행간 |

H4 이하는 사용하지 않는다. 제목 뒤에는 최소 본문 3줄이 같은 페이지에 남도록 `다음 문단과 함께`를 적용한다.

## 4. Bold·기울임·밑줄·색상

### Bold

다음에만 사용한다.

- 제목 H1~H3
- 기능명과 표 머리글
- 위험 목록의 짧은 항목명
- 문단에서 판단을 대표하는 짧은 구절

한 문단 안의 굵은 글씨는 최대 두 구절로 제한하고, 본문 전체의 약 10%를 넘지 않게 한다.

### 기울임

- 영어 논문·기사·제품 문서 제목에만 사용한다.
- 한국어 문장을 강조하는 용도로 사용하지 않는다.
- 영어 제목이 긴 경우 참고문헌에서만 기울임을 적용한다.

### 밑줄

- 일반적인 강조에는 사용하지 않는다.
- 클릭 가능한 링크에만 파란색과 밑줄을 적용한다.
- 출력본에서도 링크라는 사실을 알 수 있게 링크 스타일을 유지한다.

### 강조 색상

- 제목: `#000000`
- 인용문 배경: `#F3F3F3`
- 인용문 왼쪽 선: `#7F7F7F`
- 표 머리글 배경: `#EFEFEF`
- 표 테두리: `#C8C8C8`
- 보조 회색: `#6B7280`
- 링크: `#0563C1`

본문의 핵심 단어를 색으로 칠하지 않는다. 빨간색·형광색·그라데이션·컬러 배지는 사용하지 않는다. 흑백 인쇄에서도 제목 굵기와 음영 차이로 구조가 남아야 한다.

## 5. 문단과 줄바꿈

- 문단은 2~4문장, Word 기준 3~6줄로 유지한다.
- 한 문단은 한 가지 주장만 담당한다.
- 250자를 넘는 문단은 둘로 나눈다.
- 양쪽 맞춤은 한글 자간을 불균일하게 만들 수 있으므로 사용하지 않는다.
- 문장 중간에 임의 줄바꿈을 넣지 않고 문단 단위로만 나눈다.
- 목록은 최대 5개, 각 항목은 가능하면 1~2줄로 제한한다.
- 번호 목록은 실제 순서가 있는 경우에만 사용한다.
- 목록 도입문은 첫 항목과 같은 페이지에 둔다.

## 6. 문제 정의 인용문

문서 전체에서 문제 정의 한 문장에만 인용문 스타일을 사용한다.

- 글자: 10pt, 고정 15pt 행간
- 왼쪽 들여쓰기: 5mm
- 왼쪽 테두리: 1.5pt, `#7F7F7F`
- 배경: `#F3F3F3`
- 위·아래 내부 여백: 4pt
- 문단 전체를 한 페이지에 유지
- 별도 텍스트 상자나 떠 있는 도형은 사용하지 않음

## 7. 표 디자인

V2의 표는 정확히 세 개만 사용한다.

1. 좋은 GEO 기준 3개
2. 기능 1·2 비교
3. 성공 측정 기준

### 공통 설정

| 항목 | 설정 |
|---|---|
| 표 너비 | 본문 폭 100%, 고정 열 너비 |
| 표 글꼴 | 9pt |
| 표 행간 | 고정 13pt |
| 셀 여백 | 위·아래 1.5mm, 좌·우 2mm |
| 머리글 음영 | `#EFEFEF` |
| 머리글 글자 | Bold, `#222222` |
| 행 라벨 | 첫 열이 행 이름인 경우만 9pt Bold |
| 바깥 위·아래 선 | 0.75pt, `#A8B3C0` |
| 내부 가로선 | 0.25pt, `#C8C8C8` |
| 세로선 | 사용하지 않음. 필요한 경우만 0.25pt |
| 셀 정렬 | 글자는 왼쪽·위, 수치는 오른쪽 |
| 행 분할 | 페이지 사이 행 나누기 금지 |
| 교차 음영 | 사용하지 않음 |

권장 열 너비:

- GEO 기준 표: `30% / 35% / 35%`
- 기능 비교표: `20% / 40% / 40%`
- 성공 지표 표: `15% / 47% / 38%`

표 전체가 남은 공간에 들어가지 않으면 표 앞에서 페이지를 넘긴다. 머리글만 페이지 아래에 남거나 마지막 행 하나만 다음 페이지에 떨어지지 않게 한다.

표 첫 열 외의 본문은 Regular를 유지한다. 표를 소개하는 문단에는 `다음 문단과 함께`를 적용해 설명문과 표가 서로 다른 페이지에 놓이지 않게 한다.

## 8. 링크와 출처

- 본문 출처는 외부 사실을 사용한 여섯 위치에만 `[출처 번호 | 확인한 내용]`으로 표시하고, 해당 주장 문장 끝에 작은 회색 글자로 붙인다.
- Bain 자료는 서로 다른 주장에 사용했으므로 `출처 2-A`, `출처 2-B`로 구분한다.
- 출처 태그는 진회색 일반 글자로 두고 배경·테두리·배지·굵은 글씨를 사용하지 않는다.
- 참고문헌 제목에 링크를 삽입하고 원시 URL은 노출하지 않는다.
- 링크 색상은 `#0563C1`, 밑줄을 사용한다.
- 방문한 링크도 보라색으로 바뀌지 않도록 스타일을 고정한다.
- 출처 항목마다 `본문 사용`과 `자료의 한계`를 적어 자료의 쓰임과 해석 범위를 구분한다.
- 각 출처는 서지정보, `본문 사용`, `자료의 한계`를 줄 단위로 분리해 훑어보기 쉽게 만든다.
- 출처 설명은 항목 단위로 페이지 중간에서 나누지 않는다.
- PDF 생성 뒤 모든 링크를 클릭해 확인한다.

## 9. 머리말·꼬리말·페이지 번호

첫 페이지:

- 머리말 없음
- 꼬리말 오른쪽에 페이지 번호만 표시

2페이지 이후:

- 머리말 왼쪽: `스퀘어스 서비스기획 PM 과제 · 박종혁`
- 꼬리말 오른쪽: 현재 페이지 번호

머리말과 꼬리말은 8pt `#6B7280`을 사용하고 구분선은 넣지 않는다. 첫 페이지부터 1로 계산한다.

## 10. 페이지 나눔과 7~8쪽 배치

수동 페이지 나눔은 `기준 1`, `2. PRD`, `2-3`, `2-5`, `2-8` 앞에 적용해 각 논리 묶음을 페이지 상단에서 시작한다. `2-10`은 앞 절의 남는 공간에 자연스럽게 이어지게 한다.

`출처와 해석 범위` 앞은 최초 Word 생성에서는 나누지 않는다. 제목이 페이지 하단에 고립되거나 앞 본문과 섞여 읽기 어려울 때만 조건부로 페이지를 넘긴다.

권장 배치:

| 페이지 | 주요 내용 |
|---:|---|
| 1 | 제목·지원자 정보, 실무 경험, 좋은 GEO 정의, 세 기준 표 |
| 2 | 기준 1·2·3의 근거와 관계 |
| 3 | PRD 문제 정의, 사용자·시나리오, 제품 범위 도입부 |
| 4 | 기능 비교표, 기능 1 |
| 5 | 기능 2, 두 기능의 우선순위, 큐샵 연결 |
| 6 | 성공 지표표, 파일럿 이후 결정, 위험과 대응 |
| 7 | 위험과 대응, 출처와 해석 범위 도입부 |
| 8 | 상세 출처, 생성형 AI 활용 범위 — 7쪽에 무리 없이 들어가지 않을 때만 사용 |

7쪽으로 자연스럽게 들어가면 그대로 사용한다. 상세 출처 때문에 8쪽이 더 자연스러우면 글자나 행간을 줄여 억지로 7쪽에 맞추지 않는다. Concierge MVP와 진행·중단 조건은 채용자가 실행 판단을 확인하는 내용이므로 페이지 수를 줄이기 위해 삭제하지 않는다.

## 11. 고아·과부와 페이지 안정성

- 문단이 페이지를 넘길 때 앞·뒤 페이지에 최소 두 줄씩 남긴다.
- 제목 아래에는 최소 본문 세 줄을 둔다.
- 표 행은 페이지 사이에서 나뉘지 않게 한다.
- 목록의 마지막 항목 하나만 다음 페이지에 떨어지지 않게 한다.
- 페이지 하단에 제목만 남으면 제목부터 다음 페이지로 넘긴다.
- 페이지 하단 빈 공간이 본문 네 줄 이하라면 다음 논리 단위를 새 페이지에서 시작한다.
- 빈 공간을 줄이려고 글꼴 크기·행간·자간을 바꾸지 않는다.

## 12. Word·PDF 변환 후 검수

Word 생성 뒤 다음 순서로 확인한다.

1. 모든 페이지를 PNG로 렌더링한다.
2. 제목 고립, 문단 과밀, 표 잘림, 행 분할을 확인한다.
3. 긴 영어 참고문헌의 줄바꿈과 한글 글리프를 확인한다.
4. 페이지별 여백과 하단 빈 공간의 균형을 확인한다.
5. Word의 `다른 이름으로 저장 → PDF`를 사용해 구조 태그와 링크를 유지한다.
6. PDF를 다시 페이지 이미지로 렌더링해 Word 결과와 대조한다.
7. PDF의 페이지 크기가 A4 100%인지, 글꼴이 포함됐는지 확인한다.
8. 참고문헌과 본문의 모든 링크를 클릭해 확인한다.

Word와 PDF는 V2 Markdown에 대한 사용자 승인 뒤 생성한다.
