# 스퀘어스 서비스기획 PM 과제

## 문항 1. “GEO를 잘 하고 있다”는 것은 무엇을 의미하는가

제가 생각하는 좋은 GEO는 고객이 제품을 찾고 비교하는 질문에서 브랜드가 후보로 등장하고, 선택되는 이유가 실제 제품 정보와 맞는 상태입니다. 이를 다음 세 가지 기준으로 판단하겠습니다.

| 기준 | 좋은 상태 | 측정 방법 |
|---|---|---|
| 중요한 질문에서 발견되는가 | 문제 탐색과 도입 검토 질문에서 브랜드가 반복해서 등장한다 | 노출률 = 자사가 등장한 유효 답변 수 ÷ 해당 질문의 전체 유효 답변 수 |
| 선택이 필요한 질문에서 추천되는가 | 이름만 나열되지 않고 사용자 조건에 맞는 선택지로 제시된다 | 추천률 = 자사가 추천된 답변 수 ÷ 추천 및 비교 질문의 유효 답변 수 |
| 실제 제품과 맞게 설명되는가 | 적합한 고객과 강점이 올바르게 설명되고 구매 판단을 바꿀 오류가 없다 | 사실 일치율 = 공식 정보와 일치한 문장 수 ÷ 사람이 검수한 사실 문장 수, 중대 오류 건수 |

### 1. 중요한 질문에서 발견되는가

모든 질문의 가치는 같지 않습니다. “협업툴이란 무엇인가”보다 “50명 규모의 국내 스타트업이 쓸 협업툴을 추천해줘”가 실제 검토에 더 가깝습니다. 특히 협업툴은 일반적인 사용 편의 질문과 도입 승인에 영향을 주는 보안, 권한, SSO, 데이터 보관, 연동과 이관 질문을 구분해야 합니다. 사용자가 우선순위를 정하되 도입을 막을 수 있는 질문을 먼저 확인하겠습니다.

### 2. 선택이 필요한 질문에서 추천되는가

여러 제품을 나열한 답변에 이름만 포함된 경우는 추천으로 세지 않습니다. 사용자의 규모, 사용 목적이나 도입 조건과 브랜드를 연결해 선택지로 제시한 경우만 추천으로 분류합니다. 추천률도 정보 탐색 질문 전체가 아니라 추천이나 비교 의도가 있는 질문에서만 계산합니다.

### 3. 실제 제품과 맞게 설명되는가

노출이 늘어도 지원하지 않는 SSO나 연동 기능을 지원한다고 설명하거나 오래된 가격을 제시하면 좋은 GEO라고 보기 어렵습니다. 검증 가능한 문장은 공식 정보와 대조해 맞음, 다름, 판단 보류로 기록합니다. 보안, 권한, 데이터 보관, SSO, 연동과 이관처럼 도입 승인에 영향을 주는 오류는 중대 오류로 구분합니다. 답변에 표시된 출처는 사실을 확정하는 증거가 아니라 어떤 정보가 함께 제시됐는지 추적하는 단서로 사용합니다.

세 기준은 같은 AI 서비스, 언어, 검색 설정에서 반복해 확인합니다. 단일 답변이나 한 번의 상승만으로 추세를 단정하지 않으며 결과에는 백분율과 실제 답변 수를 함께 표시합니다.

## 문항 2. PRD

### 1. 문제 정의

구독형 협업툴은 요금제 변경, 기능 출시, 서비스 장애, 경쟁사 캠페인처럼 브랜드 인식이 달라질 만한 일이 반복해서 생깁니다. 담당자는 평소의 기준선과 사건 이후 결과를 비교해 AI 답변의 변화가 일시적인지, 도입 검토에 영향을 줄 문제인지 판단해야 합니다. 그러나 몇 개 질문을 직접 검색하는 방식으로는 과거 결과를 같은 조건에서 비교하기 어렵고, 어느 질문의 어떤 설명과 출처를 더 살펴봐야 하는지도 알기 어렵습니다.

### 2. 핵심 사용자와 시나리오

핵심 사용자는 AI 내 브랜드 노출 변화를 보고 대응 여부를 결정하는 담당자입니다. 브랜드 매니저가 판단하고 콘텐츠 마케터가 근거를 조사할 수 있지만 초기 스타트업에서는 한 사람이 두 업무를 함께 맡을 수도 있습니다. 따라서 직무를 두 명의 사용자로 고정하지 않고 다음 두 업무를 하나의 흐름으로 설계합니다.

1. 노출과 추천이 달라진 질문을 찾아 지금 확인할 문제인지 결정한다.
2. 해당 답변의 설명과 출처를 보고 추가로 조사할 정보가 무엇인지 기록한다.

평소에는 정기 결과로 기준선을 만들고, 가격 변경이나 장애 같은 사건이 생기면 같은 조건으로 다시 확인합니다. 담당자는 변화 후보를 고른 뒤 원문과 출처를 확인하고 제품 정보 확인, 외부 비교 자료 확인, 자사 페이지 확인, 이상 없음 중 하나로 판단을 남깁니다.

확인 주기와 구독형 제품의 적합성은 아직 가설입니다. 인터뷰에서는 최근 90일 동안 직접 AI 답변을 확인한 횟수, 계기가 된 사건, 소요 시간과 실제 결정을 묻겠습니다. 파일럿에서 절반이 넘는 계정이 사건이 있는 주에만 사용한다면 주간 대시보드보다 사건 리포트와 알림을 우선 검토하겠습니다.

### 3. 최우선 기능 2개와 선정 근거

기능 후보는 사용자 결정에 직접 기여하는지와 다른 기능보다 먼저 필요한 데이터인지에 가장 큰 비중을 두고, 사용 빈도와 오판 피해, 구현과 운영 부담을 함께 비교했습니다.

| 후보 기능 | 사용자 결정과 선행 관계 | 사용 빈도 | 오판 피해와 운영 부담 | 판단 |
|---|---|---|---|---|
| 노출 및 추천 흐름 진단 | 변화 여부를 판단하며 이후 기능의 기준선을 만든다 | 정기 확인과 사건 발생 시 | 수집 변동이 있으나 원문으로 확인 가능 | 최우선 1 |
| 브랜드 설명과 출처 진단 | 대응할 내용과 조사 대상을 정한다 | 변화 후보가 있을 때 | 사실 오판 위험이 있어 사람 검수가 필요 | 최우선 2 |
| 자동 질문 생성 | 초기 설정을 줄이지만 사용자가 직접 정할 수 있다 | 최초 설정과 질문 개편 시 | 부적절한 질문이 전체 결과를 왜곡할 수 있음 | 설정 실패가 확인되면 재검토 |
| 실시간 알림 | 대응 시점을 앞당기지만 기준선이 먼저 필요하다 | 사건 발생 시 | 잘못된 알림과 상시 수집 비용이 발생 | 긴급 수요가 확인되면 재검토 |
| 자동 사실 비교와 개선안 | 실행을 돕지만 공식 정보와 신뢰할 진단이 먼저 필요하다 | 문제 확인 후 | 잘못된 판정과 콘텐츠 실행의 피해가 큼 | 후순위 |

따라서 첫 버전에는 다음 두 기능만 포함합니다.

1. 핵심 질문별 노출 및 추천 흐름 진단
2. 브랜드 설명과 출처 진단

조사한 제품에서 반복 수집과 출처 분석은 공통적인 기반 기능으로 확인했습니다. 반면 종합 점수나 자동 콘텐츠 생성은 담당자가 어떤 결정을 내려야 하는지 연결이 약해 제외했습니다. 처음에는 운영자가 직접 수집하고 분류해도 됩니다. 사용자가 결과를 실제 판단에 쓰는지 확인한 뒤 반복 수집부터 자동화하겠습니다.

### 4. 주요 기능 요구사항

#### 기능 1. 핵심 질문별 노출 및 추천 흐름 진단

- 담당자가 고객의 문제 탐색, 제품 비교, 도입 승인 단계별 핵심 질문을 검토하고 확정한다. 보안, 권한, SSO, 데이터 보관, 연동과 이관처럼 도입을 막을 수 있는 질문은 별도로 표시한다.
- MVP는 담당자가 실제로 확인하는 AI 채널 한 곳에서 시작한다. 같은 질문을 같은 언어와 검색 설정에서 우선 3회 실행한다. 이 횟수는 추세를 확정하기 위한 표본이 아니라 결과가 흔들리는지 확인하기 위한 초기값이며, 필요한 반복 수는 파일럿의 변동성과 수집 비용을 보고 조정한다.
- 요청이 정상 완료되고 분석 가능한 본문이 있는 경우만 유효 답변으로 계산한다. 계획한 답변이 모두 수집되지 않으면 미노출로 세지 않고 데이터 부족으로 표시한다.
- 노출률과 추천률은 문항 1의 계산식을 사용한다. 질문별 결과에는 비율과 실제 답변 수를 함께 표시하고, 한 주기의 차이는 추세가 아니라 변화 후보로 제시한다.
- 질문이나 수집 채널이 바뀌면 새 버전으로 기록한다. API와 소비자 화면처럼 채널이 다르면 같은 시계열로 합치지 않는다.

#### 기능 2. 브랜드 설명과 출처 진단

- 담당자가 핵심 고객, 대표 강점, 공식 가격과 기능, 보안과 연동 범위 등 비교 기준이 될 정보를 등록한다.
- 답변에서 자사의 역할을 추천, 비교 후보, 단순 언급, 주의 또는 비추천으로 나누고 판정 근거 문장을 함께 보여준다. 자동 분류는 사용자가 수정할 수 있다.
- 검증 가능한 문장을 맞음, 다름, 판단 보류로 기록하고, 답변에 표시된 URL을 자사, 경쟁사, 제3자 자료로 나눈다. 공식 정보가 없으면 오류를 자동으로 확정하지 않는다.
- 도입 승인에 영향을 주는 보안, 권한, 데이터 보관, SSO, 연동과 이관 오류는 일반적인 표현 차이보다 먼저 보여준다.
- 사용자는 근거를 확인한 뒤 제품 정보 확인, 외부 비교 자료 확인, 자사 페이지 확인, 이상 없음 중 하나를 저장한다. 첫 버전에서는 개선안이나 콘텐츠를 자동으로 제안하지 않는다.

### 5. 성공 측정 기준

핵심 지표는 유효한 리포트를 받은 계정 중 근거 문장과 출처를 확인하고 판단을 저장한 계정의 비율입니다. 리포트를 열어본 계정만 분모로 삼지 않아 설정과 전달 단계의 실패를 숨기지 않겠습니다.

| 확인할 것 | 측정 방법 | 다음 결정 |
|---|---|---|
| 처음 써도 판단할 수 있는가 | 도움 없이 변화 후보를 찾고 판단을 저장한 사용자 수 ÷ 테스트 사용자 수, 완료 시간 중앙값 | 5명 중 4명 이상이 완료하면 다음 단계로 진행하고, 미달하면 화면과 질문 설정부터 수정 |
| 기존 업무보다 빨라지는가 | 제품 사용 시간 중앙값 ÷ 기존 직접 검색과 정리 시간 중앙값 | 시간이 절반 이상 줄지 않으면 자동화보다 정보 구조를 먼저 수정 |
| 결과가 실제 판단으로 이어지는가 | 판단을 저장한 계정 수 ÷ 유효한 리포트를 받은 계정 수 | 절반 이하라면 기능을 추가하지 않고 원문 확인과 판단 저장 과정을 재검토 |
| 반복해서 쓸 이유가 있는가 | 네 번의 유효 리포트를 받은 계정 중 두 번 이상 판단을 저장한 계정 비율 | 절반 이하이거나 사건이 있는 주에만 사용하면 구독형 대시보드 가설을 재검토 |
| 분석 결과를 믿고 볼 수 있는가 | 사람 검수 대비 추천 및 사실 판정의 정밀도와 재현율, 중대 오류 건수 | 표본 수와 성공 건수를 함께 보고 중대 오류가 나오면 자동 확정 범위를 줄임 |
| 수동 운영이 감당 가능한가 | 유효 리포트 한 건당 수집, 분류, 검수 시간 | 투입 가능한 운영 시간을 넘으면 반복 수집 자동화를 먼저 검토 |

개발 전에는 담당자 5명에게 운영자가 수동으로 만든 결과 화면을 제공합니다. 이 단계에서는 시장 성과를 추정하지 않고 과업 성공 수, 막힌 단계와 완료 시간을 기록합니다. 파일럿 비율은 성공 계정 수와 전체 계정 수를 함께 표시하고, 소표본을 정밀한 시장 수치처럼 해석하지 않겠습니다.
