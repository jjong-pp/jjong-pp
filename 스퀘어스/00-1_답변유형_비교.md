# 답변 유형 비교 — 무엇을 고르고 무엇을 버리는가

> **내부 비교·결정 문서.** 결정 01~23은 모두 확정됐고 실제 제출 원고는 [07_최종제출본.md](07_최종제출본.md)에 압축했다.

기준일 2026-08-15 · `00_출제의도_분석.md` 의 후속. 출제 의도를 알았다는 전제에서, **실제로 쓸 수 있는 답안이 몇 갈래이고 각각 어디서 죽는지**를 분류한다.

---

## 0. 이 문서를 쓰는 이유

`00` 은 "출제자가 무엇을 보려 하는가"를 다뤘다. 그런데 의도를 알아도 **답안은 여러 갈래로 쓸 수 있고, 갈래마다 죽는 지점이 다르다.** 초안(`01`·`02`)은 그중 한 갈래를 이미 골라 놓은 상태다.

이 문서는 그 선택을 **다시 검증**한다. 고른 길이 맞는지, 버린 길에 값이 남아 있는지, 면접에서 "왜 이렇게 안 하셨어요"를 맞았을 때 답이 있는지.

## 1. 답변의 의도 — 채점자의 머릿속에서 일어나야 하는 일

### 1-1. 두 문항은 한 동작의 앞뒤다

| | 문항이 요구하는 변환 | PM 동작 |
|---|---|---|
| 문항 1 | 모호한 것 → **재는 것** | 지표 정의 |
| 문항 2 | 잰 것 → **만드는 것** | 제품 구현 |

이 회사가 만들려는 건 GEO **진단·개선 서비스**다. 진단 서비스의 본체는 지표이고, 지표가 없으면 대시보드에 넣을 컬럼이 없다. 즉 **문항 1은 "우리 제품의 지표 체계를 설계해봐라", 문항 2는 "그 지표를 화면으로 자를 수 있나"** 다.

### 1-2. 냉정하게 보면 — 이건 입사 첫 주 업무다

과제를 "시험 문제"로 읽으면 정답을 찾으려 하게 된다. **"입사 첫 주에 시니어 PM에게 제출할 첫 문서"로 읽으면 쓸 것이 달라진다.**

- 시험 답안은 아는 것을 나열한다.
- 업무 문서는 **모르는 것을 표시하고, 정하지 않은 것을 정하자고 제안한다.**

후자가 이 자리에서 값이 나가는 문장이다. 공고 전체가 "정해진 답이 없는 신생 영역"을 두 번 반복한다. 정답을 아는 사람을 뽑는 게 아니라 **정답이 없을 때 기준을 세우고 그것을 남에게 설명할 수 있는 사람**을 뽑는다.

> **실무 판단:** 답안 안에 "이건 확인이 필요하다", "이 부분은 A와 B 중 정해야 한다"를 최소 2~3군데 남긴다. 모른다는 고백이 아니라 **범위를 통제하고 있다는 신호**로 읽힌다. 다만 핵심 축(기준 3개·기능 2개)에는 쓰지 않는다. 거기서 흔들리면 그냥 못 정한 것이다.

### 1-3. 채점자가 눈으로 훑는 순서 (추정)

| 순서 | 보는 것 | 여기서 걸러지는 답안 |
|---|---|---|
| 1 | 기준이 정확히 3개인가 / 기능이 정확히 2개인가 | 개수 안 맞음, "대시보드" 같은 그릇을 기능으로 씀 |
| 2 | 세 기준이 **서로 다른 축**인가 | 비슷한 것 셋 — 축을 하나만 본 것이 드러남 |
| 3 | 각 기준에 **재는 방법**이 붙어 있는가 | "브랜드 신뢰도 향상" 류 |
| 4 | 문항 1 → 문항 2가 **이어지는가** | 두 문항 독립 작성 (대부분) |
| 5 | **왜 이 둘인가**가 기능 설명만큼 길거나 긴가 | 기능 설명만 길고 근거는 한 줄 |
| 6 | 뺀 것이 쓰여 있는가 | 안 씀 |

**1~3은 30초 안에 판정된다.** 여기서 걸리면 나머지를 읽지 않는다. 4~6이 상위권을 가른다.

## 2. 문항 1 — 기준을 세울 수 있는 축 (재료)

기준 3개를 만들 때 쓸 수 있는 축은 대략 여덟 개다. 이 중 셋을 고르는 게 문항 1이다.

| # | 축 | 질문 형태 | 측정 가능성 | 개선 행동으로 이어지나 |
|---|---|---|:---:|:---:|
| ① | **등장량** | 얼마나 자주 나오는가 | 높음 | 낮음 |
| ② | **재현성** | 반복해도 나오는가 | 높음 | — (전제) |
| ③ | **상대 위치** | 경쟁사 대비 어디인가 | 높음 | 중간 |
| ④ | **서술 정확성** | 맞게 말하는가 | 중간 | **높음** |
| ⑤ | **언급 맥락** | 어떤 꼬리표로 나오는가 | 중간 | 중간 |
| ⑥ | **인용 출처** | 무엇을 근거로 나오는가 | 중간(모델 의존) | **높음** |
| ⑦ | **질의 커버리지** | 어느 여정 단계에서 나오는가 | 높음 | 중간 |
| ⑧ | **사업 기여** | 매출로 이어지는가 | **낮음(제로클릭)** | 낮음 |

### 여기서 이미 판단이 하나 갈린다

②(재현성)와 ③(상대 위치)를 **독립 기준으로 세울 것인가, ①에 내장할 것인가.**

- **독립으로 세우면**: 축 3개 중 2개를 "얼마나"의 변주에 쓰게 된다. 남는 축이 하나뿐이라 "어떻게"와 "왜"를 둘 다 못 다룬다. → **축 낭비**
- **내장하면**: ①이 "재현되는 등장 · 경쟁사 대비"라는 한 기준이 되고, ④~⑥에서 두 개를 더 고를 여유가 생긴다.

초안은 내장을 선택했다. **이 판단이 맞다.** 다만 면접에서 "비결정성을 왜 별도 기준으로 안 두셨나요"가 나올 수 있으니, **"기준이 아니라 모든 기준에 걸리는 측정 전제이기 때문"** 이라는 답을 준비해 둔다.

### 3-1. E를 고른 것의 진짜 값

E의 강점은 지표 세 개를 나열하는 데 있지 않다. **성과를 정의하고, 그 성과의 품질을 지키고, 실제 행동 뒤의 변화를 다시 검증하는 하나의 순환**을 만든다는 데 있다.

```
성과 기준선: 자사 가중 노출률·추천률과 경쟁사 대비 가중 추천 점유율. 선두 격차·평균 추천순위는 해석용 진단
품질 가드레일: 추천 역할·이유·사실 정확성·포지셔닝. 사람이 P0로 확인했고 최신 상태가 활성·해제 후보·재개방인 미해결 이슈는 원점수를 보존하고 최종 등급을 `주의` 또는 `위험`으로 표시
학습 루프: 근거 → 원인 가설 → 행동 → 즉시 동조건 검증 → 주간 유지·재발 감시 → 다음 결정
```

세 기준은 서로 대체하지 않는다. 노출만 높으면 잘못 알려질 수 있고, 정확하기만 해도 후보에 들지 못하며, 측정만 반복하면 고객의 다음 행동으로 이어지지 않는다. 이 관계가 문항 1의 기준을 문항 2의 제품 구조로 연결한다.

### 3-2. E의 약점과 방어

| 약점 | 방어 |
|---|---|
| ‘지속적 개선’은 좋은 GEO의 기준보다 제품 기능처럼 들린다 | 좋은 GEO의 **상태**를 ‘중요한 질문에서의 바람직한 성과가 유지되거나 개선되는 것’으로 정의하고, `가설 → 행동 → 재측정`은 그 상태를 검증·유지하는 **제품 메커니즘**으로 구분한다 |
| 행동 전후 수치가 좋아지면 원인이 증명됐다고 오해할 수 있다 | 공식 시계열은 웹 검색을 지원하는 API 경로에서 만들고, 질문·가중치·모델/스냅샷·언어·지역·반복·산식 버전을 기록한다. 검색 실행을 모델이 판단하는 경로는 실행 증거를, 웹 그라운딩 전제 경로는 검색 결과·인용 메타데이터를 보존한다. 통제 UI 표본은 대표성 검증으로 분리하며 결과는 인과 확정이 아니라 `개선 / 유지 / 악화 / 비교 불가`의 운영 증거로 표현한다 |
| 세 기준이 선행지표라 사업 성과와 멀어 보인다 | AI 리퍼럴·브랜드 검색·리드 유입 경로·파이프라인은 후행 검증 지표로 별도 추적한다. 다중 접점 때문에 GEO의 직접 인과로 단정하지 않는다 |
| 종합 점수가 정밀해 보이지만 경쟁사 하락·질문 변경·오류 상쇄를 숨길 수 있다 | 절대·상대 지표를 분리하고 질문·경쟁사군·산식을 버전 관리한다. 사람이 확인한 미해결 P0는 원점수를 바꾸는 산술 감점이 아니라 최종 등급 상한으로 처리한다 |

## 4. 문항 2 — 기능 후보 (재료)

| 축 | 후보 |
|---|---|
| **측정** | M1 목표 질문 가중 노출률·추천률 반복 측정 · M2 경쟁사 대비 추천 점유율 · M3 목표 질문 세트·가중치 관리 · M4 모델별 비교 · M5 공식 API 시계열과 통제 UI 대표성 표본의 분리 검증 |
| **진단** | D1 추천·비교·단순 언급·주의 역할 분류 · D2 사실 오류 검출 · D3 추천·제외 이유와 근거 원문 · D4 인용·언급 출처와 기준 정보 대조 |
| **행동** | A1 근거가 연결된 원인 가설·우선 행동 · A2 개선 과제 관리 · A3 즉시 동조건 검증·주간 재발 감시 · A4 리포트 내보내기 |

경영진용 종합 원점수는 M1의 `가중 노출률 25 + 가중 추천률 45`와 M2의 `가중 추천 점유율 30`으로 시작한다. 사람이 P0로 확인했고 최신 상태가 `활성·해제 후보·재개방`인 미해결 이슈가 있으면 원점수는 그대로 두고 최종 등급을 `주의` 또는 `위험`으로 표시한다. 선두 격차와 평균 추천순위는 해석용으로만 표시한다. 이 구조는 고객 문제와 실제 추천을 우선하는 MVP 가설이며, 질문군·경쟁사군·산식 버전이 다른 점수는 직접 비교하지 않는다.

측정 정본은 **웹 검색 도구 사용을 허용한 공식 API의 표준 관측 시계열**로 둔다. 고정된 모델/스냅샷·언어·지역·반복 조건과 응답별 `search_used`를 기록한 API 결과만 원점수·추이·변화량에 사용한다. 실제 화면과의 차이는 로그인·메모리·대화 이력 등 개인화 요인을 줄인 **통제 UI 표본**으로 별도 확인하고, API와 UI의 노출·추천 격차와 대표 역할 일치도를 보여주되 두 경로의 값을 합산하지 않는다. 어느 경로에서든 사람이 P0를 확인하면 원점수는 보존한 채 최종 등급 상한을 적용하며, 해제 검증은 그 P0가 처음 확인된 경로에서 수행한다.

| **6. 측정 + 개선 루프형** ← 선택 | F1(M1+M2+M3+M4+D1) + F2(D2+D3+D4+A1+A2+A3) | `어디에서 얼마나·어떻게`를 측정하고 `무엇을 바꿔 나아졌는가`까지 연결 | **F2가 넓어 보일 수 있음.** 하나의 JTBD와 동일 데이터·동선을 근거로 범위를 설명해야 함 | **상 (단 방어 필요)** |

### 5-1. 초안(유형 6)의 최대 리스크

면접 첫 질문으로 이게 나올 확률이 높다.

> "F2가 오류·출처 진단부터 행동과 재측정까지 들어 있는데, 이게 하나의 기능인가요?"

**준비된 답이 있어야 한다.** 세 가지 방어가 가능하고, 셋 다 쓰는 게 좋다.

1. **데이터 원천이 하나다.** F1이 보존한 답변 원문·판정 근거·출처와 고객이 승인한 기준 정보를 함께 사용한다. 진단과 과제를 분리하면 같은 증거를 다시 찾아야 한다.
2. **사용자 동선이 하나다.** 담당자의 과업은 “왜 이렇게 나왔고 이번 주 무엇을 바꿀까?”다. 문제 원문에서 원인 가설·행동·재측정으로 이어지는 하나의 결정 흐름이다.
3. **기능의 끝은 화면이 아니라 완료된 과업이다.** 행동을 보여주는 데서 끝나면 권고안이고, 다시 숫자만 재면 대시보드다. 선택한 행동을 같은 기준으로 재측정해 다음 결정을 정해야 루프가 닫힌다.

### 5-2. 그래도 손볼 것 — F2 내부에 우선순위를 준다

FR 18개를 같은 무게로 나열하면 "다 필수"라고 말하는 셈이고, 자를 줄 모른다는 인상을 준다. **F2 안에서도 1차/2차를 갈라 쓴다.**

| F2 내부 | 핵심 (1차) | 후순위 (같은 릴리즈 내 후반) |
|---|---|---|
| 근거·출처·기준 정보 진단 | FR-11~FR-15 | |
| 원인 가설·행동 우선순위 | FR-16 | |
| 과제 등록·즉시 동조건 검증·주간 재발 감시 | | FR-17~FR-18 |

추천 역할 분류는 ‘어떻게 등장했는가’를 측정하는 F1의 FR-05에 둔다. F2는 그 판정과 근거를 받아 원인 가설과 다음 행동으로 바꾼다.

FR-16은 단일 합산 점수가 아니라 `목표·최소 근거 관문 → 중대한 사실 오류(P0) → 고객·사업 영향 등급 → 근거 신뢰도 → 실행 효율` 순으로 판단한다. 고영향·저신뢰 항목은 즉시 수정하지 않고 검증 과제로 바꾼다.

위 표는 **무엇을 먼저 개발할지**에 대한 우선순위다. FR-16이 사용자에게 **어떤 행동부터 제안할지**는 별도 규칙이며, 확정된 목표 질문 안에서 고객·사업 영향을 먼저 비교하고 같은 영향 등급에서만 근거 신뢰도와 실행 효율을 본다.

이렇게 쓰면 **"2개로 묶었지만 그 안에서도 자르고 있다"** 가 드러난다. 자를 줄 안다는 증거는 기능 개수가 아니라 이런 데서 나온다.

### 6-3. 분량 — 통합 제출본으로 압축

상세 `01·02`는 의사결정과 면접 방어 자료로 남기고, 실제 PDF 원고는 `07_최종제출본.md`에 별도로 압축한다. 목표는 본문 5~6쪽과 출처·운영 가설을 담은 짧은 부록 1~2쪽이다.

**FR 18개 · NFR 5개 · 리스크 5개는 4년차 이하 과제로는 많다.** 두 가지 리스크가 있다.

- **의심**: 분량과 완성도가 경력과 안 맞으면 "직접 쓴 게 맞나"가 든다.
- **방어 실패**: 1차 면접이 "지원 서류와 과제를 바탕으로" 진행된다. **문장 수가 곧 질문 수다.** 방어 못 하는 문장은 자산이 아니라 부채다.

**다만 완화 요인이 하나 있다.** 포트폴리오의 관세 API 문서가 이미 FR-01~10 / NFR-01~05 / 제약 3건 형식이다. 형식이 같으면 "평소에 이렇게 쓴다"는 증거가 된다. → **과제에 "포트폴리오와 같은 형식으로 작성했습니다" 한 줄을 넣으면 의심이 근거로 바뀐다.**

**결론: 형식은 유지하고 분량만 줄인다.** FR을 지우지 말고 **표현을 압축**한다(근거 열의 문장을 명사구로). 서술형 단락 중 논증이 아닌 것부터 덜어낸다.

## 7. 주니어 포지션 캘리브레이션

신입~4년차를 뽑는 자리다. 기대치를 잘못 잡으면 두 방향으로 다 틀린다.

| | 과소 | 적정 | 과잉 |
|---|---|---|---|
| **기준의 근거** | "중요하니까" | **왜 이 축인지 + 안 고른 축과의 대비** | 학술 인용 남발 |
| **측정 방법** | "측정한다" | **N×M×R 설계와 지표 정의** | 통계적 검정력 계산 |
| **기능 범위** | 아이디어 나열 | **FR/NFR + 뺀 것과 사유** | 화면 설계·API 스펙 |
| **리스크** | 없음 | **모델 종속·오탐·원가 3~5건** | 전사 리스크 매트릭스 |
| **모르는 것** | 얼버무림 | **"이건 정해야 한다"로 표시** | 전부 미정으로 남김 |

**주니어에게 기대되는 건 완결성이 아니라 사고의 뼈대다.** 다만 이 과제는 예외가 하나 있다 — **GEO 시장에 4년차 전문가는 존재하지 않는다.** 아무도 안 해본 영역이라 연차가 만드는 격차가 가장 작다. 그래서 "직접 두들겨 봤다"가 연차를 뒤집을 수 있는 거의 유일한 자리다.

> **즉 이 과제에서 주니어가 이기는 방법은 지식량보다 검증 가능한 판단이다.** 접근이 확보되면 27회 파일럿을 원문까지 검수하고, 확보되지 않으면 숫자를 만들지 않는다.
