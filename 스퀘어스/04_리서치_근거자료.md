## 1. 비결정성과 측정 설계 — 결과변수 주의가 필요한 보조 블록

### 1-0. 최종 본문에 사용하는 직접 근거

Jack et al.의 2026년 사전연구는 상업 추천 질문 50개를 두 모델(OpenAI gpt-5.4-mini, Anthropic Claude Sonnet 4.6)의 저·고 추론 강도, 총 네 조건에서 각 30회 재실행했습니다. 동일 질문 재실행에서도 추천 브랜드 집합의 평균 중첩도(Jaccard)는 0.50~0.61이었고, 의미를 유지한 표현 변형 간 추천 집합 Jaccard는 0.288이었습니다. 단일일·영어·두 제공사 실험이므로 수치를 보편화하지 않습니다. 이 연구는 단발 측정뿐 아니라 고정 문장 하나를 구매 의도의 대리값으로 쓰는 설계도 불안정할 수 있다는 근거로 사용합니다.

> 출처: [Jack et al. (2026), *Paraphrase Brittleness in Production Retrieval-Augmented Commercial Recommendation: Reproducibility Below the Rerun-Stability Baseline*, arXiv preprint](https://arxiv.org/abs/2605.27440)

### 1-1. 핵심 논문

**"Where Does the Noise Come From? A Variance-Components Decomposition of Non-Determinism in LLM Brand Answers"** (arXiv 2607.13304, 2026-07)

응답별 다국어 **감성값**의 노이즈가 어디서 오는지를 분산 성분으로 분해한 연구다. 제목에 Brand Answers가 들어가지만 결과변수는 브랜드 포함 여부나 추천률이 아니다.

> **최종 인용 주의:** 아래 수치는 원문과 일치하지만 노출·추천 측정의 최적 예산이나 충분 반복 수를 직접 검증하지 않는다. 최종 제출본에서는 추천 집합의 재실행 변동을 직접 측정한 [arXiv 2605.27440](https://arxiv.org/abs/2605.27440)을 반복 측정 필요성의 근거로 사용하고, 이 절은 후속 다국어 실험 가설로만 보존한다.

**설계**

| 항목 | 규모 |
|---|---|
| 총 응답 | 12,933건 |
| 브랜드 | 20개 (중·동유럽, 복수 산업) |
| 언어 | 8개 |
| 모델 | 3종 (GPT-5.2, Gemini 3 Flash, Perplexity) |
| 프롬프트 | 15개 (5개 카테고리) |
| 반복 | 안정성 부분집합에 약 5회 |

**분산 분해 결과**

| 성분 | 비중 |
|---|---:|
| 프롬프트 내 재샘플링 (같은 질문 반복) | **34.8%** |
| 질의 언어 | 31.6% |
| 브랜드 × 맥락 상호작용 | 29.6% |
| 브랜드 × 언어 (이중언어 페널티) | 8.6% |
| 브랜드 자체 (맥락 무관) | 0.7% |
| 브랜드 × 모델 | ≈ 0% |
| 브랜드 × 프롬프트 | ≈ 0% |

### 1-2. 답안을 뒤집는 발견 — 측정 예산 배분

기준 설계(1언어 × 1모델 × 5패러프레이즈 × 5반복 = 25회)에서 **무엇을 더 늘릴 때 오차가 가장 줄어드는가:**

| 추가 항목 | 상대오차 분산 감소 |
|---|---:|
| 언어 3개 추가 | **0.00462** |
| 모델 2개 추가 | 0.00167 |
| 패러프레이즈 5개 추가 | 0.00125 |
| **반복 5회 추가** | **0.00030** |

> **언어 다양성은 반복 5회 추가보다 약 15배 더 오차를 줄인다.**
> 논문의 권고: **반복은 5회에서 멈추고, 언어와 모델 커버리지를 먼저 최대화하라.**

### 1-3. 후속 감성·다국어 실험에 주는 시사점

해당 연구의 감성 결과 안에서는 반복 확대보다 언어·모델 범위를 늘리는 편이 예산 효율이 높았습니다.

- 반복·언어·모델이 모두 관측 변동의 원인이 될 수 있다는 점을 보여줍니다.
- 다만 이 결과만으로 노출·추천 측정의 반복 수나 최적 예산을 정할 수 없습니다.
- 현재의 최소 3회는 연구에서 도출한 정답이 아니라 단발 오판 위험과 비용을 절충한 MVP 가설입니다.

**활용 범위:** 이 결과는 감성 분석을 다국어로 확장할 때 언어·모델·반복 예산을 다시 실험해야 한다는 가설을 만듭니다. 현재 한국어 MVP의 노출·추천 반복 수를 정당화하거나 “5회면 충분하다”고 주장하는 데에는 사용하지 않습니다.

### 1-4. 또 하나 — 신뢰도 천장

- **단일 답변(1언어·1모델·1패러프레이즈·1반복)의 브랜드 판별력: Eρ² ≈ 0.01** → 랭킹 신호가 사실상 없음
- 완전 크로스 설계(8언어 × 3모델 × 15패러프레이즈)로도 **Eρ² ≈ 0.36 이 천장** (반복 1~20회 무관, 0.347~0.365)

**활용 제한:** 이 신뢰도는 해당 연구의 감성 결과와 설계에 대한 값입니다. 일반적인 브랜드 노출 랭킹의 신뢰도 천장으로 최종 본문에 인용하지 않습니다.

## 4. 업계 표준 지표 6종 — 이미 정의되어 있다

| 지표 | 정의 | 계산 |
|---|---|---|
| **Mention Rate (Visibility Score)** | 추적 프롬프트 중 브랜드가 등장한 비율 | 등장 응답 수 ÷ 전체 응답 수 |
| **Share of Voice (SoV)** | 자사+경쟁사 전체 언급 중 자사 비중 | 자사 언급 ÷ (자사+경쟁사 언급) |
| **Citation Share** | 브랜드가 **출처로 명시 인용**된 빈도 | — |
| **Recommendation Rate** | 언급 중 **실제 추천**인 비율 | 추천 응답 ÷ 전체 프롬프트 |
| **Sentiment** | 언급의 긍/부정 | — |
| **Prompt Coverage** | 커버한 질의 범위 | — |

**벤치마크:** AI SoV **10~15%면 기성 사업자로 양호**, 시장 리더는 25%+

### 4-1. 이게 초안에 주는 충격

**기준 2의 "위치·맥락"은 Recommendation Rate·Sentiment 같은 상용 지표로 이미 다뤄진다. 사실 정확성 역시 미개척 영역이 아니다.** Profound FactCheck는 AI 답변에서 객관적·원자적 주장을 추출해 고객이 등록한 Knowledge Base와 대조하고 `accurate / inaccurate / not relevant`로 분류한다. 부정확한 주장에는 관련 인용 URL과 Knowledge Base의 기준 정보도 연결한다.

> **조치: 기준 2는 차별화 축이 아니라, 높은 노출이 잘못된 설명을 가리지 않게 하는 품질 기준으로 유지한다.** 제품 차별화는 사실 오류 탐지 자체가 아니라 고객 문제·목표 질문에 따른 영향 우선순위, 사용자 확인, 특정 행동과 동조건 재측정의 연결에서 검증한다.

**추가 재료 — 인용 실패 분류** (arXiv 2603.09296): Missing / Incorrect / Hallucinated / Incomplete. 사실 오류를 유형화할 때 이 분류를 인용하면 임의 분류가 아니게 된다.

### 4-2. 정확성을 평균 점수와 분리할 근거

Profound가 정확성을 가시성과 분리한 계층으로 운영하고 사용자 피드백으로 오탐을 제거하는 것은 `원점수와 품질 판정의 분리`를 뒷받침한다. FactCheck는 기간별 정확도 변화도 제공한다. NIST AI RMF는 위험관리가 지속적·반복적이어야 하고 운영 중 정기 평가와 모니터링이 필요하다고 설명한다. 이 자료들은 수정 직후의 재검증과 이후 정기 모니터링을 분리하는 방향을 뒷받침한다. 다만 `P0 발생 시 원점수를 보존하고 최종 등급을 주의 또는 위험으로 표시`, `한 유효 사이클 후 사람 승인으로 운영상 해제`, `주 1회 감시`라는 구체 규칙은 제시하지 않는다. 등급 표시·해제 조건·정확한 주기는 본 PRD의 MVP 운영 가설이다.

### 5-1. 초안이 정면으로 맞는 지점

**F2의 핵심 구성요소인 출처 추적과 사실 오류 검출·대응은 Profound FactCheck에 이미 있다.** FactCheck는 Knowledge Base를 정본으로 주장을 검증하고, 부정확한 주장과 관련 인용 URL을 연결하며, 해당 화면에서 외부 출처 아웃리치·자사 정보 갱신·신규 콘텐츠 생성을 위한 Agent를 실행할 수 있다. Accuracy Score·Share와 기간별 변화도 제공한다. 따라서 "출처를 보여준다", "사실 오류를 찾는다", "수정 행동을 제안한다"만으로는 차별화되지 않는다.

**공개 문서에서 아직 확인되지 않은 설계 차이 3개:**

| 설계 차이 | 검증 결과 |
|---|---|
| **통제 수준·실행 권한의 명시적 분류** | Profound는 인용 URL과 아웃리치·Knowledge Base 수정·콘텐츠 생성 행동을 제공하지만, 공개 문서에서는 발행 주체·통제 수준·실행 권한을 독립 필드로 분류하는지 확인되지 않음 |
| **특정 행동과 동조건 재측정 결과의 연결** | Profound는 기간별 정확도 비교를 제공하지만, 특정 행동의 기준선·질문/산식 버전과 이후 변화를 연결해 `개선/유지/악화/비교 불가`로 판정하는지는 공개 문서에서 확인되지 않음 |
| **측정 예산 배분 근거** | 모델·언어·패러프레이즈·반복 사이의 예산 효율을 공개 연구에 따라 배분하는 제품 설계는 확인되지 않음 |

> **조치: F2의 약속을 "인용 출처 추적·사실 오류 검출"이 아니라 "고객 문제에 미치는 영향을 기준으로 행동을 정하고, 사용자가 선택한 행동을 동일 조건의 후속 측정과 연결해 검증한다"로 쓴다.** 경쟁 제품에 없다고 단정하지 않고, 공개 문서에서 확인되지 않은 설계 차이이자 MVP 가설로 표현한다.

## 7. llms.txt — 초안의 주장이 사실로 확인, 그것도 훨씬 세게

초안은 "인과가 아직 검증되지 않았다"고 썼다. **실제로는 그보다 강한 증거가 있다.**

| 증거 | 내용 |
|---|---|
| **Google 공식 문서 (2026-06)** | llms.txt는 Search 순위·AI Overviews에 **영향이 없다.** Search가 파일을 무시한다 |
| **John Mueller** (Search Off the Record, 2026-06-15) | **자기 신고 매니페스트는 사이트 간 차별자가 될 수 없다.** 모든 사이트가 자기가 최고라고 주장할 것이기 때문 |
| | AI 크롤러 중 어느 것도 llms.txt로 정보를 추출한다고 밝힌 곳이 없다 |
| **Ahrefs, 137,000 사이트 분석** | **97%의 llms.txt 파일이 2026년 5월 한 달간 트래픽 0** |
| 예측력 검정 | 상관 분석 + XGBoost로 AI 인용 빈도 예측력 검정 → **없음.** llms.txt를 모델에서 빼니 정확도가 **올라감** (= 노이즈였음) |

### 7-1. 답안 활용 — 함정 1을 정면으로 친다

`00` 3절의 함정 1이 "SEO 재탕(llms.txt·스키마)"이다. 대부분의 지원자가 여기를 밟는다.

**초안의 "뺀 기능" 절에서 이렇게 쓸 수 있다:**

> llms.txt·구조화 데이터 자동 생성을 검토했으나 제외했습니다. 구글은 2026년 6월 문서에서 llms.txt가 검색 순위와 AI Overviews에 영향이 없으며 Search가 이 파일을 무시한다고 명시했고, 137,000개 사이트를 분석한 결과 97%의 llms.txt가 한 달간 한 번도 읽히지 않았습니다. 효과가 검증되지 않은 실행 도구를 진단 제품의 1차 기능으로 두는 것은 순서가 맞지 않습니다. **검증 수단(F1·F2)을 먼저 갖춘 뒤, 이 도구의 효과를 자사 데이터로 확인하는 것이 맞다고 봅니다.**

**이 한 단락이 함정 1을 밟은 다른 답안 전부와 대비된다.** 남들이 "해야 한다"고 쓴 것을 "근거를 들어 안 한다"고 쓰는 것이다.

## 8. 측정 정본 검증 — API 시계열 + 통제 UI 표본

확인한 공식 문서에서는 API 응답과 소비자 웹 UI 응답의 동일성을 보장하는 문구를 찾지 못했다. API는 모델·검색 도구·위치·언어 등 일부 조건을 명시하고 반복 실행할 수 있지만, UI에는 계정 개인화·검색 모드·요금제·제품별 모델 선택과 위치 정보가 추가된다. 따라서 두 경로의 역할을 나눈다.

| 사업자 | API에서 통제·기록할 조건 | 소비자 UI가 달라질 수 있는 이유와 자동화 제약 |
|---|---|---|
| **OpenAI** | Responses API에 `web_search`를 넣어야 하며 모델이 실제 검색 여부를 결정한다. 검색 설정·근사 위치와 고정 모델 스냅샷을 기록할 수 있다. | ChatGPT Search는 필요 시 자동 검색하고 Memory와 IP 기반 일반 위치·선택적 기기 위치를 검색어에 반영할 수 있다. 이용약관은 Output의 자동·프로그램식 추출을 금지하므로 UI 대량 자동화는 하지 않는다. |
| **Anthropic** | Claude API에 `web_search` 도구를 넣고 검색 횟수·도메인·근사 위치를 설정할 수 있다. API 모델 ID는 고정 스냅샷이다. | Claude UI는 검색 토글·모델·노력 수준·프로필/프로젝트 지침과 IP 위치의 영향을 받는다. 소비자 약관은 API 키 또는 명시적 허용이 없는 자동·비인간 접근을 금지한다. |
| **Google Gemini** | Gemini API에 `google_search` 도구를 넣으면 모델이 검색 필요 여부를 판단한다. `stable` 모델은 보통 고정되지만 `latest` 별칭은 새 릴리스로 교체된다. | Gemini UI는 모델 선택, 일반·정밀 위치, 과거 대화와 Connected Apps 개인화의 영향을 받는다. Google 약관은 웹페이지의 기계 판독 지침을 위반하는 자동 접근을 금지하므로 별도 허용을 확인하기 전에는 수동 표본만 사용한다. |
| **Perplexity** | Sonar는 웹 기반 응답을 제공하고 모델·검색 활성화·검색 모드·언어·위치·도메인 필터를 설정할 수 있다. | UI는 모델 선택·프로필·응답 언어·네트워크 위치의 영향을 받는다. Perplexity는 API가 공개 답변 엔진과 같은 검색 인프라를 쓴다고 설명하지만 같은 응답을 보장한다는 문구는 확인되지 않는다. 소비자 UI 자동화 허용 범위는 공식 약관에서 확인하지 못했으므로 API를 자동화 경로로 쓰고 UI는 수동 표본으로 제한한다. |

### 8-1. 확정한 제품 규칙

1. **API를 공식 시계열로 사용한다.** 정확한 API/모델 ID·측정 경로·질문 버전·언어·지역·검색 도구와 설정 버전·반복 규칙을 고정한다.
2. **UI는 실제 경험 대표성의 통제 표본이다.** 로그인·Memory·프로필·Connected Apps·요금제·표시 모델·검색 모드·네트워크 지역·실행 시각을 기록한다. 로그아웃·시크릿이어도 IP/네트워크 위치가 남을 수 있으므로 `비개인화`가 아니라 `개인화 요인을 줄인 통제 UI 표본`이라고 부른다.
3. **두 경로는 합산하지 않는다.** API 결과는 `표준 관측치`, UI 결과는 `소비자 경험 표본`으로 나란히 표시하며 한 경로의 미등장으로 다른 경로의 오류·노출을 상쇄하지 않는다.
4. **검색 정책과 실제 실행을 분리한다.** `search_policy`(`available_auto / forced / ui_default`)와 `search_used`를 따로 저장한다. 도구를 사용할 수 있게 해도 OpenAI·Claude·Gemini 모델이 검색하지 않을 수 있으므로, 검색 호출 블록·검색 표시·인용 같은 증거가 없으면 `search_used=unknown`으로 둔다. 검색을 끈 API는 이번 MVP 측정 범위에서 제외한다.
5. **모델·경로·검색 설정이 바뀌면 새 조건 버전이다.** 변화량에 합치지 않고 `비교 불가`로 표시한다. UI의 정확한 모델 빌드를 알 수 없으면 표시 모델명은 저장하되 API와 동일 모델이라고 판정하지 않는다.
