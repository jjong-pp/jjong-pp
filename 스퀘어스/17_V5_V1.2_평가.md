#### B1 문제 정의

34행은 사건 발생이라는 트리거와 직접 검색의 한계를 구체적으로 설명한다. 38~41행은 두 역할이 어떤 결정을 내리는지까지 연결해 일반적인 페르소나 설명보다 훨씬 강하다.

다만 “같은 팀에서 판단과 실행을 나눠 맡는 두 역할”은 아직 검증되지 않은 조직 구조다. 구독형 B2B SaaS 스타트업에서는 한 명이 두 역할을 겸할 가능성도 높다. 다음처럼 가설 상태를 더 명확히 하는 편이 안전하다.

> 초기 핵심 사용자는 AI 노출을 주간 단위로 확인하는 브랜드 담당자로 가정한다. 콘텐츠 마케터가 별도로 있는 조직에서는 원문 조사와 후속 실행을 넘겨받는다. 두 역할의 분리 여부는 인터뷰에서 확인한다.

#### B2 기능 경계

기능의 개별 가치는 명확하다.

- 기능 1: 변화가 큰 질문을 찾아 대응 여부 결정
- 기능 2: 원문과 출처를 확인해 조사 대상 결정

하지만 두 기능의 연결 조건이 한 문장으로 고정되어 있지 않다. 예를 들어 `기능 1에서 기준선 대비 변화가 크거나 경쟁사 격차가 벌어진 질문을 선택하면 기능 2의 해당 답변 묶음으로 이동한다`가 필요하다.

수집 실패가 많아 변화량을 계산할 수 없을 때 무엇을 보여주는지, 공식 정보가 없어 사실 확인이 불가능할 때 어떤 종료 상태가 되는지도 기능 단위 실패 흐름으로 묶으면 수준 4에 가까워진다.

#### B3 우선순위

50행의 두 문장은 매우 좋다.

> 기준선이 없는 알림은 무엇이 변했는지 설명하기 어렵고, 믿지 못하는 진단에서 나온 개선안은 실행하기 어렵습니다.

선행 관계와 신뢰 문제를 동시에 보여주며, 자동화 전에 수동으로 핵심 가치를 시험한다는 판단도 명확하다.

다만 다음 후보를 같은 기준으로 비교하지 않았다.

- 실시간 알림
- 자동 질문 생성
- 공식 자료 자동 사실 비교
- 자동 개선안
- 콘텐츠 생성·게시

`사용자 결정 기여 / 선행 데이터 필요 / 수동 검증 가능 / 구현·운영 위험`으로 비교하고, 예를 들어 “사용자가 주간 회의보다 사건 직후 대응을 더 중요하게 여기면 알림을 재검토한다”는 역전 조건을 제시하면 수준 4다.

#### B4 요구사항

V5의 가장 강한 부분이다.

- 질문 변경 시점 기록
- 동일 서비스·언어·검색 설정 반복
- 수집 실패를 미노출로 계산하지 않음
- API와 소비자 화면을 별도 시계열로 기록
- 자동 판정 근거 문장 제공
- 공식 정보가 없으면 오류 확정 금지
- 맞음·다름·판단 보류 사용자 검수

개발자가 다시 확인할 부분은 남아 있다.

- `유효 답변`: 거절, 빈 답변, 관련 없는 답변, 중단된 답변 중 무엇을 제외하는가
- `적합한 선택지`: 단순 나열과 추천의 경계는 무엇인가
- 질문 변경: 변경 전후를 한 그래프에 표시하되 비교 불가로 처리하는가, 새 기준선을 만드는가
- 등장 역할 판정: 사용자가 분류를 수정할 수 있는가

이 누락들은 B4를 수준 3으로 내릴 정도는 아니지만, 구현 착수 전 정책 결정 목록에 들어가야 한다.

#### B5 성공 측정

72행의 핵심 지표는 제품 목적과 직접 연결된다. 클릭이나 체류시간이 아니라 원문과 출처를 확인한 뒤 업무 판단을 저장했는지를 본다. 79행의 사람 검수 일치율과 판단 보류 비율은 핵심 지표가 좋아도 자동 분류가 불안정할 수 있는 위험을 통제한다.

83행도 5명이라는 작은 표본을 시장 성과로 과장하지 않고, 다음 개발 단계로 넘어가는 내부 판단선이라고 명시했다. 이는 0→1 과제에서 적절하다.

다만 핵심 지표의 분모가 `첫 리포트를 확인한 계정`이므로 설정 또는 리포트 생성에 실패한 계정은 제외된다. 실제 제품 퍼널에는 다음 지표가 추가로 필요하다.

> 질문 설정을 완료한 계정 중 유효한 첫 리포트를 확인한 계정 비율 및 첫 리포트 생성 소요시간

## 6. AI 문체 위험 진단

**위험 등급: 낮음**

### 위험 신호

- `첫 가치 / 진단 가치 / 반복 가치 / 분석 품질`처럼 대칭적인 지표 구분이 있다.
- “기준선이 없는 알림은…, 믿지 못하는 진단에서 나온 개선안은…” 문장은 다듬어진 카피처럼 읽힐 수 있다.
- 요구사항이 일정한 문장 구조로 반복되어 일부 독자에게는 AI가 정리한 문서 인상을 줄 수 있다.

이 신호만으로 AI 작성이나 대필을 의심할 수준은 아니다. 해당 구조는 정보 탐색에 실제로 도움을 주며 문장부호와 굵은 글씨도 과도하지 않다.

### 사람의 판단이 분명한 반대 증거

- 추천률을 모든 질문에 적용하지 않고 추천·비교 의도 질문으로 제한했다.
- 수집 실패를 미노출로 세지 않았다.
- API와 소비자 화면을 별도 시계열로 분리했다.
- 공식 정보가 없을 때 사실 오류를 자동 확정하지 않았다.
- 알림과 자동 개선안을 첫 버전에서 제외했다.
- 5명 파일럿 수치를 시장 목표가 아닌 내부 판단선이라고 밝혔다.

이 결정들은 일반론을 매끄럽게 조립한 문서보다 실제 제품 판단의 흔적에 가깝다.

### 점수 반영

- D1 가독성: AI 문체 때문에 추가 감점하지 않음
- D2 신뢰성: AI 사용 추측으로 감점하지 않음
- D3 소유권: 선택과 제외가 구체적이므로 실무 충족 수준 인정

### 면접 소유권 질문

1. 왜 추천률을 정보 탐색 질문에 적용하지 않았으며, 추천과 단순 나열의 경계를 어떻게 판정할 것인가?
2. 공식 정보가 등록되지 않았을 때 자동 오류 판정을 막은 이유와 그에 따른 운영 비용을 설명해달라.

## 7. 이해관계자별 평가

### 채용 담당자 관점

과제 형식 준수, 문서 완결성, 자연스러운 한국어, 사실 상태 통제는 안정적이다. 포트폴리오와 함께 보면 면접으로 넘길 만하다. 다만 실제 지원자의 사고인지 확인하기 위해 두 기능의 대안과 수치를 자료 없이 설명하도록 해야 한다.

판정: **진행 권고**

### CEO·대표 관점

좋은 점은 큰 GEO 플랫폼을 한 번에 만들려 하지 않고 수동 운영으로 고객의 업무 사용 여부부터 보겠다는 판단이다. 한 채널, 주 1회, 3회 반복이라는 임시 운영값도 파일럿에서 조정한다고 밝혀 과도한 확신이 없다.

우려는 사용자 역할과 문제의 빈도다. “브랜드 인식이 달라질 만한 사건”이 얼마나 자주 발생하며, 주간 회의에서 이 문제에 실제 예산과 시간을 쓰는지가 아직 가설이다. 이 빈도가 낮다면 반복 제품보다 일회성 리포트나 대행 서비스가 먼저일 수 있다.

판정: **0→1 감각은 강함. 문제 빈도와 지불 의사 면접 검증 필요**

### 시니어 PM·조직장 관점

문제→기능→정책→지표→수동 검증의 논리 연결이 좋다. 특히 성공 지표를 단순 노출 개선이 아니라 업무 판단 저장으로 둔 것이 제품 사고를 보여준다.

다만 우선순위 논증은 “왜 알림과 개선안이 아닌가” 수준이다. 모든 후보를 같은 기준으로 잘라낸 흔적과 우선순위 역전 조건이 있어야 강한 PM 판단으로 올라간다.

판정: **과제 통과. 우선순위 방어 면접 필요**

### 개발자 관점

수집 조건, 분모, 실패 제외, 시계열 분리, 판정 근거, 사용자 검수까지 있어 구현 논의를 시작할 수 있다. 일반적인 PRD보다 정책 밀도가 높다.

착수 전 필요한 결정은 다음과 같다.

- 유효 답변과 수집 실패의 상태값
- 추천·비교 후보·단순 언급의 분류 기준
- 질문 수정 뒤 과거 시계열 비교 규칙
- 소비자 UI 수집의 접근 방법과 운영 안정성
- 등장 역할 자동 분류의 사용자 정정·재학습 처리

판정: **착수 가능하나 핵심 정책 워크숍 필요**

### 디자이너 관점

사용자가 무엇을 보고 어떤 결정을 저장하는지가 명확하고, 전체 점수보다 변화가 큰 질문을 먼저 보여준다는 우선순위도 좋다. 원문으로 이동할 수 있게 한 점은 신뢰 형성에 유리하다.

다만 첫 화면에서 브랜드 매니저와 콘텐츠 마케터가 각각 다른 대시보드를 보는지, 한 사람이 두 역할을 겸할 때 흐름이 어떻게 달라지는지, 판단 보류 후 다시 돌아오는 상태가 무엇인지가 필요하다.

판정: **핵심 과업은 명확. 역할과 상태 전이 정의 필요**

## 8. P0 수정: 최대 세 개

### P0-1. 주 사용자와 문제 가설을 한 단계 더 좁힌다

현재 두 역할을 확정 구조로 쓰지 말고 주 사용자, 보조 사용자, 한 사람이 겸하는 경우, 비대상 사용자를 구분한다. 문제 빈도와 현재 업무 행동을 인터뷰에서 검증할 가설로 표시한다.

예상 영향: B1 수준 3→4, 최대 +2점

### P0-2. 기능 후보 비교와 우선순위 역전 조건을 추가한다

알림, 자동 질문 생성, 자동 사실 비교, 자동 개선안, 콘텐츠 생성 중 최소 세 개를 `사용자 결정 기여 / 선행 데이터 / 수동 검증 가능 / 구현·운영 위험`으로 비교한다. 각 제외 기능을 다시 검토할 조건을 한 줄씩 둔다.

예상 영향: B3 수준 3→4, 최대 +3점

### P0-3. 두 기능의 연결과 핵심 판정 용어를 고정한다

다음을 짧게 추가한다.

- 기능 1에서 어떤 조건의 질문을 선택하면 기능 2로 이동하는가
- 수집 실패가 많아 추세를 계산할 수 없을 때 무엇을 보여주는가
- 유효 답변과 적합한 선택지의 판정 기준
- 질문 변경 시 새 기준선을 만드는가
- 등장 역할 분류를 사용자가 수정할 수 있는가

예상 영향: B2 수준 3→4, 최대 +2점. B4 수준 4의 방어력 강화

## 9. P1 수정 사항

- 문항 1의 세 번째 기준에 사실 오류율 또는 판단 보류율을 연결한다.
- 첫 리포트 확인 이전의 설정·생성 퍼널 지표를 추가한다.
- 브랜드 인식 변화 사건의 발생 빈도와 주간 업무 여부를 문제 가설로 둔다.
- 한 채널을 선택할 때 사용자 사용 빈도뿐 아니라 수집 가능성, 비용, 소비자 UI 재현성을 함께 본다.
- 요구사항 한 문장에 정책이 여러 개 들어간 부분을 번호나 정책 표로 분리한다.
- 참고 자료가 구현 패턴의 근거라는 점을 본문에서 한 번 명시하면 출처 역할이 더 선명해진다.
