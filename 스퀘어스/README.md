## 답안을 관통하는 축

```text
고객 문제·기대 결과
→ 목표 질문 승인
→ 질문별 노출·추천 현황
→ 확인할 답변 하나 선택
→ 등장 역할·이유·사실 확인
→ 이번 주 행동 하나 결정
→ 같은 질문 재확인
```

| 문항 1 | 문항 2 | 성공 측정 |
|---|---|---|
| 중요한 질문에서 반복해 후보가 되는가 | 기능 1. 목표 질문 노출·추천 현황 | 첫 현황 확인과 문제 질문 선택 |
| 맞는 이유로 추천되는가 | 기능 2. 답변 진단·우선 행동 카드 | 역할·사실 판정 신뢰와 행동 결정 |
| 고친 뒤에도 유지되거나 나아지는가 | 기능 1의 같은 질문 재확인 | 재확인 완주와 관측 변화 |

## V2에서 확정한 제출 범위

- 첫 파일럿은 한국어·한 브랜드·한 측정 환경·사용자가 승인한 소수의 목표 질문에 한정한다.
- 첫 검증은 Concierge MVP로 진행하고 반복되는 수동 단계부터 자동화한다.
- 기능 1의 출력은 질문별 노출·추천 현황표, 기능 2의 출력은 원문 근거가 있는 우선 행동 카드 하나로 닫는다.
- 재확인은 기능 1을 다시 사용하는 흐름이며 별도 세 번째 기능으로 세지 않는다.
- 디자인 파트너 과반의 루프 완주와 실제 업무 사용을 다음 자동화 검증의 초기 판단선으로 두며, 판정이 반복해서 뒤집히거나 공통 자동화 단계를 찾지 못하면 개발을 보류한다.
- 종합점수, 자동 콘텐츠 작성·게시, 프로젝트 관리, 다중 브랜드·국가 운영은 본문 범위에서 제외한다.
- V1의 점수 산식·상태 관리·API와 UI 운영 설계는 탐색 이력과 후속 검토 자료로만 보존한다.
- Word·PDF는 별도 장식 표지 없이 A4 약 6~7쪽을 목표로 하고 페이지 수보다 가독성을 우선한다.
