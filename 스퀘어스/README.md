## 제출 전 체크리스트

**공통**
- [ ] 문항 1의 기준 3개가 문항 2의 기능 2개로 이어지는가
- [ ] `[실측]` 표시가 전부 사라졌는가 (숫자로 채웠거나 문장째 삭제)
- [ ] 근거 없는 수치가 없는가
- [ ] 큐샵·스퀘어스 제품 얘기를 억지로 넣지 않았는가 (→ `00` 2절 주의)
- [ ] SCM·통관·물류 얘기가 본문에 없는가 (→ `00` 6절 주의)
- [ ] 문체가 본인 것인가

**문항 1**
- [ ] 기준 3개가 서로 겹치지 않는 축인가
- [ ] 각 기준에 **재는 방법**이 붙어 있는가
- [ ] 비결정성을 다뤘는가
- [ ] 수단(`llms.txt`·스키마)을 기준으로 제시하지 않았는가

**문항 2**
- [ ] 기능이 정확히 2개인가
- [ ] "왜 최우선인가"가 기능 설명보다 길거나 비슷한가 (배점이 거기 있다)

- [ ] 문제 정의 / 사용자·시나리오 / 기능 요구사항 / 성공 측정 4개가 다 있는가 (문항이 명시)

## 면접 대비 (과제 제출 후)

1차 비대면(조직장, 1시간)은 "지원 서류와 과제를 바탕으로" 진행된다고 공고에 명시돼 있다. 과제에서 쓴 모든 문장이 질문 대상이다.

거의 확실히 나올 질문:
- "이 기준 세 개를 왜 이렇게 잡으셨나요" → `01` 각 기준의 근거
- "직접 측정해 보셨나요" → `03` 실행 결과, 특히 답안에 안 넣은 모델별·유형별 차이
- "기능을 왜 이 두 개로 좁혔나요" → `02` 5-1·5-2절
- "큐샵 써보셨나요, 개선하고 싶은 점은" → 진행 순서 6번
- "0에서 1로 만든 경험이 있나요" → B2B 폐쇄몰(없던 시스템을 정책부터 설계), 수요예측 대시보드

`00_출제의도_분석.md` 6절에 본인 이력과의 연결점을 정리해 뒀다. **과제 본문에는 넣지 않고 면접에서 쓴다.**
